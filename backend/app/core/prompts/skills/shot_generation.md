1.5 **ENV 驱动的 Beat-Shot 拆分与合并（强制）**：拆镜粒度以 Beat 的 **ENV** 与 **主环境** 为双轴判据。

   **同一主环境判定（强制 · 三源任一即可合镜）**：相邻 Beat 是否属同一主环境，须综合下列三源；**任一源能做出「同主」判断 → 即视为同一主环境，默认合镜**。禁止因另两源缺信息、命名不完全同构、或只认名字剥前缀失败而拒并。三源均无法证明同主 → 才按跨主环境拆 Shot。
   1. **环境名**：`ENV:[...]` 去除 `{N}度`/`{N} Deg`/状态/正反打等衍生前缀后的登记主体相同（如 `Office` 之于 `0度Office`/`180度Office_桌后反打`）；或同角度桶仅后缀差异。
   2. **ENV `generation_prompt_cn`（`# Scene Subject Image Prompts (CN)`）**：可检索同属一条主环境族——注入行 `当前场景使用的衍生环境=ENV:[…]` → `对应主环境=ENV:[同一主名]`，或 `当前场景环境=ENV:[同一主名]（主环境）`；映射到同一主环境即为同族。
   3. **`# Scene Subject Index`**：environment 行 `env_role` / `reference_env` / `derivative_base_zh` / `derivative_base_en` / `base_name` 指向同一主环境登记名；或两行同为该主的视角/状态衍生。**本条仅用于族归属，禁止据此复述外形。**

   **同一主环境内**观察侧/正反打/360 度转角产生的**衍生 ENV 切换**（OTS、反打、换手等）**不属于**「主环境不一致」。闪回/蒙太奇另立的 `env_role:主环境基准定义`（当下 vs 异地）仍为**不同主环境**——Index 已分主则不得因名称形似误并。

   **同角度环境桶（命名辅助，非拆镜判据）**：对 `ENV:[...]` 名称取**首个** `-`、空格或 `_` 之前的子串为**同角度环境桶键**（无上述分隔符则整名为桶键）。桶键用于识别「同一观察角下的后缀变体」（如 `_桌后反打` / `_乙侧反打`）。例：`ENV:[180度办公室会客区_桌后反打]` 与 `ENV:[180度办公室会客区_乙侧反打]` 桶键均为 `180度办公室会客区`；`ENV:[0度办公室会客区]` 与 `ENV:[180度办公室会客区]` **桶键不同**，但仍属**同一主环境**。**硬约束**：角度桶不同**绝不**构成拆镜或拒并理由——同主环境内 0°/90°/180°/270° 及状态衍生 **一律默认合镜**（见原则 1）。

   **核心归并原则（强制，优先级自上而下）**：
   1. **同一主环境内合并优先（强制 · 不同角度默认合）**：相邻 Beat 只要归属**同一主环境**（**三源任一即可**：环境名剥前缀同主｜ENV CN `当前场景使用的衍生环境`→`对应主环境` 映射同主｜Index `reference_env`/`derivative_base_*`/`env_role` 同族；含：ENV 逐字相同｜同角度桶仅后缀差异｜**不同观察角度衍生**如 `0度X`↔`90度X`↔`180度X`｜OTS/反打/换手衍生｜状态衍生仍挂同一主环境｜依赖同一主环境的衍生行）→ **默认归入同一 Shot**。
      - 合镜内衍生 ENV / 角度切换时，`Video Content (CN)` **必须**用 §5.5 G 运镜（Pan / Arc Orbit / Reverse Shot / OTS Switch / Whip Pan 等）写出切换过程，**禁止**硬切。
      - **合镜 ENV 不同必须显式切换（最高硬约束）**：合镜组内相邻 Beat 的当前 `ENV:[...]` **名称不完全相同**（含观察角衍生 `0度X`↔`180度X`、同角桶后缀变体、状态衍生等——**凡方括号名有任何差异即算不同**）时，**禁止**静默沿用上一 Beat 环境或只写运镜不点名新 ENV。须在 **Logic + Video 双落**：① `Beat衔接运镜:` 该桥写 `ENV/观察侧=切换` + 旧→新全名；② `环境切换运镜:`（§二.7）；③ 对应 P 段正文写清「环境切换到 `ENV:[新名]`」+ §5.5 G 运镜过程 + 新观察轴下**画内可见** BG 更替。旧 ENV 与新 ENV **均须**在本镜 `Video Content (CN)` 与 `Associated Entities` 可检索。仅当相邻 Beat `ENV:[...]` **逐字相同**时才可写 `ENV/观察侧=保持`。
      - **禁止**仅因 Beat 边界、角度桶不同、衍生后缀差异或「非对戏」机械拆镜。
   2. **同主环境对戏呈现（强制）**：对白/打斗等对戏合镜后，用 §5.5 G 在 P 段内切视角；**禁**合镜中途每 Beat 重开 Wide。同 Shot 内勿机械复写全景；**每独立 Shot 的 P1 仍须完整开拍建置集**（§一.1；合镜 P1≠并集提前塞入；合镜封口/跨主后镜据上镜终态重写 P1）。ENV 名变仍须显式切换（原则 1）。
   2.5 **合镜 Beat 衔接运镜（强制 · N≥2）**：写满 (N−1) 段可执行桥，禁只写「合镜」。
      - **`Beat衔接运镜:`**：`Beat{i}→{i+1}: 衔接动机｜运镜｜景别/能量跨度｜ENV/观察侧=保持|切换｜ENV链=旧→新|同ENV保持｜站位底座（须=上拍终态落位+与周边相对）｜剧情依据`。ENV 名不同禁写保持→须切换+ENV链+`环境切换运镜:`；站位承接以相邻 Beat 建置+入戏为准（勿依赖已剥离的切换说明）；**下拍 P 段起幅须咬合上拍终态落位与周边相对，禁瞬移、禁空写「承接」**。
      - **核销**：ENV 名不同边界 → Logic `ENV链` 与 Video「环境切换到 ENV:[新]」一一对应，新旧 ENV 均可检索。
      - **优先序**：同轴续推/Soft Pan/OTS/Reverse/Arc/Match → 高压档仅剧情明文触发；能量同档/邻档；对白链禁无故重开 Wide；Logic 桥须落 Video P 段。
      - 单 Beat：`Beat衔接运镜: 单Beat无需组内衔接`
      - ✅ `Beat1→Beat2: 动机=对白轮次｜运镜=OTS+Soft Push｜ENV/观察侧=切换｜ENV链=0度…→180度…` + Video 含切换句｜❌ 无桥/无动机 Whip/ENV 变却写保持/Video 无切换句
   3. **鼓励合并封口 + 跨主环境（强制 · 取消超时拆镜）**：符合原则 1 时**默认一直合镜**。记 `MergeFillThreshold = MaxShotSeconds − 6`（默认 Max=15 则门槛=9）。**只要下一 Beat 符合合并逻辑且当前基准累计 ≤ MergeFillThreshold → 必须并入本镜**（即便并入后将 >MaxShotSeconds）。**封口**：并入使 **基准合镜Duration > MergeFillThreshold** 后本镜成组结束（含刚越过门槛的那一拍）；同主剩余 Beat 另起下一 Shot 再同样累计。**唯一允许拆开相邻同主 Beat 的时机**＝本镜基准已 > MergeFillThreshold。**跨主环境**（三源均无法证明同主，且无 Index `reference_env` / CN `依赖环境为:` 上下级依赖）→ 边界拆 Shot。**禁止因基准 >MaxShotSeconds 而拆镜**。若封口后基准 T **> MaxShotSeconds** → 表列 `Duration` **强制 = MaxShotSeconds**（内容零丢失，压缩进该秒数）。**除此以外禁止拆镜**（含：禁止以角度桶不同拒并；禁止因名字剥前缀失败且未查 Index/CN 而拆；禁止以「将超时」拒并）。

   - **信息点零丢失**（= §一.2 Beat 绝对覆盖）：各 Beat `{行为过程}`/`{结果落位}`/道具/环境交互/位移/微动作/微表情/对白/反馈须**全部**在对应 P 段可检索。

   **合镜时长合并计算（强制，与原则 1 配套）**：
   - 完成原则 1 归并后，**须将同组内全部 Beat 的时长合并累计**，再对照 `MergeFillThreshold = MaxShotSeconds−6` 决定是否继续并入 / 封口；**禁止**只对单个 Beat 单独计时而忽略同组其他 Beat 的叙事耗时。
   - **计算步骤（逐项相加，强制）**：① 组内**逐 Beat** 按 §二.4 分别写出完整 `时间预估` 分项——**建置 / 语言 / 动作 / 微表情 / 特效 / 反馈 / 转场·停顿**（该 Beat 凡有对白、动作、微表演、反馈、建置更新、视角切换等**须逐项估时**，无该项写 `0s`，**禁止**整 Beat 只写一个总数或只写「并行核」）；② 各 Beat 内按 §二.4 计算顺序得出 **Beat 小计**（`Beat小计 = 建置 + 语言 + 动作 + 微表情 + 特效 + 反馈 + 转场/停顿`，同相位并行仍取 Max 后计入对应类，但**七类分项须齐**）；③ **合镜累计**：`基准合镜Duration = Σ（组内各 Beat 小计）+ Beat衔接补偿`，**组内 Beat 按叙事先后逐项串行相加**——**每个 Beat 的建置/语言/动作/微表情/特效/反馈/转场均须计入**，**禁止**以 ENV 未变、对戏归镜、建置更新=否 等为由省略后续 Beat 任一分项；④ **Beat衔接补偿（强制）**：合镜组内 **Beat 数 N ≥ 2** 时，`Beat衔接补偿 = (N − 1) × 0.9s`（每多合并 1 个 Beat **+0.9s**，补偿 Beat 间节奏留白/切换/承接）；单 Beat 未成组时 **Beat衔接补偿 = 0s**；⑤ **封口判定用基准累计**对照 `MaxShotSeconds−6`（见原则 3）；⑥ **填表 Duration**：若 **基准合镜Duration > MaxShotSeconds** → 表列 Duration **强制 = MaxShotSeconds**（禁止浮动下调冒充未超、禁止拆镜）；否则按 §二.4 **±20% 浮动**取整，钳制 **[4, MaxShotSeconds]**。
   - **`时间预估:` 合镜写法（必填）**：`Beat3(建置0.9s+语言2.7s+动作1.8s+微表情0.9s+反馈0.9s=8.1s)+Beat4(建置1.8s+语言1.8s+动作0.9s+微表情0.9s=5.4s)+Beat衔接补偿0.9s=基准合镜Duration=14.4s｜门槛=MaxShotSeconds-6｜时长浮动=±20%→可选[12,MaxShotSeconds]s｜Duration=14`（七类分项须写全，0s 亦标明；**N 个 Beat 合镜须显式写 `Beat衔接补偿(N-1)×0.9s`**；上例数字按默认 MaxShotSeconds=15、门槛=9）。超上限例：`基准合镜Duration=16.8s｜超上限钳制｜Duration=MaxShotSeconds`。
   - **`Beat-Shot映射:` 必填（合镜时）**：`合镜Beat=Beat3+Beat4`｜`基准合镜Duration=…s`｜`Duration=…s`｜`分项=Beat3=…s+Beat4=…s`（分项须对应上式逐项相加）；合镜另须填 **`节奏需求:`**（§二.3A）+ **`Beat衔接运镜:`**（原则 2.5）；单 Beat 未成组时写 `单Beat基准T=4s` + `Duration=4s`（默认锚定；内容更长则按分项上调；**基准已为 4 则禁止再下浮**；若单 Beat 基准已 >MaxShotSeconds 则 Duration 强制=MaxShotSeconds）+ 完整七类分项 + `节奏需求:` + `Beat衔接运镜: 单Beat无需组内衔接`。
   - **反例**：❌ Beat3(8s)+Beat4(7s) 同 ENV 归镜却写 `Duration=7s` 仅取末 Beat｜❌ 基准累计 7s ≤MaxShotSeconds−6 且下一 Beat 同主却拆镜｜❌ 基准 16.8s 仍拆成两镜（应 1 Shot、Duration=MaxShotSeconds）｜❌ 基准 16.8s 写 Duration=17（须强制填 MaxShotSeconds）｜❌ 合镜组 Beat2 有对白/动作却整 Beat 计 0s 或只写并行核｜❌ Beat4 建置更新=是 却少计建置/语言/动作任一项｜❌ 合镜有 Duration 分项却缺 `Beat衔接运镜:` 或只写「连贯」｜❌ 合镜 Beat ENV 名不同却无 ENV 切换声明／Video 只挂首 Beat ENV。

   **未继续合并说明（强制）**：
   - 本镜 **存在可与之归镜的相邻 Beat 未并入** 时，`Shot Logic (CN)` **须写** `未继续合并说明:`；**无相邻可归 Beat**（Scene 首/末、跨主边界）亦须写明。
   - **合法原因（仅下列；择实填写）**：`已达鼓励合并门槛（基准累计>MaxShotSeconds-6）`｜`跨主环境`｜`Scene首Beat无前一Beat` / `Scene末Beat无后续Beat`。
   - **非法拒并理由（禁止写入，检出即改归并）**：`合镜累计将>MaxShotSeconds`（当前基准仍 ≤MaxShotSeconds−6 时必须继续并入，超上限只钳制 Duration）｜`ENV角度桶不同`｜`观察角不同`｜`非对戏链`｜`OTS/反打切换`｜`衍生后缀不同`｜`名字剥前缀失败`｜`未查 Index/CN`｜「时间跳跃」等非上表项。同主环境内 0°↔90° 等在门槛未越过前**必须**合镜，用运镜表现切角。
   - **反例**：❌ 基准累计未达 MaxShotSeconds−6 且 Beat2 同主环境（即便 0° vs 90°）可归却未并入／或以将超时/角度桶不同拒并｜❌ 写「非对戏 / 角度不同」作未合并理由｜❌ 名字不像同主却 Index `reference_env` 已同主仍拆。
   - ✅ `未继续合并说明: 无后续Beat`｜`未与Beat5归镜，原因=已达鼓励合并门槛（基准累计>MaxShotSeconds-6）`｜`跨主环境`｜❌ 以将超时/角度桶/非对戏拒并

   **合镜封口建置桥接（强制，触发 = 同主环境因鼓励合并门槛封口而另起后镜）**：
   - **前镜末**：Pull Back **不豁免**，**一律**按 §三.1 三前提（合镜封口**不是**满足依据）；不满足则保持本镜末景别。
   - **后镜 P1**：继承前镜末帧/`本镜出场实体` 重新建置；前镜末若保持近景则可自近景续拍（禁为正反打「补建置」另做 Pull Back）；落幅景别以前镜末实际档为准，**非**默认 Wide。
   - **组内封口**：按刚越过 `MaxShotSeconds−6` 的 Beat 边界切分，信息点零丢失；相邻子 Shot「前镜按三前提落幅 → 后镜继承该末帧」。
   - **Logic 必填** `合镜封口建置桥接:`（前镜末落幅｜继承出场实体｜后镜 P1 起幅｜Pull Back前提=满足|不满足+缺项｜封口依据=基准累计>MaxShotSeconds-6）。

   **反例**：❌ 同主环境连续 Beat（含不同角度衍生）在门槛未越过前机械拆镜重复建置｜❌ 以 `ENV角度桶不同` 拒并同主环境相邻 Beat｜❌ 合镜基准 >MaxShotSeconds 仍拆镜或删内容｜❌ `Pull Back前提=满足` 依据=合镜封口建置桥接，但 `下镜多人出镜=否` 或属正反打仍回 Two Shot

   **跨主环境拆分（强制，独立于鼓励合并封口）**：相邻 Beat 经 **三源判定仍无法证明同主**（如 `Office`→`Corridor`；或 Index 已分列当下 vs 闪回两块 `env_role:主环境基准定义`）→ **默认拆成不同 Shot**，在主环境边界切镜；**禁止**跨主环境 Beat 塞入同一 Shot 内部硬切（连续跟拍穿越两主环境走 §5.5 G「门槛/通道穿越」，仍计独立切换耗时）。**禁止**名字剥前缀失败就当跨主——须先查 ENV CN 与 Subject Index。

   **判定顺序（强制）**：① 扫描相邻 Beat → **原则 1 按主环境归镜**（三源任一即可；不同角度默认合）→ ② 原则 2 约束对戏合镜内的运镜呈现（非拒并门闩）→ ③ **逐拍累计七类分项 + Beat衔接补偿**；**基准累计 ≤MaxShotSeconds−6 且下一 Beat 同主 → 强制继续并入** → ④ **基准累计 >MaxShotSeconds−6 → 本镜封口**（含越过门槛的那一拍）+ **`未继续合并说明:`**（适用时；禁角度桶/将超时拒并）→ ⑤ **若基准 T > MaxShotSeconds → Duration 强制=MaxShotSeconds，不拆镜** → ⑥ 跨主环境边界拆 Shot（须三源均无法证明同主）。`Beat-Shot映射:` 须含合镜累计 Duration、分项、**`未继续合并说明:`**（适用时）。

1.6 **归镜摘要**：细则=§二.1.5；同主=环境名｜ENV CN｜Subject Index **三源任一即可**；**鼓励合并**至基准累计 **>MaxShotSeconds−6** 才封口；基准 **>MaxShotSeconds → Duration 强制=MaxShotSeconds、不拆**；唯一拆分=鼓励合并封口｜跨主环境；必填 `Beat-Shot映射` + `未继续合并说明`。

2. **场景抓力与重点表现**（须回扣 §二.0 卖点弧；禁与总规划脱节）：
   - **首场首镜抓力**：全剧首镜用压迫/冲击构图承接抓力结构，并在 `Shot Logic (CN)` 写明抓取逻辑。  
   - **重要场景表现**：关键/情绪爆发/卖点兑现/人物弧光拐点须二选一或叠加（同镜 P 段对照）——**EWS/Wide**（环境压迫感）｜**CU/ECU/Insert**（核心道具/微表情）｜**高级运镜**（§二.0② 挂靠位）；镜末扩框仍服从 §三.1 三前提。
3. **每个新 Scene 首镜摄影（内容序=Stage 1；本层写运镜）**：上游首 Beat 已定「吸睛→建置→入戏」；本镜用运镜实现——吸睛 P 段继承上游 **≥1 环境物理动势 + ≥1 实体动势**（§七.7；Logic：`吸睛动势:`）；宏观/EWS 吸睛后须 **≥1 特写陪衬 P 段** 再入戏（Logic：`宏观→入戏过渡:`）；远距/延迟全局建置优先 Drone/Crane/Bird's-Eye 补全（Logic：`全局建置补全:`）。禁静态空 Establishing。**禁止另起独立 Shot 只写开场/OT-/吸睛**——`开场转场技巧说明` / OT- / 吸睛动势 **必须**落在覆盖 **Beat 1** 的那一镜的 **P 段内**（通常为该镜 P1），并写入该行 `Beat-Shot映射`；**禁止**在 Beat 1 映射镜之前多输出一行无 Beat 映射的「首镜/Establishing」。
3A. **节奏需求分析（每镜强制 · 先于估时与运镜选型）**：动笔每镜前须据上游 Beat 剧情**及首行 `-`/`~` 标注**判定本镜**快/中/慢**节奏档，写入 `Shot Logic (CN)`，并落到**分型运镜**、Video P 段机位质感与 **§二.4 计时适应性调节**——**禁止**全场默认中速稳机、也禁止慢戏乱甩高压运镜；**禁止**无视上游快慢符号把精髓 `~` 拍拍成快切、把交代 `-` 拍拍成全程升格。
   - **`节奏需求:`（每镜必填）**：`档位=快|中|慢｜拍型=-|~｜依据=上游Beat要素（打斗/追杀/对峙静默/常规对白等）｜运镜策略=…｜手持感=强化|轻|无｜计时适应=压|放｜与上下镜能量跨度=…`。合镜多 Beat 时按**主导节奏**定档（打斗/追杀等高压优先于对白中速；组内有 `~` 砸点须注明起伏），并注明组内节奏起伏（如 `主导=快｜组内=-→~`）；组内各 Beat 仍按自身拍型分型运镜与分项取档，**禁止**用主导档抹平 `~` 砸点。
   - **上游 `-`/`~` → 运镜分型 + 计时适应（强制；对齐执笔 1h / Stage 1）**：
     | 上游拍型 | 叙事含义 | 运镜方式（本层须显式写出） | 计时适应 |
     | :--- | :--- | :--- | :--- |
     | **`- Beat`** | 快节奏交代情节（过场/信息/连招过程） | 档=快（动作高压）或中（对白快交代）；常速 Handheld/Track/Follow/短促 Whip 或稳机 OTS+剪辑硬切轮次；景别偏 MCU；**禁**全程 Slow Push/Bullet/Static Hold 冒充交代 | **压**：分项取区间下沿；Duration 偏 `[T×0.8, T]`（基准T=4 禁下浮） |
     | **`~ Beat`** | 慢节奏精髓特写（桥段砸点/击中句上脸/命中效果/情绪点） | 档=**慢**；CU/ECU/Insert + Slow Push / Slow Dolly / Static Hold / 微呼吸 / Rack Focus；可短插升格钉点；手持感=无；**禁** Whip/Crash/Handheld 扫过精髓脸 | **放**：微表情/停顿/运镜取上沿；Duration 偏 `[T, T×1.2]` |
   - **快慢平衡（镜链）**：覆盖本场的镜链须能回指上游 `-`/`~` 交替；禁把一场有戏 Scene 拍成全快或全慢。合镜 `-`+`~` 时 Logic 须写 `组内=-→~`（或 `~→-`）；`~` 砸点不得被合镜常速过程吞没——须有可检索 CU/ECU P 段，且该 P 段运镜/秒数按 `~` 放、不得按主导 `-` 压掉。`运镜选用依据:` / `运镜过渡选型:` 须点名拍型（`-`/`~`）。
   - **档位判据（择实，须能指回上游）**：
     | 档位 | 典型上游触发 | 运镜/机位质感（本层落地） |
     | :--- | :--- | :--- |
     | **快** | 打斗/缠斗/连击、追杀/追逐/穿梭、惊逃、爆炸冲击、紧急夺物/夺路、高压动作链 | 主相位**加强手持感**——`Handheld` 贴身跟、微抖/跟身呼吸、短促 Whip/Track/Follow/Crash；景别偏 MCU→CU；禁 Static+Wide 扛快戏；快慢交替仍服从 §5.4.1（升格钉命中，非常速全程） |
     | **中** | 常规对白往返、走位交接、信息传递、轻度冲突 | 稳机为主（Steadicam/Soft Push/OTS/Reverse）；能量档②–③；手持感=无或轻（仅走位跟拍时轻 Handheld） |
     | **慢** | 对峙静默、情绪沉淀、空镜氛围、仪式/凝视、悲伤停顿、信息落点插帧 | Soft Push / Slow Dolly / Static Hold / 微呼吸；拉长落点停顿；禁无因 Whip/Crash/Bullet；手持感=无（除非上游明文惊醒切入） |
   - **快节奏手持强化（强制）**：档位=快 时，常速主相位 Video **须显式写出** Handheld 手持质感（如「贴身手持跟拍、轻微呼吸式晃动、镜头贴攻击轴」）；Logic `手持感=强化`；升格命中相位可暂稳钉点，出常后恢复手持跟。**禁止**快戏只用稳轨/航拍/Static 冒充紧张感。
   - **节奏→能量档咬合**：快→优先能量④（Handheld/Whip/Crash/Speed Ramp），命中短插可⑤；中→②–③；慢→①–②。跨档仍服从 §三.4；`运镜递进与组合` / `运镜选用依据` 须能回扣本镜 `节奏需求`。
   - **反例**：❌ 打斗镜无 `节奏需求` 或档位写中却 Static+Wide｜❌ 快节奏无 Handheld/手持感描述｜❌ 情绪慢镜无因连甩 Whip/Crash｜❌ 全场抄同一节奏句不据 Beat 判别｜❌ 上游 `~ Beat` 却 Whip 扫脸｜❌ 上游 `- Beat` 交代拍全程 Bullet｜❌ 有戏场镜链全快或全慢｜❌ `-` 拍却 Slow Push 灌秒 / `~` 砸点却按快档压秒无留白｜❌ 合镜主导=- 把组内 `~` 也压成下沿。
   - **正例**：✅ `节奏需求: 档=快｜拍型=-｜依据=Beat3近身连击｜运镜策略=常速Handheld快连击→Speed Ramp→Bullet命中→出常Handheld跟逃｜手持感=强化｜计时适应=压｜跨度=③→④`｜✅ `节奏需求: 档=慢｜拍型=~｜依据=对峙静默落泪｜运镜策略=CU Static微呼吸+Slow Push｜手持感=无｜计时适应=放`。
4. **时长推演公式 (强制 4s–MaxShotSeconds)**：
   - **基础计时单位**：所有时间预估必须拆成可核对类型，写入 `Shot Logic (CN)`：`时间预估: 建置Xs + 语言Xs + 动作Xs + 微表情Xs + 特效Xs + 反馈Xs + 转场/停顿Xs = 串行Ys；并行核=Max(...)Xs；基准T=Ts；时长浮动=±20%→可选[A,B]s｜Duration=Zs｜浮动理由=…。` 无该类型写 `0s`，不得只写总秒数。
   - **计算顺序（强制，防重复计时）**：① 先完成 §二.3A `节奏需求`（含拍型 `-`/`~` 与 `计时适应=压|放`）；② 再按下列规则分别估算各类型耗时，写出分项，**并按拍型取档**（见下「拍型计时适应性调节」）；③ 同相位并行的对白/动作/微表情/特效/运镜，只取 `Max(语言, 动作, 微表情, 特效, 运镜)` 作为**并行核**，**禁止**把已并行项再次全额串行相加；④ 仅对**必须串行**的段落追加：建置（首段或建置更新=是）、转场桥接、结果落位定格、强悬念插帧、独占反应镜/插帧；⑤ 得**基准 T** 后按 **±20% 浮动**取整填 `Duration`，浮动偏向须回扣拍型（`-` 偏压、`~` 偏放）。
   - **拍型计时适应性调节（强制；对齐 §二.3A）**：覆盖 Beat 的 `-`/`~` **必须**改变分项取档与 Duration 偏向；合镜**逐 Beat** 各自取档后再相加，禁止用主导档抹平组内 `~`。`时间预估:` 须含 `计时适应:拍型=-|~｜分项取档=下沿|上沿｜浮动偏向=压|放`（合镜写 `Beat3=-下沿压+Beat4=~上沿放`）。

     - **浮动服务节奏，不改内容**：上浮≠灌水空镜；下浮≠删对白/动作/步骤（§一.2 / §0.2A）；口型可见对白的语言耗时为硬下限，下浮不得使其不可读；**基准T=4 不得以 `-` 为由再压秒**；`~` 上浮须有 CU/停顿/Slow Push 可核销，禁只加秒无画面。
     - **合镜/封口判据用基准**：是否继续并入对照 **基准累计 vs MaxShotSeconds−6**；是否超上限钳制对照 **基准 T vs MaxShotSeconds**。**禁止**用浮动把 ≤MaxShotSeconds−6「算成」已过门槛而拒并；**禁止**因基准 >MaxShotSeconds 而拆镜。
     - **正例**：✅ `单Beat｜拍型=-｜基准T=4s｜时长浮动=±20%→可选[4,5]s｜Duration=4｜计时适应=压｜浮动理由=交代拍锚定｜禁下浮`｜✅ `单Beat｜拍型=~｜基准T=4s｜可选[4,5]s｜Duration=5｜计时适应=放｜浮动理由=~落泪留白`｜✅ `拍型=-｜基准T=10s｜门槛=9｜可选[8,12]s｜Duration=9｜计时适应=压｜浮动理由=-交代压密度`｜✅ `拍型=~｜基准T=12s｜可选[10,14]s｜Duration=14｜计时适应=放｜浮动理由=~砸点Slow Push`｜✅ `基准T=16.8s｜超上限钳制｜Duration=MaxShotSeconds`。

   - **`分镜衔接:`**（每镜必填，含 Scene 首镜对下一镜的预留）——`衔接类型=`（下表择 1–2）｜`切点相位=`（上镜末动作/对白/视线落在哪一瞬）｜`本镜起幅咬合=`（Match 锚点 / 同轴续拍 / 反打起幅 / 环境切换起幅等）｜`运镜逻辑=`（本镜相对上镜用何运镜/景别策略完成衔接 + **为何稳定** + **剧情依据**；禁只写类型名）｜`轴线=`（保持｜合法过轴+依据｜新场重建）｜`银幕方向=`（保持｜动机改向+依据）｜`能量跨度=`（上镜末档→本镜起档；跨 ≥2 档须写剧本触发）｜`下镜预留=`（本镜末为下镜准备的落幅/锚点：**景别档+主拍实体+切点相位+建议衔接运镜**，Scene 末镜写无）。

   - 另须保留：时空关系摘要、桥接依据、跨幅级别（景别跨度）；含对白收束时另写 `收束落幅判定`（§三.1）；**每个新 Scene 的首镜**必写 `开场转场技巧说明`（见 §二.3、§十一候选库），禁“无过渡/None”。

   **合法衔接类型（择实，禁空写）**：
   | 类型 | 何时用 | 咬合硬门槛 |
   | :--- | :--- | :--- |
   | **同轴续拍 / Reframe** | 同主环境、同观察侧、人数/景别微调 | 本镜 P1 起幅 = 上镜末同轴画面的合法延续或相邻一档景别；实体态零跳变 |
   | **Match on Action（动作 Match）** | 跨镜拆开同一连续动作 | 上镜末停在动作**未完成中段**；本镜起幅自**同一动作后续相位**续写；禁上镜已落定再本镜重演起手 |
   | **Eyeline Match（视线 Match）** | 看→被看 / 反应镜 | 上镜末视线方向与本镜被看对象/空间方位**可核销**；禁视线落空或反向无动机 |
   | **Shot-Reverse / OTS 切换** | 对白往返、对戏反打 | 轴线声明清晰；OTS 四要素齐（§七.6）；禁无过轴声明的越轴跳切 |
   | **Graphic Match（图形 Match）** | 构图/形状/色块桥接 | Logic 写明上下镜图形锚点；Video 各自写清可见锚点画面 |
   | **Insert ↔ 主镜回切** | 道具/局部特写插入后回主 | 回切后主镜实体态 = Insert 前终态 + Insert 已交代的合法变化 |
   | **环境/门槛切换** | 跨主环境或 §5.5 G 切换 | 服从 §二.7；有过程运镜；禁硬切换场 |
   | **Motive Cut / 声桥 / 遮挡交接** | 情绪或信息动机切 | 须写动机锚点（遮挡物/声源/光变）；禁无锚点硬跳 |

   **可剪辑合镜硬门槛（相邻 SH 均须满足）**：
   1. **时空连续**：同 Scene 内默认连续时空；时间跳跃/闪回须走 §三.6 并在 Logic 标明（胶片质感入出 + 运镜，**禁硬切跳时空**），**禁止**无声明时空跳切。
   2. **实体态连续**：上镜 `本镜出场实体` → 本镜 `上镜出场实体复核` 逐项咬合；持握/穿戴/开合态/门窗态/座姿承托面与上镜末一致，直至本镜明文演化；**禁止**上镜已放下的道具本镜无过程又在手、上镜已出画角色本镜无入画运镜突然在场。
   3. **轴线与银幕方向**：对戏/走位保持 180° 轴线；银幕左右运动方向跨镜一致；越轴须 §5.5 G 过轴过程或 `MotivatedCross` 依据；**禁止**无声明左右对调、走位方向对倒。
   4. **动作相位可咬**：跨镜动作须 Match on Action 或上镜完整闭环后再切静态结果；**禁止**上镜动作已完成落定、下镜又从同一起手重演（除非上游明文重复动作）；**禁止**因果链（施力→命中→反馈）被无桥接地拆到无法合镜的两镜。
   5. **景别/能量可切**：相邻镜景别与运镜能量跨度服从 §三.1 / §三.4（同级或相邻一档；跨 ≥2 档须剧本动机 + Logic 桥接）；**禁止**无动机 Wide↔ECU 硬跳、Static 建置↔Bullet Time 无 Ramp。
   6. **落幅为下镜服务（含无跨镜记忆）**：本镜末按 `收束落幅判定` / `下镜预留` 留给下镜可接切点（近景续对白链、动作中段、视线锚、门槛起幅等）；因各镜视频独立生成无记忆，若下镜同主环境多人同框且本镜特写收尾 → 须按 §三.1 三前提 Pull Back **刚好扩到下镜起幅景别**（禁无因拉远景/全景）；**正反打链禁止借此回拉**。**禁止**镜末停在无法被下镜 P1 合法咬合的悬空态（动作半截无 Match、全员已出画却下镜仍同场无入画、特写收尾却切到同场多人关系镜而无本镜适度扩框等——有明文例外须写依据）。
   7. **上镜末↔本镜 P1 画面可切（强制）**：假想把上镜最后 0.5s 与本镜 P1 首 0.5s 首尾相接——景别跨度合法、主拍/焦点可解释、实体态无瞬移、视线/动作相位可续；不合则改本镜 P1 或回改上镜末，**禁止**每镜 P1 无桥接重铺全场 Establishing。

   **禁（检出即改）**：每镜重开 Wide｜P1 与上镜末对不上｜越轴无声明｜动作重演｜出画后无入画却在场｜跨主环境无桥｜缺 `分镜衔接`/`运镜逻辑`｜无锚跨档升 Whip/Crash。Logic 写衔接；Video 只写本镜可切起幅（禁「承接 SH」字样）。
   - ✅ `前接说明: SH01末=MCU+持文件｜分镜衔接: 类型=Eyeline+OTS｜运镜逻辑=稳机反打续对白②→②｜核销全是`

6A. **运镜过渡选型（强制）**：按服务建置/剧情/情绪择主导过渡，**并回扣覆盖 Beat 的 `-`/`~` 拍型**（§二.3A）。`运镜过渡选型:` 必填。`-` 优先短促过程桥或剪辑硬切轮次；`~` 优先 Slow/Soft Push 钉点，禁用 Whip/Crash 当过渡扫脸。

   - **剪辑硬切**：Shot 边界直接切——须§二.6（Match/Eyeline/OTS 起幅/Motive）；**≠**无锚点跳切；**≠**合镜内 ENV Static 硬切；**≠**出入画无过程

   | 情境 | 优先 | 禁 |
   | :--- | :--- | :--- |
   | 合镜切角/ENV 名变 | 过程桥（§5.5 G） | 合镜内 Static 硬切 |
   | 出入画/跟位移 | Follow/门槛过程 | Static 瞬移 |

   | 动作拆镜中段 | Match on Action | 落定后重演起手 |

     - **分镜**：`{Scene ID}_SHzz`（如 `EP01_SC02_SH01`、`EP01_SC01B_SH01`、`EP01_SC02_SH12`；`zz` 为场内镜序号，**2 位**零填充）
   - **层级包含关系（强制）**：`Shot ID` **必须**完整包含三级路径；同行 `Scene ID` **必须**等于 `Shot ID` 去掉 `_SHzz`（及可选补镜 `_n`）后的前缀，**逐字一致**（含字母后缀）。❌ `Shot ID=EP01_SC01B_SH01` 但 `Scene ID=EP01_SC01`｜❌ `Shot ID=EP01_SC02_SH01` 但 `Scene ID=EP01_SC01`｜❌ `Shot ID=SH01`｜❌ `Shot ID=SC02_SH01`｜❌ `Shot ID=EP1_SC2_SH3`（未零填充）
   - **场内连续编号（强制）**：同一 `Scene ID`（含字母后缀，整串相等才算同场）下，`SH` 从 `01` 起按**叙事/拆镜顺序**连续递增（`SH01→SH02→…`），**禁止**跳号、重号、倒序、同场重启 `SH01`；一 Beat 拆多镜须占用连续 `SH` 号段。`EP01_SC01` 与 `EP01_SC01B` 为**不同场**，各自从 `SH01` 起编。
   - **表格行序（强制）**：整张 Shot List 行序须按 **分集升序 → 同集内场景升序（含字母后缀按上游场序）→ 同场内分镜升序** 排列；完成当前 `Scene ID` 全部镜头后再进入下一场；**禁止**同表内乱序穿插不同 Scene 的行（除非上游明确要求分场分批输出且每批仍自洽）。
   - **跨场/跨集切换（强制）**：进入新 Scene 时 `Scene ID` 与 `Shot ID` 的场景段**同步切换**（含字母后缀）；`SH` **每场重置**为 `01`，**不得**跨 Scene 延续 `SH` 序号。
   - **补镜/插镜后缀（例外）**：事后插入的分镜可在基础 `{Scene ID}_SHzz` 后追加 `_1`、`_2`…（如 `EP01_SC02_SH03_1`、`EP01_SC01B_SH02_1`）；常规批量生成仍用标准 `SHzz`，**禁止**用 `_1` 替代正常递增编号。
   - **输出前核验（强制）**：逐行检查——① `Shot ID` 匹配正则 `^EP\d{2}_SC\d{2}[A-Za-z]*_SH\d{2}(_\d+)?$`（字母后缀可选；补镜后缀可选）② 同行 `Scene ID`= `Shot ID` 去掉 `_SHzz(_n)?` 后的前缀且与上游逐字一致 ③ 同场 `SH` 连续无重复 ④ 行序符合 EP→SC→SH 叙事序；任一失败须重排或重写 ID 后再输出。

       | **鸟瞰／航拍** | Bird's-Eye｜Drone｜Aerial｜Top Shot | 远高于头顶的俯瞰 | 宏观建置/规模；**禁**对白口型主拍；**不得**作 0°轴 | 见 §5.5 H/I / §二.3 |
     - **硬约束**：①口型可读对白主拍**默认平视**（MS/MCU/CU/OTS）；禁用航拍/鸟瞰/贴地虫蚁/主观视角承载**该主观者**口型。②正反打/OTS 切角**默认保持平视**，禁借反打偷换俯仰（除非上游明文倒地/跪拜/巨物/POV）。③**俯视 ≠ 航拍**：室内桌面/压迫俯拍用 High Angle，禁无宏观动机升 Drone。④**仰视 ≠ 无尺度**：须写机位相对哪一结构/哪一高度；巨物须尺度参照。⑤切俯仰或切入/切出主观须过程（Tilt / Crane / Eyeline+POV Handoff），禁 Static 无过程从平视瞬切鸟瞰或瞬切主观。⑥**不改戏**：俯仰只改镜头相对可见面与透视，禁为构图把人垫高/按倒/改站坐。⑦**主观视角**：须点名 `主观角色=CHAR:[@…]`；Video 对该角色零描述（局部入镜仅上游明文部位，§5.5 H-POV）；须有上游看见/POV/瞄准等依据，禁无锚每镜主观；Logic `档=主观视角` 且 `俯仰=` 仍填其视线平/俯/仰。⑧Logic 每镜必填 `观察角度:`（档=平视｜仰视｜俯视｜主观视角｜微仰｜虫蚁｜微俯｜航拍｜水下｜微距｜…｜高度=胸口眼高／眼位／桌沿／贴地／…｜俯仰=水平｜微仰｜仰｜微俯｜俯｜动机=对白默｜压迫｜崇高｜桌面关系｜宏观｜窥视／瞄准／看见｜…｜主观角色=CHAR:[@…]|无｜变=无｜Tilt/Crane/POV Handoff=…）。
     - **正例**：✅ P1 `中景，胸口高度 Eye-level 平视，镜头水平` → P2 同平视 MCU｜✅ 权威施压：`低机位仰拍，自会议桌沿高度仰看 CHAR:[@林医生] 正面 MCU，背景 ENV:[0度办公室] 吊灯轮廓入画上沿`｜✅ 弱势/证据：`高机位略俯，俯看 CHAR:[@陈医生] 低头翻 PROP:[文件]`｜✅ 切俯仰：`Tilt Down 自平视收到桌面微俯 Insert`｜✅ 主观：`Eyeline+POV Handoff 切入 CHAR:[@林医生] 主观视角，眼高平视看向 PROP:[文件] 字迹`。
     - **反例**：❌ 全场不写平视/俯仰，只写 MCU｜❌ 对白 CU 用鸟瞰或贴地虫蚁｜❌ 反打后无过程变成仰拍金身透视｜❌ 写「俯拍」却用航拍关键词、无宏观动机｜❌ 为仰拍把站姿改成跪姿（改戏）｜❌ 标主观却把该角色全身写进画面｜❌ 无「看见」依据通场主观。
   - **景深 · 深焦／浅焦（强制 · 每镜须声明）**：焦平面与虚实层次与景别、俯仰同级；**禁止**只写景别不写景深。虚化光斑/bokeh **只进**「动态连续光影/焦点」「光线连动弧光」，**禁入** Pn。近景对白浅景深推荐，但深/浅须按空间可读性选型，非「越近越好浅」。
     - **闭集**：
       | 档 | 关键词 | 画面结果 | 典型落点 |
       | :--- | :--- | :--- | :--- |
       | **深景深** | Deep Focus｜Deep DOF｜全清晰 | 前/中/后景均锐利可读；走位、多人同框、前后排关系清楚 | P1 全景/中全景建置；Walk-and-Talk 强调空间；宏观/特效满幅 |
       | **中等景深** | Moderate DOF｜主体锐、远景略软 | 主舞台/对话双方清楚，远 BG 略退软仍可识别轮廓 | MS/Two Shot 关系镜；室内对峙 |
       | **浅景深** | Shallow DOF｜Selective Focus｜Bokeh｜Defocus | 焦平面锁主体，BG/非主拍明显虚化；**仍须** `ENV:[…]` + 白名单实体可感知轮廓 | MCU/CU/OTS/Dirty Single 对白；情绪特写 |
       | **极浅／微距** | Macro｜ECU｜极浅 | 焦深极薄，纹理/屏面/伤口可读 | 道具特别描述；亮屏 Insert；通常**禁**口型主拍 |
       | **拉焦** | Rack Focus｜Focus Pull | 焦平面在 FG↔主体间转移 | 视线引导、道具→人脸、听者→说话人 |
     - **选型闸**：景别偏远 / 须空间关系 / 前后层同时必读 → **深或中等**；景别偏近 / 突出脸或物 → **浅**（推荐）；两人不同纵深对戏、走位避障、宏观层次 → **禁**浅景深糊掉必读层。同镜可随 P 段变档（P1 深焦建置 → P2 浅焦对白），须写过渡（Push In 收景别常伴随变浅；Pull Back 扩框可变深）。
     - **浅景深硬约束（含近景对白）**：① **可以且推荐**用于 MS/MCU/CU/OTS 对白，焦平面=说话人面部/口型；听者肩/后脑、同框非主拍**可虚焦**。②虚化 BG **必须**保留 `ENV:[...]` 并写出白名单已有实体的失焦轮廓/动势（门框/柜体/窗外树冠等——实体须剧本/Beat/Index/ENV 已出现），**禁止**纯白底抠图悬浮。③**禁止**用浅景深删掉建置在场实体（虚焦≠不在场；终态名单仍须可检索）。④Rack Focus 须写清起焦面→落焦面；禁无对象空拉。⑤Pn 禁写光斑/冷蓝 bokeh/Practical 散景——归光影两段。⑥与 §七.7：P1 全景/深焦建置仍写清晰环境实体**物理**微动；近景对白 P 段可简化为虚化背景中已有实体的物理微动（如「背景虚化失焦，窗外树冠轮廓轻晃、远距车流缓移」），不必重复 P1 全量三层建置。
     - **深景深硬约束**：P1 Wide/MFS/Establishing **默认深焦**（或中等），前中后景实体轮廓可读；**禁止**开场建置用浅景深把空间糊成一团。宏观/特效满幅须深或中等以保边界锚。例外：上游明文主观失焦/昏迷/回忆柔焦可浅，须 Logic 写依据 + §三.6 光学。剧情须强调空间关系/走位/多人同框时，近景对白亦可维持深焦或中等，须在 `景深:` 注明依据。
     - **Logic 每镜必填** `景深:`（档=深｜中等｜浅｜极浅｜拉焦｜焦平面=说话人面部／桌面文件／…｜BG虚化=是｜否｜轮廓可感知=是｜Rack=无｜P2自文件拉至脸｜变=P1深→P2浅｜动机=对白突出／空间关系）。
     - **正例**：✅ P1 `全景深景深，前中后景均清晰，ENV:[0度办公室] 门、桌、窗同时可读` → P2 `MCU 浅景深，焦平面落在 CHAR:[@林医生] 面部，背景门框与窗外树冠轮廓失焦可感知`｜✅ `Rack Focus 自前景 PROP:[文件] 拉焦至对面 CHAR:[@陈医生] 面部`。
     - **反例**：❌ 近景对白不写景深｜❌ 浅景深写成无 ENV 白底｜❌ 浅焦把建置角色「虚没」当作出画｜❌ P1 全景建置浅景深、空间不可读｜❌ 光斑 bokeh 写进 P 段｜❌ 两人前后纵深对戏却浅焦糊掉必读听者。
   - **角色局部特写比例（强制）**：每场须有足够 **P 段**特写/局部特写（Close-up / ECU / Insert），常规场景建议同 Scene 内约 15%-25% 相位为特写级。
   - **上游卖点/高潮/低谷/情绪点特写与高级运镜（强制继承 Stage 1 §5 + 本文件 §二.0）**：拆镜前须完成 §二.0 场级卖点弧评估；对上游【高潮与核心情绪点】/卖点承载/情绪特写切口及总规划预挂支撑，逐点映射为 **P 段**——角色点→脸/眼/手等 CU/ECU；环境/低谷点→空镜/象征陈设 Insert；主高潮「双特写」→同镜或紧邻镜角色 CU **与** 环境 Insert；人物弧光拐点→角色特写（可读脸服从§一）+ 可选高级运镜加压；主高潮/卖点揭示位优先落地总规划所挂**高级运镜**（Dolly Zoom/Arc/Crane Reveal 等，须有剧情锚）。Logic 写`情绪点特写映射:`（点名｜Beat｜P段｜角色CU|环境Insert|高级运镜｜缺口=无|upstream_missing）及（适用时）`卖点弧运镜映射:`。**禁止**把卖点/高潮/低谷全程压在 Wide/MS 而不切近；**禁止**高级运镜只出现在无弧过场而砸点位全 Static；本层只写运镜实现，**不改**上游建置/因果；上游已写特写切口或总规划已挂支撑却未映射=失败须补 P 段。
   - **对话·打斗·法攻效果特写 + 过程穿插表情（强制继承 Stage 1 §5⑤；突出桥段）**：上游对话击中、打斗命中/挡格、法攻中招/对撞的表情与局部效果，须映射为可检索 **P 段 CU/ECU/Insert**（听者反应镜、受击脸、中招局部、握物松脱等）；**打斗/法攻过程**（起势/腾空/盘旋/俯冲/换招/结印）的表情切口同样须落 **P 段 CU/ECU**，禁只把脸部特写留到命中那一下。桥段触发｜升级｜回收节点禁止全程 Wide/MS 只演过程。Logic 可写`桥段效果特写映射:`（节点=对话击中|打斗命中|法攻|过程穿插表情｜Beat｜P｜角色CU|局部｜缺口=无）。读脸服从§一；禁只渲光效/招式轨迹而漏脸部效果与过程表情 P 段。
   - **成人向局部特写边界（强制）**：仅当画面角色明确为成人时，成人向/成熟向场景可安排嘴唇、眼部、胸部、腿部、臀部等局部特写；所有胸部/臀部/腿部特写必须以服装覆盖、姿态线条、剪影、光影轮廓、镜面/遮挡构图等影视化方式表达，禁止裸露、露骨性行为、低俗挑逗、未成年人或年龄不明角色的性化局部镜头。
   - **局部特写功能约束**：嘴唇特写用于口型、呼吸、停顿、欲言又止；眼部特写用于视线、泪光、瞳孔、警觉；胸部/肩颈特写用于呼吸起伏、服装材质、心跳紧张、权力姿态；腿部特写用于步伐、站姿、距离变化；臀部/腰臀线条特写只用于服装轮廓、转身、落座、走位节奏或遮挡转场。禁止把局部特写写成脱离剧情的孤立凝视。**群演/匿名背景人群例外（强制）**：局部特写/中景/中近景**原则上不分配给群演/背景人群**；群演仅作远景/全景/虚化 BG 层出现，见 §七.7-b。
   - **对话景别切分（强制）**：口型可读的对白、画内听者可见的 OS/V.O.、Shot-Reverse-Shot / OTS、反应镜、以及 `(Pn)` 段内须可读的微表情与微动作，**原则上**采用 **Medium Shot / Medium Close-up / Close-up / OTS**（中景、中近景、特写、过肩）；禁止在常规对话段落用 Wide / Full / Master / Two Shot 全景承载口型可读对白。听者反应、微表情链、微动作须与说话镜处于**同级或相邻一级**景别，保证面部与口部/眼部可读。**画幅比例外与强化**见下条「画幅比驱动的对话景别」。**例外**：特效相位、宏观群体主节拍（Stage 1 §28 + §5.5 E）须远景/全景主拍。
   - **画幅比驱动的对话景别（强制，读 Project Context `Aspect Ratio`）**：
     - **竖屏画幅（强制强化）**：当 Project Context **明确**为竖屏比例（如 **`9:16`**、`3:4` 等 height ≥ width 的声明）时，**原则上**每条口型可读对白须为该**说话人**单独分配 **中景或特写** P 段——**Medium Shot / Medium Close-up / Close-up / OTS / Dirty Single**；竖屏画幅窄、双人同框信息密度低，**禁**用 Wide / Full / Master / Two Shot / Establishing 承载说话人主拍落幅。多人对话须**按说话人逐句/逐组切换**至该人物中景或特写主拍（可 OTS 但落幅仍须说话人面部/口部可读）；Scene 建置 P1 若用全景/中全景，须在本镜内**尽快 Push In / Reframe** 至说话人近景。**Walk-and-Talk** 竖屏时仍优先 **Medium Shot / Medium Close-up** 跟拍，禁长时间 Wide 跟拍承载口型对白。
     - **横屏画幅（灵活安排）**：当 Project Context **明确**为 **`16:9`** 或未声明画幅比、且无从推断为竖屏时，对话景别**可根据剧情合适安排**——允许 Two Shot / 中全景关系镜、Walk-and-Talk 中全景跟拍、Scene 建置 Wide、以及 **§三.1 三前提满足时**的收束 Pull Back（落幅刚好适配下镜起幅，禁无因远景/全景）等，但仍须遵守本条「对话景别切分」口型可读禁 Wide 主拍之通则，以及 §三.1 景别递进、收束落幅、动作主体运镜等专规；不必机械要求每句对白都切至 MCU/CU，但说话人须保证面部/口部可读；**正反打链仍禁无因 Pull Back**。
     - **其他画幅**（如 `4:3`、`2.35:1`、`1:1`）：`画幅比继承:` 注明比例与竖|横判定；对话景别在遵守口型可读通则前提下，**竖向窄画幅倾向说话人中景/特写**，**横向宽画幅可按剧情灵活调度**。
   - **近景对话背景虚化**：并入上条「景深 · 深焦／浅焦」；近景对白**推荐浅景深**，须 ENV 轮廓可感知；空间关系优先时改深/中等。
   - **景别递进与防越级（强制）**：同镜内相邻 **P 段**景别变化原则上**逐级**递进或回退；禁止无动机地从全景直切极特写。情绪高点、上游 `细节特写`/【高潮与核心情绪点】、转场 Match 可例外，须在 `Shot Logic (CN)` 写明桥接依据。
   - **特写/中景/全景切换规则（强制）**：
     - **全景（Wide / Full / Master / Two Shot / Establishing）**：新 Scene 建置、空间关系首次交代、走位/调度展示、Walk-and-Talk、宏观/特效场面、群像关系；**禁止**作为常规口型可读对白的主拍落幅。
     - **中景（Medium Shot / Medium Full / Medium Close-up / OTS）**：对话主拍默认档、双人/多人关系镜、动作+对白同相位、听者反应镜；口型可读对白、OS/V.O. 听者、微表情/微动作须在 **中景或更近** 可读。
     - **特写（Close-up / Extreme Close-up / Insert）**：情绪高点、上游 `细节特写`/【高潮与核心情绪点】、**剧本/Beat 对道具的特别描述**（§三.1「道具特别描述特写运镜」）、微表情链落点、关键道具线索、口型/眼部精确读；每场须保留 §三.1 规定比例的局部特写。**群演/背景人群禁 CU/ECU/Insert 主拍**（§七.7-b）。
     - **群演/背景人群景别（强制，§七.7-b）**：匿名群演/背景人群簇**原则上不得**分配 **Medium Shot / Medium Close-up / Close-up / OTS / Dirty Single** 等中景或更近主拍；须写为 **Wide / Full / Master / Extreme Wide / Long Shot** 内的 **BG/MG 虚化层**（失焦群众、远景路人剪影、背景办公人员簇等——仍须可检索人数/规模与排列/队形，禁「背景有人」），禁 Push In / Rack Focus 对准群演个体、禁群演面部/口部可读特写。**例外**：宏观群体主节拍（Stage 1 §28 + §5.5 E）允许远景/全景群像主拍（满幅须规模+阵势可读），仍**禁止**群演 CU/中景单人主拍。
     - **切换路径（强制）**：`全景 → 中景 → 特写` 为默认同镜 **P 段**递进，用 Push In / Pull Back / Track / Rack Focus 等写清过渡。
     - **同镜收束落幅（强制 · Pull Back 三前提单权威）**：§5.5 的 Pull Back Reveal = **镜中过程**（可叙事用）；**本条只约束镜末收束扩框**（服务无跨镜记忆的下镜起幅）。`收束落幅判定` 只定本镜末 P；禁因收束另起 Shot。合镜封口/跨主后镜 P1 继承前镜出场实体。
       - **三前提（须同时满足才镜末扩框）**：①本镜末落在 CU/ECU/Insert/MCU（近景收尾）｜②下镜同主环境且 ≥2 具名 CHAR 同框可见｜③下镜**非**正反打/OTS/Dirty Single 对打链。**正反打绝不回拉**（肩背虚焦/双方合计≥2 亦不算前提②）。缺任一 → 保持本镜末景别；禁以「合镜封口/回建置/恢复全景」伪满足。
       - **满足时**：只拉到下镜起幅所需最小同框档（优先 MS/Two Shot/MFS）；写清相对 ENV 落位；**禁**无下镜宽景需求拉到 Wide/EWS/航拍。运镜 1.4–2.7s（§5.5 G）。Logic：`Pull Back前提=满足` + 目标/下镜起幅景别 + 幅度依据=刚好适配。
       - **不满足**：保持实际落幅；`Pull Back前提=不满足` + 缺项。硬禁：`下镜多人出镜=否` 或 `正反打排除=是` 却写满足。
       - **例外**：下镜跨主环境 → `例外=下镜换环境`（门槛/Match，不做回拉）；上游明文悬念停特写/全员已出画 → 写依据可保持。禁因「对白未完/情绪紧」强行回拉。
       - **档位**：扩框适配下镜｜保持本镜末｜环境切换起幅｜保持特写（须依据）｜出画落幅。Logic 必含 `收束落幅判定:`（前提=满足|不满足+缺项｜档位｜目标/下镜起幅景别｜特写收尾｜同主环境｜多人出镜｜正反打排除｜换环境｜幅度依据）。
     - **同镜内 P 段**：P1 可 Wide/MFS；对白中景/特写；终段仅三前提满足时扩框；正反打终段保持近景。

4. **摄影机运动**：每场≥1 高级运镜（§二.0 规划位置+衔接；**优先服务主高潮 / 人物弧光拐点 / 核心卖点揭示**；禁随机堆砌、禁浪费在无弧过场）；OTS 四要素§七.6；禁无声明越轴。
   - **运镜选用（强制）**：打斗/追逐/法术/轻功/宏观全覆盖。流程：①锁站位·Beat→Pn(§一.1A)→②回扣**卖点弧评估**/总规划支撑位/过渡选型/节奏→③经典语法择手法（只借语法不借站位/对白）→④§5.5 择 1–2→⑤核验递进·组合。`运镜选用依据:`=节奏｜站位摘要｜服务目标=建置可读|剧情|情绪|卖点|高潮|低谷弧｜经典语法类型｜衔接概要。禁先炫技后补位；反炫技/反贫乏见§二.6A。
   - **运镜递进（强制）**：能量①Static/微呼吸→②Slow Push/Soft Pan/Rack→③Track/Follow/Arc→④Handheld/Whip/Crash/Ramp→⑤Bullet/复合奇观。相邻同档或邻档；跨≥2 档须剧本触发+桥接。叙事弧：建置①–②｜对白②–③｜动作③–④｜奇观短插⑤｜收束回落；Pull Back 仅§三.1 三前提。景别收紧配 Push/Track In，打开配 Pull/Dolly Out。必填 `运镜递进链:`。
   - **运镜组合（强制）**：每 P **1 主导≤1 辅助**；禁同相≥3 高级名。合法：Track+Pan｜Push+Rack｜Follow+Soft Pan｜Handheld+短 Track｜Whip 独作桥。非法：Crash∩Dolly Zoom｜Push∩Pull｜Whip∩Slow Push｜Bullet∩常速缠斗无 Ramp｜鸟瞰∩口型 CU｜Static∩追逐主相。常速↔升格须 Ramp/软过渡。必填 `运镜递进与组合:`。
   - **题材硬约束**：追杀见§5.5 D｜打斗快慢§5.4.1｜轻功/宏观见§5.5 B/C/E + 对应 Logic 字段。

   - **对白运镜与说话人景别（强制）**：景别/画幅比权威见 §三.1；口型可读须 MS/MCU/CU/OTS + 显式运镜；多人按说话人分 P 段；格式见 §六.1。
   - **对白运镜例外（强制判定）**：
     - **无画内说话人**（NARRATOR、真画外 V.O./旁白、隔门/对讲/声源不可见）：**画内全员 明确 闭嘴**（§六.4）；拍听者/环境/声源方向，禁对不存在主体 Push In；禁任何画内角色张嘴对口型。
     - **自白/内心**：给予自白角色中景或特写，明确闭嘴（闭口/内心状），不按 lip-sync。
     - **Walk-and-Talk / 对白+位移**：Tracking / Follow / Lead，中景~中全景；禁硬推特写。
     - **背对/遮脸/大侧脸**：OTS / Reframe / 绕位至可读角度。
     - **Screen View / 画中画**：屏幕内说话人单独中景/特写主拍（§七.5）。
     - **句间 Insert**：可插，不得替代该句说话人主拍。
     - **抢话/单镜多句**：Whip Pan、反打或**同镜拆 P 段**；每句仍须主拍。
     - **3 人+**：Index 内具名角色单人/OTS 主拍，禁群体广角承载口型对白。
     - **特效/宏观场面**：Beat 含特效相位或全体宏观场面（大军、灾难、仪式、环境级事件等）须 **Extreme Wide / Wide / Full** 体现规模；对白以特效/宏观动势为主拍，说话人可为远景/全景群像或画外，口型非必读；可 intercut 说话人 MCU 但不得压过宏观/特效可读性。`Shot Logic (CN)` 标注例外依据。
     - **宏大特效满幅渲染（强制，继承 Stage 1 §8）**：上游判定为宏大特效时，主相位 Video 须写**画幅满铺**——前景介质 + 中景主体 + 后景边界/天际至少两层同时有可见变化；边界锚（地平/穹顶/城廓等）可读；粒子/碎屑/波前/鳞甲节段等**分相变化细节**逐 P 段写出增量（相对上一相多了什么）。结构=`满幅主相位 P 段` + `≥1 细节 Insert/CU P 段`（纹理/阵节点/巨物局部）+ `余波满幅或回落`。Logic 必填`宏大特效满幅:`（层级｜边界锚｜六相/P段变化增量摘要｜分相秒数｜细节Insert@P｜时长≥7.2s|对抗≥9s）。**禁止**半身光晕冒充满幅、一句「能量爆发」无增量、无细节却标满时长。本层只写光学/景别/运镜实现，**不改**上游因果与实体落点。
     - **宏观群体**（Stage 1 §28，`宏观群体=是`）：`宏观群体规模/三要素`（须含人数感+阵势队形）+ §5.5 E + EWS/Drone 满幅动势；稀疏 BG 小簇见 §七.7-b（同须人数+排列），≠ 宏观主节拍。
   - **对白收束与景别落幅（强制）**：本组 `(Pn)` 读完且微表演落点完成后再切 P 段/景别；镜末落幅 **仅按 §三.1 三前提**（禁据此拆镜、禁无前提/正反打回拉）。
   - **主要动作角色运镜与景别（强制，与对白运镜同级）**：凡本镜 P 段内**正在执行本 Beat 核心动作/主节拍动作**（§五.0）的角色——含发力/接触/受力、道具拾取交递穿戴放下、位移落位、开合动作、打斗/术法/投射攻击、环境结构交互等——须与对白说话人**同等强制**分配镜头，三项俱全、缺一不可：
     1. **显式分配景别**：依动作幅度与关键部位可读性择 Medium Shot / Medium Close-up / Close-up / Two Shot / OTS / Insert 等（遵守 §三.1 景别递进与越级禁令；打斗/追逐/宏观/特效相位按 §5.4.1、§5.5、§三.1 宏观/特效例外执行），**禁止**用 Static Hold + Wide/Full/Master 承载需要看清发力部位、接触细节或命中效果的核心动作。
     2. **显式写出运镜**：从 §5.5、§5.4.1 对应技法库择 1 项以上（Push In / Track / Follow / Pan / Handheld / Arc Orbit / Crane / Whip Pan 等），**禁止**只写"运镜跟随/镜头运动"等泛化词而不落到具体技法名。

     一 P 段内**同时**存在主要动作角色与说话角色时，二者须共享同一焦点主拍（§八.2 按角色组织）或按时序拆分为相邻 P 段分别落实，**不得**二者皆无明确景别/运镜；多角色同时动作（群体混战、多人协作等）按主拍/辅助分层，主动作者优先获得对应景别与运镜，辅助者可同框但不得反客为主。`Shot Logic (CN)` 须写 `动作主体运镜与景别:`（见 §十一模板）。
   - **道具特别描述特写运镜（强制）**：上游对 `PROP:` 的特别描述须在同镜 **Insert P 段**（Push In / Rack Focus / Macro CU 等）可读呈现；拆镜前扫描 Beat，未映射=失败须补 P 段。
   - **发光电子设备亮屏内容（强制，= Stage 1 正方向物件·亮屏内容）**：凡手机、平板、笔记本电脑、智能手表、车载/对讲屏、监视器、电视、全息/HUD 等 `PROP:` 在上游 Beat 写成**亮屏/来电/通知点亮/通话中**，且本镜画内屏幕面朝镜头或 POV/Screen View **可读**时，`Video Content (CN)` **必须写出屏幕上此刻可见的具体内容**——界面类型（来电/通话中/锁屏/通知/聊天/导航/监控等）+ 可读文案/号码/联系人名/图标态；**禁止**只写「屏幕亮起/蓝光映脸/看手机」而无屏面内容。屏面内容属 **Beat 态信息**（§0.05 允许），须逐字继承上游，**禁止**自造 UI/文案/联系人；上游仅「亮屏」无具体界面内容 → `Shot Logic` 标 `upstream_missing_screen_content` 回流，Video 只写「屏面亮起但界面文案不可核销/不可读」，**禁止**补最小界面。**接听/挂断/拒接后变化（强制）**：上游有接听、接通、拒接、挂断、切免提/视频等时，对应 P 段须写清**操作前界面 → 操作过程 → 操作后界面**（如来电「张三 来电」→ 点接听 → 通话中「通话中 00:03」）；**禁止**只写角色「接了/挂了」而屏面仍停在来电态或完全不交代变化。背板朝镜头/息屏/景别不可读时须明示**屏面不可读**；上游已有界面内容时，在可读 Insert/POV/Screen View P 段**转写**该内容（禁自造）。须可读的亮屏内容优先 **Insert / Macro CU / Screen View POV**。`Shot Logic (CN)` 写 `亮屏内容继承:`（PROP｜界面态｜可读性=是|否｜接听前后Δ｜特写P段=…）。

6. **闪回/回忆（强制继承 Stage 1 分档，禁止升格/降格）**：  
   - **闪回感双强制（光学 + 运镜；最高）**：凡进入回忆 / 回切当下，**禁止**只靠色调/叠化/柔焦而无机位过程，亦**禁止硬切入出**（含无声明硬切变色、Shot 边界纯硬切跳时空）。须同时落实：①**光学≥1**（**优先 OT-TX 胶片质感**，可叠 OT-DF/OT-CG/OT-FD/OT-SP）；②**运镜≥1**（从 §5.5 J 择进入手法 + 回切手法，可同族对称或互补）。Video 须写清**起幅→运镜过程→落幅/切 ENV**；Logic 必填 `闪回运镜:`（进入=…｜回切=…｜光学=…｜胶片质感=进入升起／回切褪去｜触发锚=眼/物/声/动作）。上游【场景切换与首节拍转场】已写运镜提示 → 本层落地执行，禁丢弃。  
   - **胶片质感入出（优先；进入与回切对称；最高）**：闪回 / 倒叙 / 梦境 / 想象等时空跳转的**入场与出场**，**优先**用胶片质感渐变承接——当下偏干净数码→往事卤化银/颗粒升起、轻微闪烁或细划痕、饱和与色温漂移；回切则颗粒收、饱和回当下。可叠叠化/柔焦/声桥，**不得**用剪辑硬切直接跳入往事或跳回当下。跨主拆 Shot（§二.1.5）时，前镜末 + 后镜首仍须写出该质感过程（Dissolve / Film Grain Rise-Fall），**禁止**两镜之间纯硬切跳时空。未用 OT-TX 须在 Logic 写替代光学依据（叠化/声桥/Match 等），仍**禁硬切**。  
   - **较长回忆 Scene**：上游已拆为独立闪回 Scene → 首镜走完整开场转场链（**含 §5.5 J 进入运镜 + 胶片质感升起**）；须完整 ENV 建置与实体落位，按常规拆镜；回切当下另场时同样写回切运镜+胶片质感褪去+光学；**禁止**并回当下 Scene，**禁止**场界硬切入出。  
   - **快速闪回（有情节；同 Scene）**：上游留在当下场的短暂回忆（对白 **>30 字** 或具名动作）；主节拍=快速闪回桥接；须写**进入运镜锚点→胶片质感升起→回忆内容→胶片质感褪去→回切运镜锚点**；质感 **OT-TX 优先**，可叠 OT-DF/OT-CG/OT-FD/OT-SP + §5.5 J 运镜（典型：Push Into Eyes→Film Grain+Dissolve｜Whip Pan 入出｜Match on Object｜Soft Dolly）；**可**独立 Shot 或短专拍组，Duration 通常 2.7–7.2s；须完整继承上游对白与微表演。回忆镜 ENV 挂上游闪回【主环境】族衍生（禁仍用当下主环境）；回切=跨主环境拆镜（§二.1.5）且须有回切运镜+质感过程。**禁止**本阶段另拆闪回 Scene。  
   - **无情节回忆切片（转场式；同 Scene）**：上游仅印象/情绪/物象触发，**无对白链、无完整动作情节**；**按转场处理**，**禁止**升格为独立闪回 Scene 或扩写对白/动作链。**拆镜**：**并入相邻 Shot 转场链**（P 段内光学桥或镜末桥接），**不必**单独建闪回 Shot；写法：触发→**短运镜桥**（Push Into Eyes / Whip / Match / Soft Push / Defocus Pull，择 1）→**胶片质感升起**→**≤1.8s 单幅/1–2 帧印象切片**（剪影/局部/色块/物象，**不要求**完整 FG/MG/BG 建置与口型）→ 去色/虚化/颗粒/柔焦（OT-TX、Defocus、Color Grading 等）→ **胶片质感褪去 + 短运镜回切**当下微反应/声残响；**主节拍仍归当下场**；`Shot Logic (CN)` 须写 `无情节回忆切片:`（触发/切片要点/回切/`闪回运镜`进入+回切/光学/胶片质感/是否并入本镜）。**计时**：计入 `转场/停顿Xs`，通常 **0.5–1.8s**，与触发/回切同相位时并入并行核，**禁止**为无情节切片单独全额建置计时。上游已立闪回主环境时，切片画面仍须可识别挂该 ENV 名（可不完整建置）。**禁止**用「闪切/硬切」代替质感桥。  
   - **≤30 字且有具体情节**：不闪回，当下反应/OS，本阶段不出回忆镜。  
7. **特殊时空（蒙太奇等）**：除上条外，蒙太奇/梦境/意识流等用**运镜+声画+质感**过渡；可用胶片颗粒升起/褪去、Defocus、Color Grading、亮度压低、慢速运镜（Soft Dolly / Slow Push）、Whip / Match 切点、纹理/噪点衰减、声效淡入淡出——**禁**无运镜硬切堆片段。**蒙太奇多主环境（同 Scene）**：上游同场多【主环境】时，相邻 Beat 主环境不同 → **按 §二.1.5 跨主环境拆 Shot**；各镜 ENV 挂对应主环境族衍生，禁混挂；点间切换须有 §5.5 J 或 G 过程运镜 + 光学/质感桥；**禁止**本阶段把蒙太奇拆成多 Scene。

### 四、灯光设计 (Lighting Design)

**权威 = §0.06**（提取、可见/不可见分流、配额≤3、防悬浮 3/4、实体指称）。本节只补**执行清单与独特硬约束**；光动**只写**「动态连续光影/焦点」「光线连动弧光」；与 §七.7 物理微动分写。**禁**借光影改站位/动作/对白。灯光与色彩须**服务剧情节点 + `scene_mood` 主情绪**（压迫压暗仍保主舞台可读；温煦暖 Fill 托起；悬疑冷 Key + 局部 Practical），并与焦距/构图同核（硬约束 10）。

1. **动笔顺序**：读 Index `scene_mood` → 读 ENV CN `光影体系`/`色彩体系` → Logic `光影锚定:` + `摄影综合表达:` → Video 两光影段按 §八.3–§八.4 书写顺序输出。
2. **§四.5-E 面部可读 Fill（真人优先，服从 ENV CN；≠压扁大光比）**：侧向 Key + 半影柔散｜Fill **仅** ENV 已声明反射面反弹或第二画内 Practical，保面部/口型**关键信息可读**（禁无 ENV 锚点美颜补光、禁面部局部 spotlight、禁整室同亮/均匀平光抹平 ENV 大光比）｜Rim 须有 ENV 入射动机（禁硬 rim）｜投影软过渡（禁刀切阴阳脸；恐怖/上游压暗例外）。**继承效果、不抄数字**：Stage 3 ENV 大光比以亮暗分层/冷暖对照落入 Video，**禁**写 `Key:Fill≥8:1` 等数值。
3. **独特硬约束**
   - **门外作光源**：须先核销门为开启态；`光影锚定:` 写 `门外光源门态=半开|全开｜核销依据=…`；门紧闭禁门外主动机；门外灯具不可见时只写渗光效果、禁实体名（§0.06）。
   - **Key/Fill 角色名实一致**：Key=照亮；Fill=托起暗部（禁把 Fill 写成加深阴影）；入射须与 ENV 几何一致。
   - **照度**：室内/日景默认充足（可见动机光 1–3 + ≥1 反射 Fill）；低照度须上游依据。
4. **两光影段覆盖（10 取 8，细则定义见 §0.06）**：(1)可见光源清单1–3 (2)Key方向与照亮面 (3)各可见光源作用范围 (4)可见效果 (5)多实体受光/投影分层 (6)Fill/Rim/暗部可读 (7)冷暖对照（须核销 `scene_mood` 光色倾向 + ENV 主辅色谱） (8)光学响应非外形+接地影/色溢出 (9)运镜中光向连续 (10)CHAR/PROP 融入防悬浮（同场同光，色彩跟 cue）。
5. **Logic 必填**：`光影锚定:`｜`光影继承:`｜`光源充足性:`（可见动机光个数≤3｜低照度例外）｜`摄影综合表达:`（须含色彩+灯光如何兑现情绪）。输出前自检：可见具名/不可见仅方位｜与 ENV 一致｜Fill 有反射依据｜门外光源门态｜无位置前缀｜无不可见实体名｜≤3｜冷暖分层｜**情绪光色不打架**。

| 机位 | Handheld/Whip/Track/Follow 跟轨迹 | Bullet Time/Orbit/CU 钉节点 | 快跟同向同速；慢对准命中点/接触面 |
| 播放 | 100% | Slow/Hyper/Bullet/Time Slice | 每次切换 Speed Ramp 入/出各 0.3–0.45s |

**快相位**：起势连招、闪避、弹道出手→逼近、追逐、域场建规模。运镜：Handheld｜Whip｜Track/Follow｜Crash Zoom（常速）｜Drone 读规模。每链 ≥1 快连击 P（≥2 击具名+攻防匹配，≥1.8s）；禁多击全拆升格、禁单方无反应堆招；**具名连击须继承上游差异化招式，禁同构复制**。机位须跟实体/弹道；禁 Static+Wide 扛高速。单段 1.8–3.6s；快总时长 ≥ 升格×2。

**慢相位**（每链 1–2 处）：命中/对撞/爆炸/格挡｜弹道可读节点｜弧顶/触地｜终结技破防（仅 1 处）。运镜：Bullet Time｜Time Slice｜Orbit 绕命中｜CU 读受力。钉住 Beat 轨迹节点；禁空镜慢飞。单段 0.9–2.7s；累计 ≤35%；>3.6s 须拆。

**Speed Ramp**：入慢=接触前末帧/节点可读；出常=读毕→反馈/余波。默认 `常速→升格→出常`；合镜封口后镜用 Match/Whip 衔接。失败：整镜单速｜Z>40%｜无 ≥1.8s 快连击｜无 Ramp｜机位不跟｜慢未钉节点 → 补写 P。

**类型速查**：近身 Handheld/Whip↔Bullet 命中｜弹道 Follow↔Time Slice｜法术 Orbit↔对撞慢｜腾空 Track↔弧顶短慢｜连击多段快+1 处终结升格｜域场 Drone↔波前慢｜载具 Follow↔撞击 Bullet。

**P 段**：快=运镜名+跟拍对象+轨迹向+常速+逐招具名+攻防匹配；慢=升格技法+锁定节点+可读信息；变速=Ramp 方向+落幅。禁「快速打斗/慢动作效果」泛化句。

**Logic 必填**：`快慢节奏:`（各 P=常速|升格|变速+运镜+节点+秒+`升格占比`）｜`快连击链:`（逐招+攻防）｜`升格技法:`（选用+触发+第几处）｜打斗另 `打斗运镜技法:` + `打斗正反覆盖:`；特效另 `特效攻击运镜:`（§5.5 A；法攻须正反两端）。

**反例**：❌ 全程常速无升格｜❌ 整镜 Bullet 拖镜｜❌ Z>40%｜❌ 无快连击/缺招名攻防｜❌ 弹道飞出镜头不动。
- ❌ 升格段实体仍在高速位移，未钉住命中/接触节点。
- ❌ 有 Slow Mo 无 Speed Ramp 出入，硬切速率。
- ✅ P2 常速 Handheld **快连击** 3.2s（**甲：右直拳→左勾→侧踢；乙：架肘格挡→侧身闪避→反刺**，Whip Pan 衔接）→ P3 Speed Ramp 入慢 + Bullet Time 读**侧踢**命中 1.4s（**升格占比≈1.4/6.8≈21%**）→ P4 Speed Ramp 出常 + 受力反馈 2.2s。

#### J. 闪回/回忆运镜关键词（`闪回运镜:`；§三.6 强制）
**用法**：进入回忆与回切当下**各择 ≥1**（可对称：进 Whip→回 Whip；或互补：进 Push Into Eyes→回 Soft Pull）；**默认叠 OT-TX 胶片质感**（进入=颗粒升起，回切=颗粒褪去）；写入 Logic `闪回运镜:` + Video 起幅→过程→落幅。动机须挂触发锚（眼/脸/物件/声桥/动作），禁无锚炫技。

5. **道具连续**：拾取/穿戴后每镜交代仍握持/仍佩戴，直至明确放下。

### 六、对话的镜头实现（内容=Stage 1；本层只写景别/运镜/口型可读）

**语气层 / 对谁说 / 称呼锁定 / 情绪标点 / 小语种·方言标签 / 音效尖括号 → 唯一权威 Stage 1**（本层**不展开字段定义**）。本分镜只做：逐字写入 Video + 为说话人分配景别/运镜（§三.1）+ 音效落位可听。

#### 六.0 语气层写入（强制，零删改）
- Beat 每条对白/OS/V.O./自白 → Video 对应 `(Pn)` **完整携带**上游语气层括号（含 `对{听众/方向}` + 八字段）；缺任一项=继承失败。
- 禁改对象/方向/重读词/标点；`rhythm`/`stress`/`pause` 须落到可拍微表演相位（服务口型与 §二.4 语言耗时）。
- **写面部微表情前必须确认正面（最高）**：画内可对口型说话人：`(Pn)` **须 ≥1 项面部微表情**（与 tone 咬合）——**前提**=该说话人本相位正背面=`正面/¾朝镜头可读`（`侧正面`≡¾）；若建置为`背对/侧背面` → **禁止**写面部微表情/口型句，改为背面可见外化，或先切其**上游白名单内**可读角 ENV 镜再写对白脸句（无可读角→回流 Stage 1，禁自造）；听者微表演同核听者正背面（背对听者禁写唇角/眉眼，改肩背等）。**禁**为凑「须≥1面部微表情」在背影上写脸。
- `voice_type=自白/独白/内心/OS/V.O./旁白`：跟 Stage 1 闭嘴+非口型外化；背对时外化只许背面可见面。
- 听者写上游已有微表演，**禁补创**；但须过可见面过滤器（背对不可原样贴脸句）。
- Logic：`语气层继承:`（N 条｜对谁列表｜特殊 pause/rhythm｜无则写无）+ `表情正背面核销:`（见§一.1）。

#### 六.0A 小语种 / 方言台词承接（强制，零译抹）
- **识别**：上游入戏对白含「用{语种|方言}说道」或等价明文（如 `用日语说道` / `用粤语说道` / `用四川话说道`）时，本镜 **必须**在对应 `(Pn)` **原样保留**该语种/方言标签 + **原文台词**（Stage 1 花括号 `{…}` 内全文；写入 Video 时可用 `"…"` 外壳，但**正文逐字不变**）。
- **禁止**：译成项目主语言/普通话/英文后冒充原台词；删掉语种/方言标签只留译文；用同义改写、繁简转换、罗马化转写替代原文；把方言「规范化」成普通话。
- **标准普通话 / 英文**：上游未标语种/方言时不必加标签；仍须逐字继承台词正文。
- **Logic**：有则写 `语种方言继承:`（语种|方言列表 + 对应说话人 + 原文可检索=是）；无则写 `语种方言继承: 无`。
- **与项目 Language 关系**：`# Project Context` 的 `Language` 只约束主体语种与全局风格注入；**不得**据此覆盖本条已标注的小语种/方言原文。

#### 六.1 对白写入格式（Video）
`(Pn) {说话人面部微表情+状态——仅当正面/¾可读；背对则写背面可见外化} — Dialogue (CHAR:[@名]) (对{听众/方向}, voice_type: …, voice_identity: …, tone: …, speed: …, volume: …, rhythm: …, stress: …, pause: …): [用{语种|方言}说道]"{逐字原文}" — {听者微表演——同核正背面}`

#### 六.2 音效承接（强制，零删略）

#### 六.4 OS/V.O./旁白/自白运用
凡上游 `voice_type∈{画外音,OS,V.O.,旁白,自白,独白,内心}` 或真画外/旁白相位：`(Pn)` **须明文写闭嘴/闭口**（禁只挂声却写张嘴对口型）。①OS/V.O./旁白/画外音→**画内全员明确闭嘴**（含群演）；声源标 `NARRATOR` 或对应 `CHAR:[@…]`（画外）；拍听者/环境/声源方向，禁对不存在主体 Push In 对口型。②自白/独白/内心→发言人**闭口/内心状**（不按 lip-sync）+画内他人闭嘴；须保留方向锚（对镜头｜望天｜望远｜对空位等）。**语气层**：OS/V.O./旁白/自白/独白仍须 **§六.0 全字段 inline 继承**（含 `对{听众/方向}` + `voice_identity`）；画内闭嘴≠省略语气层；不按 lip-sync 但 `(Pn)` 段须保留 Beat 原文语气层块供 TTS/后期。**小语种/方言 OS/V.O.** 同 §六.0A，标签与原文不得译抹。**背对角色**：自白/OS 外化只许背面可见面，禁唇角/口型。

#### 六.5 自然生理微动作与运动纹理保真（摄影真实感，禁表演二创）
补充 §四.5-E / §六.3：**只写**动态真实感提示（非外形；§0.05）——自然眨眼/眼球微动/发丝随动清晰；禁整镜瞪眼定格、禁「柔化/磨皮」、禁借此写骨相/肤质。有对白或 >3s 静态特写时 Logic 可标 `自然眨眼:已写`。**禁止**据此补创 Beat 未写的情绪微表演。

- 与 `观察视角继承:`、`环境切换运镜:` 配套；即使 N=0 也必须挂`0度{主环境名}`衍生 ENV，**不得把裸主环境当当前镜头约束**。

**`Video Content (CN)` 转译规则（强制，禁遗留推导信息；禁照抄【Beat切换说明】）**
- 切换说明**通常已剥离**——名单/跨拍以【建置】+【入戏】推断；若偶发残留，拓扑/转角/可见性 Delta **只进 Logic**，正文**只输出画内可见**；**禁止**粘贴切换说明原文、推导字段、度数、不可见半空间说明。
- **只写可见（最高）**：Video **只描述画内可见**的机位、运镜、实体与背景；**禁止**写「不可见」「不再看见」「机位后方半空间」「画外某某」「退出可见」等——画外/后方内容**沉默省略**，不得点名也不得用「不可见」占位。
- **禁度数入 Video（最高）**：正文**禁止**出现 `0度/90度/180度/270度`、`顺时针回转 N 度`、`回转 180 度`、`N_对手`、`(N+180)%360` 等角度工程表述（含阿拉伯数字+度作拓扑坐标）；切角用 **运镜名**（Reverse Shot / Arc Orbit / OTS / Pan to New Axis 等）表达过程。度数推演**只留 Logic**。
- **必写要素（衍生 ENV 或正反/OTS/POV 切换时）**：POV/FPV **以主观角色视角建置、默认不包含主观角色自身**（细则 §5.5 H-POV：不可见则零描述；局部入镜须部位+入镜方式）。
  1. **机位落点**：站在/位于哪一结构侧（如「会议桌长边侧面、胸口高度 Eye-level 平视，镜头水平」——**仅当该侧发光墙体本镜画内可见时**才可点名窗/灯实体）。POV 贴地/倒地主观 → 写物理高度与朝向（Ground-Level / 贴地仰看天花板）。**俯仰缺省=平视仍须写出**（§三.1）。
  2. **观察朝向 / 运镜过程**：用运镜名写切换（Reverse Shot、Left-Shoulder OTS、POV Handoff、Pan to New Axis、Motivated Reframe、Arc Orbit 等）+ 空间锚点（沿桌轴线/门槛轴线等）；**禁**写回转度数。
  3. **背景更替**：用自然语言只写 BG **看见什么**（✅「背景为半开木门与门外冷蓝走廊」）；**禁**补写机位后方/已退出可见实体，**禁**「…不可见」句（❌「百叶窗位于机位后方」｜❌「机位后方半空间不可见」）。
  4. **方向性物体可见面**：椅背/椅面、门扇开向、桌头/桌尾、床头/床尾、主客位等按当前机位写**可见面与画面左右**，禁沿用主视角朝向。
- **`ENV:[...]` 标签**：Index 原名（含 `{N}度` 前缀）**保留**作环境标识；正文空间描述须用镜头语言，**不得**把 ENV 名中的角度数字当画面说明复读。

**正反/OTS 专规**
- **OTS读对手 vs 同侧过肩（强制；对齐 Stage 1）**：
  | 类型 | 判定 | ENV |
  | :--- | :--- | :--- |
  | **OTS读对手 / 反打** | 越过近侧肩看**对方脸/对手可读面**；背景半空间相对上相位翻转/对向 | **必须**切至上游白名单内对向 `{N}度…`（常±180°）；禁同父 ENV 冒充 |
  | **同侧过肩（非反打）** | 仍看**同一观察半空间**；近侧肩仅构图框，不换对手可读面、不改背景扇区 | **沿用当前 ENV**；禁另标反打、禁另造角度 |
- **OTS 四要素（强制，`Shot Logic` + `Video Content` 均须可检索；缺任一=不合格）**：凡标 OTS / 过肩 / Left-Shoulder / Right-Shoulder，须同时写清——
  1. **过谁的肩（肩主）**：前景虚焦肩框归属人，须写 `CHAR:[@…]`；禁止只写「过肩」不写肩主。
  2. **肩主可见面**：机位相对肩主从哪一面取过肩框——**左侧面 / 右侧面 / 正面 / 背面**（可写四分之三背、后脑勺侧等，但须落四选一主类）；经典 OTS 多为**背面**或**侧面**见肩线/后脑；禁止只写肩侧不问可见面。
  3. **左肩或右肩**：Left-Shoulder（过肩主左肩）| Right-Shoulder（过肩主右肩）；须与画面左右、轴线留白一致（左肩常占画左/右缘须自洽）。
  4. **过肩后看谁（主拍）**：主焦点对象 `CHAR:[@…]` + 其相对镜头的**正/侧/背面及口型/表情可读性**。
  - **推荐句式**：`过 CHAR:[@甲] {可见面}{左|右}肩 → 看 CHAR:[@乙] {正/侧/背面}{景别}`；例：`过 CHAR:[@Lin] 背面右肩 → 看 CHAR:[@Chen] 正面中近景`；`过 CHAR:[@Chen] 左侧面左肩 → 看 CHAR:[@Lin] 四分之三面 MCU`（**禁**剥成裸名 `Lin`/`Chen`）。
  - **Shot Logic 摘要字段**：`OTS四要素: 肩主=…｜可见面=左侧面／右侧面／正面／背面｜肩侧=左肩／右肩｜主拍=…+可读面=…｜类型=OTS读对手|同侧过肩`
  - **反例**：❌ `Left-Shoulder OTS，Chen 中近景`（缺肩主与可见面）｜❌ `过肩看 Lin`（缺左/右肩与肩主可见面）｜❌ `OTS 反打`（四要素全缺）｜❌同侧构图过肩却切未登记 ENV｜❌OTS读对手却同父 ENV。
- **OTS/反打 ENV 角判定（强制，禁止盲套主环境+180°；目标 ENV∈上游白名单）**：切 OTS/反打衍生 ENV 前，须据上游 Beat 判定**被拍对象/对手**在主环境 360 度拓扑中的可读观察角 **N_对手**（落位+面向+轴线）；本镜 ENV 角 = **`(N_对手 + 180) % 360`**，且该 `{N}度…` **须已在上游 Scene/Beat/Index 声明**——**禁止**分镜层发明未登记角度。**不得**不经判定一律用主环境 0 度 + 180 度。例：对手可读角 90° → ENV 270°；对手可读角 0° → ENV 180°。上一镜已在衍生角 M 时，仍须以对手可读角推导，而非「M+180」或盲套 180 度 ENV。白名单无对应角 → 回流 Stage 1。
- 正反/OTS 须写同一空间锚点（桌中线/门框/门槛）+ **连续运镜过程**切换至对侧（**禁 Static 硬切**）；Shot Logic 写 **N_对手**、**`(N_对手+180)%360` 目标 ENV 角**、**OTS 四要素**及可见 Delta（禁只写「180 度互补」而不列对手角；上述**只进 Logic**）；Video Content 写 **Arc Orbit / Pan / Track + Reverse/OTS** + **四要素落幅句** + **画内可见** BG **渐进**更替 + 椅背/门扇等可见面重判 + **三分构图自然留白**（§七条目7）；**禁**回转度数、**禁**「不可见/机位后方」句。
- **闪回/蒙太奇切主 vs 反打（标签）**：换主环境名=`闪回切主环境|蒙太奇切主环境|回切当下主环境`（**非反打**）；同主名±180°可读对手=`反打/OTS读对手`。禁混标。

**转译口径**：Logic 度数/Delta → Video **运镜名 + 画内可见 BG + 方向性物体可见面**；禁照抄切换说明/工程字段/不可见句/度数回转。❌ 写机位后方实体或「不可见…」｜✅ `过 CHAR:[@Lin] 背面右肩 OTS 看 CHAR:[@Chen]；环境切换到 ENV:[180度…]；Arc Orbit 至桌内侧，背景为半开木门与走廊`（看不见的沉默省略；实体须保留完整 `CHAR:`/`ENV:` 前缀）。

#### 7.7 环境背景微动态（强制）
每镜 BG/可见 ENV **≥1** 项全镜持续**实体物理微动**（禁静态空镜）。近景对白可写虚化背景中已有实体微动（§三.1）；**禁**光斑/bokeh 顶替（光学进光影两段）。

**实体白名单（最高）**：P1–Pn/`(Pn)`/微动点名的环境陈设 ∈ 剧本∪Beat∪Index∪本镜 ENV 清单；**禁**为凑数新增未出现实体。无可动锚→对已有结构写极轻态 1 句，仍禁造实体。匿名人群簇仅上游已暗示时可写（§七.7-b），禁具名新角色。

**双层（强制）**：①ENV 实体物理微动（每镜必填，无人群亦须）→②有簇时追加人群随机动势（禁用人群替代①）。P1 BG 必写；P2+ 延续/随 BG 更替更新白名单项。幅度 subtle、不抢主拍；宏观禁整齐机械同步。光影禁入本段（§0.06）。选型：只从白名单择 1–2（树冠轻晃/窗帘轻摆/远距车流/雨丝/旗帜等——实体须已出现）。

#### 7.7-b 背景人群 / 群演簇（有簇时追加；继承 Stage 1）
**人数与排列（最高）**：凡 Index/`CHAR:[@簇名]`/Beat 建置出现群演簇，Video P 段须可检索——①**人数/规模**（约N人／两排各6／百人方阵等；禁裸写「众人/一批」）；②**位置排列/队形**（镜头相对落位带 + 内部排布：整齐纵队／横列／方阵／扇形围观／散点簇／前后梯次等）；③主导正背面/姿态短注（虚焦同框亦可点名）。军警/卫兵/军队/仪仗等制式簇须写**整齐度与行列**（如`三列整齐纵队齐肩`）。上游缺规模或队形 → Logic 标 `upstream_missing_crowd_scale_or_formation`，**禁臆造**。
簇位+人数/规模+排列/队形+虚化 → 氛围杂装簇内≥2 种随机微动作（禁机械齐步同步）；制式阵列**继承上游整齐队形**，微动仅为呼吸/甲叶轻晃级、**不打散行列**；禁跨镜复用同组合；景别 Wide/Full/EWS；禁 CU/OTS 主拍。≠宏观主节拍（§5.5 E；宏观另写满幅规模+阵势）。

### 八、视频提示词要求 (Video Content Prompting)

只写入 `Video Content (CN)`：`Shot Logic (CN)` **仅** §Logic-FMT 极简标签（禁散文）；本字段**只写**发给 AI 视频模型的纯画面结果。维度间用 `<br>`，共五段 + 固定收束句：**全局动态风格 / 运镜与动作流 / 动态连续光影·焦点 / 光线连动弧光 / 物理文字生成 / 品质收束**。

**写法要点（强制）**
- 叙述体；禁键值体/`FG/MG/BG=`拼贴；层位用「近处/纵深/画面左」等自然语言（§七.3）——**但实体指称必须用标准标签**，不得为「更像自然语言」而剥掉 `CHAR:`/`ENV:`/`PROP:`
- **只写画面结果**：禁承接说明/规则判定/环节号/§引用/Logic 字段入正文；光影**只**进两光影段
- 实体/ENV 零缺失(§一.1–1.2)；标准标签(§一.0.1)；**建置标签全代入、与入戏同等、禁剥前缀**；白名单(§七.7)；外形禁复述(§0.05)
- 禁【Beat切换说明】/度数工程坐标/「不可见」句入 Video——黑名单与转译见§七.6；`ENV:[…]`/`CHAR:[@…]`/`PROP:[…]` **必须**保留完整前缀与 Index 原名
- 追杀跟拍须写「约占 Xs」（§5.5 D），计入 Duration

1. **全局动态风格（强制，§一.3A）**：首句注入上游已有类型+语境+风格定位；类型 1–2 条正向落点；禁自拟题材/补陈设。
2. **运镜与动作流**（只输出画面）：

   **P 段骨架（强制 · 细则权威 §一.1A / §二.6 / §二.1.5 / §二.6A / §二.3A / §三.1）**
   - 序：P1=开拍建置集全员落词（**景别+镜高俯仰+景深+焦距/透视+构图落点**+完整 `ENV:[…]`+各 `CHAR:[@…]`/`PROP:[…]` 落位/朝向/姿态/距离；**群演簇另须人数/规模+位置排列/队形**（§七.7-b）+§七.7 微动；禁动作/对白/光影；**建置标签不得省略或剥前缀**）→ P2…Pn=挂靠站位入戏（景别→**俯仰若变则写 Tilt/Crane 过程**→**景深/焦距若变则写变浅/变深/Rack/收焦**→运镜起落→动作/对白 `(Pn)`；主语/对象仍用完整标准标签，与建置同等；簇在场则规模/队形短注可挂靠继承）
   - SH02+ P1 咬合上镜末（§二.6）；禁每镜重开 Wide；近景非主拍者仍须过肩/虚焦/画缘点名
   - Pn 不丢空间锚；ENV 名变须「环境切换到 ENV:[…]」+过程运镜；出入画须过程；过渡选型§二.6A；快档 Handheld
   - Logic 字段：`内容继承核销`/`建置角色覆盖`/`运镜服从站位`/`观察角度`/`景深`/`焦距`/`构图规划`/`摄影综合表达`/`总规划`/`过渡选型`/`Beat衔接运镜`/`前接`/`分镜衔接`/`P段时序链`/`运镜递进与组合`
   - ✅ P1 全员站位+平视+深景深+标准焦+构图落点 → P2 MCU+平视+浅景深+中长焦+Soft Push 对白 → P3 OTS/Arc 或边界硬切预留 → 收束｜❌ 跳过建置｜❌ 只写 MCU 不写平视/景深/焦距｜❌ 五技与 `scene_mood` 无对账｜❌ Pn 丢左右距离｜❌ 合镜 ENV 用硬切躲过程｜❌ 全 Static

3. **动态连续光影/焦点（强制 · 权威 §0.06 / §三.1 景深 / §三.3 焦距）**：与下段独占光学。序：可见源(1–3)→作用→Key/Rim→Fill→投影→接地影/色溢出→冷暖（核销 `scene_mood` 光色）→**焦平面/景深虚实/焦段透视（浅景深 bokeh/散景光斑写于此，禁回 Pn）**→运镜连动。不可见源零实体名；≥3 ENV/PROP 受光面 + 每主 CHAR≥1 句。

5. **物理文字生成**：上游有则写可见关系；无则「无」。
6. **品质收束（强制，逐字固定）**：五段后以独立句结尾：`人物面部稳定不变形，动作自然流畅，无卡顿无闪烁，无背景音乐，无字幕，视频全程禁止出现外形、着装、配饰完全一致的人物，禁止生成同款分身、双胞胎效果，同一画面中仅保留单个对应人物，不出现人物重复复刻，高清，细节丰富，电影质感，色彩自然，光影层次清晰可读`。禁改写/漏写；末尾自检须等于该原文。

### 九、兼容列留空规则 (Empty Compatibility Columns)
1. 保留原表头与列顺序（**固定 14 列，顺序不可增删/调换**）；除 `Video Content (CN)` 外，Start/End/Keyframes 及其中文列均留空。
2. **留空列写法（强制，防列错位）**：须留空的列写为**空单元格** `| |`（两竖线之间可有 0–1 个空格），**禁止**：
   - 多写或少写 `|`（每行 `|` 分隔后的单元格数必须 = 14）；
   - 在空列位置插入占位符（如 `-`、`N/A`、`无`、`空`、`(留空)`）；
   - 在 `Duration (s)` 与 `Video Content (CN)` 之间、或 `Video Content (CN)` 与 `Associated Entities` 之间**额外插入空 `|`**（这是最常见错位源：多一个空列会把 `Duration` 挤进 `Video Content`，导致 apply 失败）。
3. **列位对照（强制，输出前默数）**：

| # | 列名 | 本分镜填什么 |
| :--- | :--- | :--- |
| 1 | `Shot ID` | `{Scene ID}_SHzz`（§二.8；含字母后缀如 `EP01_SC01B_SH01`） |
| 2 | `Shot Name` | 核心动作简述 |
| 3 | `Scene ID` | 上游原样（如 `EP01_SC01` / `EP01_SC01B`） |
| 4 | `Shot Logic (CN)` | **极简标签串**（§Logic-FMT）；字段间 `<br>`；**禁散文、禁裸换行、禁未转义 `\|`** |
| 5 | `Start Frame` | **空** |
| 6 | `Video Content` | **空**（英文视频列不写；内容只进第 11 列） |
| 7 | `Duration (s)` | **正整数秒**（如 `11`）；基准 T ≤MaxShotSeconds 时由 §二.4 **±20% 浮动**取整，钳制 [4, MaxShotSeconds]；**基准 T > MaxShotSeconds 时强制填 MaxShotSeconds**（不拆镜）；禁空、禁单位后缀、禁小数（除非上游明确要求） |
| 8 | `Keyframes` | **空** |
| 9 | `End Frame` | **空** |
| 10 | `Start Frame (CN)` | **空** |
| 11 | `Video Content (CN)` | **完整中文视频提示词**（§八）；单元格内换行只用 `<br>`，**禁裸换行、禁未转义的 `\|`** |
| 12 | `Keyframes (CN)` | **空** |
| 13 | `End Frame (CN)` | **空** |
| 14 | `Associated Entities` | 本镜 `CHAR:`/`PROP:`/`ENV:` 标准标签，逗号分隔 |

4. **正确空列骨架（复制对照）**：`Shot Logic` 之后到 `Associated Entities` 之前，空列模式必须是：

```text
| <Shot Logic> |  |  | <Duration> |  |  |  | <Video Content (CN)> |  |  | <Associated Entities> |
```

即：Logic 后 **2** 个空列 → Duration → **3** 个空列 → Video CN → **2** 个空列 → Entities。  
**错误示例（多一个空 `|`，禁止）**：`| <Logic> | | | 11 | | | | | <Video CN> | | | <Entities> |`（Duration 与 Video CN 之间多了一格，解析后 Duration 错位）。

5. 完整性校验 `Shot ID`、`Scene ID`、`Shot Logic (CN)`、`Video Content (CN)`、`Duration (s)`、`Associated Entities`：**`Shot ID`/`Scene ID` 须满足 §二.8 三层编码与连续编号**；实体列与正文须满足 §一.0.1 标准实体表达双源交集规则；**`Video Content (CN)` 须逐镜核验 Beat 实体零缺失 + 建置标签全代入**——本镜承担 Beat【建置】与【入戏】中每一个 `CHAR:`/`PROP:`/`ENV:` 须以**完整前缀+方括号名**在正文可检索（禁正文裸名、禁只列 `Associated Entities`）；`Associated Entities` 不得多于正文引用、正文不得少于 Beat 实体清单；**须逐镜核验建置可移动主体全覆盖**——枚举=`【建置】∪【入戏】主语`（含金身/法相；合镜并集须**全镜按时序**可检索，P1 仅须含首 Beat 开拍集），`Shot Logic` 的 `建置角色覆盖:` 漏项须为无；**有宿主↔法相直接因果时须核验同相位双方动作与原则同步**（`宿主法相因果:` 漏侧=无｜动作同步=是或已核销例外）；**须逐镜核验环境标签**——最少含 1 个 `ENV:[...]`，本镜有明确环境切换要求时须按切换次数写出对应数量的 `ENV:[...]`，缺失或数量不足须补写后再输出（§一.1、§一.2、§一.3、§七.4、§八）；**须逐镜核验合镜 ENV 切换**——合镜 N≥2 时，对组内每一对相邻 Beat：若二者当前 `ENV:[...]` 名不同，则 Logic `Beat衔接运镜` 须含该桥 `ENV/观察侧=切换` + `ENV链=旧→新`，Video 对应相位须含「环境切换到 ENV:[新]」（或「切换到 ENV:[新]」），且新旧 ENV 均在正文与 `Associated Entities` 可检索；任缺 = 补写后再输出（§二.1.5）。

### 十、最终标准输出 (Final Output Format)
- 只输出一张 Markdown 表格；禁表外寒暄、思考过程、代码围栏、表前/表后说明文字。
- **表结构（强制 · 管道唯一合法 schema）**：
  1. **第 1 行**：表头，列名与顺序**逐字**与 §十一「表头与示例」一致（**固定 14 列**，英文列名，含括号与空格）。合法表头原文：  
     `Shot ID | Shot Name | Scene ID | Shot Logic (CN) | Start Frame | Video Content | Duration (s) | Keyframes | End Frame | Start Frame (CN) | Video Content (CN) | Keyframes (CN) | End Frame (CN) | Associated Entities`
  2. **第 2 行**：分隔行，恰好 14 段 `| :--- |`（或等价 `---`），**禁止**少段/多段。
  3. **第 3 行起**：数据行；每行单元格数 = 14；行首/行尾各 1 个 `|`。
- **禁止自创/改写表头（最高硬约束，违者整表作废）**：  
  - **禁止**输出中文列名表或任何「精简分镜表」（如 `Beat-Shot映射` / `环境与景别` / `出场实体` / `运镜与机位` / `画面光影与色彩` / `画面主体与构图` / `人物动作与视线` / `P段描述` 等）。  
  - **禁止**增删列、调换列序、把 Logic 字段拆成多列、把 Video 拆成多列。  
  - Beat 映射、ENV、出场实体、运镜、光影等推演核销进 `Shot Logic (CN)`（**仅极简标签**，§Logic-FMT）；画面进 `Video Content (CN)`（§八 五段）；实体进 `Associated Entities`。  
  - 自创表 = 管道解析失败；输出前若发现非上述 14 列英文表头 → **整表重写**。
- **单元格安全（强制，防解析裂列）**：
  - 长文本（`Shot Logic (CN)` / `Video Content (CN)`）内换行**只允许** `<br>` / `<br/>`，**禁止**真实换行把一行拆成多行。
  - 单元格正文若必须出现竖线字符，写为转义 `\|`；**禁止**裸 `|`（会被当成新列）。
  - **禁止**单元格内再嵌套 Markdown 表、代码块、标题 `#`。
  - 整表只含**一张**表；禁止输出第二张表或表后附录。
- 只在 `Video Content (CN)`（第 11 列）写完整中文视频提示词；`Video Content`（第 6 列）必须留空。
- **`Video Content (CN)` 不得留空（最高）**：每行第 11 列必须以「全局动态风格」起笔并含 §八 五段 + 品质收束；**禁止**只写 `Shot Logic (CN)` 而省略 Video；缺 Video = 整表失败须重写。
- **`Duration (s)`（第 7 列）必填正整数**；不得因空列骨架写错而把秒数填进相邻列。
- **`Shot ID` / `Scene ID` 必填且规范（§二.8）**：每行须写完整 `{Scene ID}_SHzz` 与对应上游 `Scene ID`（含字母后缀须原样，如 `EP01_SC01B` / `EP01_SC01B_SH01`）；**禁止**缩写如 `S02_SH01` / `SC02_SH01` / `SH01`；禁止留空、`(自动生成)`、纯数字序号、缺 `EP`/`SC` 层或剥除字母后缀；表格行序=分集→场景→分镜叙事序。
- **输出前列数自检（强制）**：表头 = 上列 14 个英文名逐字；每行单元格=14；第 1 格=`EPxx_SCyy_SHzz`；第 3 格=`EPxx_SCyy`；第 7 格=Duration 正整数；第 11 格以「全局动态风格」起笔、以 **§八.6 品质收束原文** 收束；第 14 格=实体列表；不符则重写。
