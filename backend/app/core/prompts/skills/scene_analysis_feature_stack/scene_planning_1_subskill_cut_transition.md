## 目标（最高）
本文件只做六件事：
1. 按时、空、叙事线、场内目标切分 Scene，并允许把原剧本的一场细分为多场。
2. 把不属于任何单独 Scene 的整体简介、人物简介、世界观等包入综合信息块。
3. 对每个 Scene 宽松评估 VFX/XIAN，写机器可提取路由标签与原文证据。
4. 先通读全集，再对每个 Scene 输出场级评估结论与下游放大目标；不改写正文、不拆 Beat。
5. 根据综合信息与全部 Scene 生成一次全项目 `project_visual_backfill`。
6. 识别每个 Scene 的主环境（可多个），对照 `[项目主环境名开始]…[项目主环境名结束]` 与本集之前已有环境，用机器可提取标签写出环境名与复用状态。

本文件不做 Beat 拆分，不落地卖点/高潮低点/情绪弧/三闸/构图，不做文戏/动作/特效优化，不把转场画面写入正文，不写【主环境】四向骨架或衍生白名单。

## 最高硬约束
1. **Scene 内容逐字透传 + 禁虚化（最高）**：每个 Scene 的正文必须是输入原文连续片段；不总结、不润色、不扩写、不重排、不删除、不改标点、不把叙述改成画面。**禁止**用「同原文／按原文／见原文／原文如此／照原文／如上／略／大意／照旧／不赘述」代替正文。
2. **不处理 Beat**：不新增 `[BEAT_START]` / `[BEAT_END]`，不生成 `- Beat` / `~ Beat`；不按对白、动作、特写、Reveal、快慢节奏拆拍。输入已有 Beat 标记逐字保留，不改编号、不合并、不拆分、不重排。
3. **只评估、只给放大目标**：必须输出本文件规定的全部场级标签。`指导=` 只写对象、细节、反馈、运镜目的与保护项；禁止镜头执行表、焦距、机位、分镜处方。禁止用新增/拆分 Beat 或改写正文来兑现结论。
4. **不改剧情**：不改事实、因果、胜负、伤亡、人物关系、对白、专名；禁止臆造台词、动作、转场、闪回画面或服化道。
5. **允许新增的内容仅限结构、场级结论标签、环境识别标签与项目视觉回填**：SCENES/SCENE 包裹、综合信息包裹、场景名称、场级评估、`SCENE_ENV_IDENT`、特殊情景路由包裹及单一 `project_visual_backfill` JSON。标签与 JSON 不得混入原文正文。
6. **零丢失、零重复**：输入每个信息单元须且仅须出现一次；全部 Scene 正文与综合信息块按原输入顺序拼接后，能够还原输入内容。
7. **一集内禁止可复用 Scene（最高）**：同一连续时空、同一主环境包络、同一场内目标，不得拆成两个 Scene 再互标复用；能合并必须合并。复用只评估项目库主环境与本集之前各集。出去再回来按 §1 闪切/闪回口径，禁止拆成回切场再标 `来源=本集`。

## 1. Scene 切分
先判断**时 / 空 / 叙事线 / 场内目标**是否连续。任一明确断开即可新起 Scene：
- 时间发生明确跳转，且不是同一连续动作中的短暂感受。
- 真正异地、进入不共享外形的独立功能空间，或叙事确认已离开当前地点。
- 主叙事线切换到另一组人物/另一地点并形成独立段落。
- 场内目标、冲突对象或行动阶段发生明确切换，后段可独立成立。
- 较长且完整的回忆段、梦境段、想象段，可独立成 Scene。
- 整体环境因崩塌、火灾、水淹、域场等实质改写，且后段持续停留在改写后状态。

### 出去再回来（闪切 / 闪回口径；最高）
本集角色短暂离开主空间再回来，不拆成「主场 / 出去场 / 回切场」三场再互标复用。
- **较短出去**（一眼、几句、短巷、门外一瞥、对位短切、马上回切）：必须并入当前大场。本场写多个主环境（当下主线 + 出去落点），【闪回分档】=`同场闪切` 或 `同场短闪回`。
- **较长且完整、可独立成立的出去段**（已换叙事目标、可单独成场）：可拆为独立 Scene，【闪回分档】=`独立闪回Scene`；回切当下仍并回原大场。禁止把三明治结构拆开后再标 `来源=本集`。
- 出去落点只是同空间走位、门口、窗边：不是新主环境，也不是新 Scene。

### 原场细分
- 原剧本已标为同一场，仍可依上述边界细分为多个 Scene；禁止因“原文写在一场”而硬并。
- 换观察侧、反打、特写、景别变化、气氛微调、同空间走位、对白换说话人，本身不是拆 Scene 依据。
- 后段仍在同一主环境包络且时间/叙事线未断开，必须留在同一 Scene；禁止为“方便复用环境”另起场。
- 只插 Scene 边界，不改边界两侧原文；禁止为让新场“更完整”补开场、补收尾或搬移句子。

### 场景名称（每场强制一行）
紧接 `[SCENE_START:{scene_id}]` 后必须写且只写一行：
`【场景名称】{原文场名或简短内容名}·{日夜/未知}·{内外/未知}·{季节/未知}·{气候/未知}·{正常叙事/闪回/倒叙/梦境/想象}`
- 原文已有场名则逐字沿用；无场名时只写检索用短内容名。
- 只写字段值，字段间统一用 `·`；禁止 `短名=`、`日夜=`、`内外=`、`叙事线=`、`校验=`、`纯地名=`。
- 无原文依据的季节/气候可省略，不为凑格式补写；最低结构=`短名·日夜·内外`。
- 短名不是环境注册名；环境名只写入 `SCENE_ENV_IDENT`。命名是否通过、是否纯地名写入【场景综合】的 `命名校验` 与 `纯地名`，不写进本行。

## 1b. 场级环境识别与复用（每个 Scene 强制）
只读本环节注入块 `[项目主环境名开始]…[项目主环境名结束]`（已删除环境不计入）。先读完全部已有主环境及其摘要/已有衍生，再逐场判定。若写明 `可复用/可参考主环境=无`，一律 `复用=否｜来源=新建｜匹配主环境=无`。本文件不读、不写 `[用户选定全局环境]` 或 `待复用主环境`。

### 识别
- 每个 Scene 至少 1 个主环境；同场快闪/蒙太奇/闪切出去再回来/出入封闭舱（仓外+仓内）/二层内部不共享外形时**可多个**。
- 环境名用稳定空间注册名，不写日夜后缀，不写 `{N}度…` 衍生名。
- 日夜/天气/气氛不同不另起名；换观察侧、反打、特写不是新环境。

### 复用判定（只对项目库与本集之前）
- `来源=项目库`：与注入清单同空间，名称须**逐字**等于清单已有名。
- `来源=上集`：与本集之前某集已锁定主环境同空间，名称逐字沿用。
- `来源=新建`：清单与上集都没有可复用的同空间。同场闪切/短闪回的出去落点若为新空间，标新建并写在**同一场**第二行 `[ENV]`，不另起 Scene。
- `来源=本集`：禁止用于出去再回来的回切场。仅当回切与原场之间已插入其他独立长场、无法并回原场时允许，依据必须写明无法合并的原因。
- `复用=是` 仅用于 `项目库|上集`；上一款唯一例外才可写 `本集`。`新建` 必须 `复用=否`。
- 禁止把本集相邻、未离开的同一空间，或三明治「出去再回来」，拆成两场再标复用。

### 包裹格式（最高；环境规划只读此块）
必须位于【场景名称】之后、【场景综合】之前，ID 与本场 `scene_id` 逐字一致：

```text
[SCENE_ENV_IDENT_START:EPxx_SCyy]
[ENV] 名称={主环境名}｜复用=是|否｜来源=项目库|上集|本集|新建｜匹配主环境={已有主环境名}|无｜依据=原文：“…”
[SCENE_ENV_IDENT_END:EPxx_SCyy]
```

- 每场恰好一对包裹；有几个主环境就写几行 `[ENV]`。
- `复用=是` 时 `匹配主环境` 必须等于注入清单或本集前文已声明名，禁止近义改写。
- `复用=否` 时 `匹配主环境=无`。
- 本文件不写【主环境】四向、【衍生】或 `ENV_BLOCK`。

## 2. 综合信息块（有则强制）
输入若含不属于任何单独场景的整体剧本简介、人物简介、世界观/时代背景、全局关系说明、创作前言或其他场外资料，须与 Scene 并列输出：

```text
[COMPREHENSIVE_INFO_START]
[INFO_ITEM_START:PLOT:1]
{剧情综合信息原文}
[INFO_ITEM_END:PLOT:1]
[INFO_ITEM_START:ASSET:1]
{资产综合信息原文}
[INFO_ITEM_END:ASSET:1]
[COMPREHENSIVE_INFO_END]
```

- 位于 `[SCENES_BLOCK_START]` 后、首个特殊分析包裹前，与各 Scene 同级。
- `INFO_ITEM` 只分 `PLOT｜ASSET`；同类型 `{n}` 从 1 连续。
- **ASSET**：角色、道具、环境/场景资产、载具、服装、武器、法器、生物等资产资料及其外观/属性/关系说明。
- **PLOT**：其余全部场外综合信息，包括整体/分集简介、梗概、主题、世界观、时代背景、剧情关系、规则说明、创作前言。
- 同一段同时含剧情与资产时可拆成相邻 PLOT/ASSET 项，原文字句不得改写；无法安全拆句时整体归 PLOT。
- 只分类包裹，内容逐字保留；不总结、不补设定、不改写成 Scene/Beat。
- 一段同时含场外资料与场景正文时，仅分离明确的场外资料；场景正文进入对应 Scene，禁止重复。
- 无场外综合资料时不输出空块；全稿最多一对。

## 3. 场级评估结论（每个 Scene 强制；只判定，不落地）
必须先通读全集全部 Scene 与综合信息，并先确定 `project_visual_backfill.borrowed_films` 及可核验名场面，再逐场输出。禁止只看本场孤立判断。输入已有 Beat 可原样引用；输入无 Beat 不得臆造编号。

各分析项只在 `## 6` 模板中输出一次。禁止先写分析说明再在 Scene 内重复输出。

1. **【场景综合】**：判断本场在全集中的作用，不复述本场剧情。作用闭集可多选：`引入｜铺垫｜埋伏笔｜加压｜升级｜延宕｜解谜｜揭示｜误导｜转折｜回收｜高潮释放｜低潮蓄压｜余波｜过渡｜集末钩子`。同时写上文承接与下文交付。
2. **【卖点综合】**：判断观众为什么愿意看本场；卖点可以不是具体剧情事件。每场取最强 1–3 项，复合大场面可多选。类型必须取下列闭集（复合用 `|`），禁止空泛“精彩/刺激”，禁止另造大类：
   - **动作/战斗**：`近身打斗｜兵器交锋｜打斗美学·飘逸｜打斗美学·暴力｜连续攻防｜绝地反击｜以弱胜强｜强者压制｜追杀逃亡｜团队配合｜战术智斗｜决战快感`。
   - **特效/奇观**：`通用法攻｜仙攻奇观｜法相/金身｜御剑空战｜变身/化形｜技能首次展示｜大招释放｜能量对撞｜域场/法阵｜宏大特效｜环境毁灭｜灾难奇观｜宏观群体｜军阵压境｜世界观奇观｜科技奇观`。
   - **悬念/解谜**：`埋伏笔｜伏笔悬念｜谜面抛出｜线索发现｜解谜快感｜真相揭示｜身份揭晓｜秘密暴露｜误导反转｜反转冲击｜危机倒计时｜集末钩子`。
   - **情绪/人物**：`高潮快感｜低潮压抑｜情感拉扯｜暧昧张力｜关系决裂｜重逢释放｜牺牲虐点｜复仇快感｜成长蜕变｜人物魅力｜精彩对白｜喜剧反差｜恐怖压迫｜治愈温情｜仪式感`。
   - **审美/感官**：`美景｜美物｜美人｜美食｜服化道审美｜环境氛围｜声音冲击｜蒙太奇技巧｜视觉反差｜类型爽点`。
   无独立卖点写 `无·过场承接`。
   `指导=` 强制字段：`重点对象`｜`细节特写参考`｜`反馈特写参考`｜`运镜参考`｜`贯穿保护`｜`名场面参考`。
   - 禁止 `交下游实现｜后续加强｜加强特写｜优化运镜`。
   - `重点对象`：最需被看清的具名道具/信息载体/人物状态/环境锚；若看点即【叙事综合】`关键人物`，须同名列入。
   - `细节特写参考`：放大对象的哪一处细节，以及该细节让观众获得什么信息或感受。
   - `反馈特写参考`：由谁对该看点产生何种可见反馈；悬念/解谜/高潮/低潮均须指出反馈承载者。
   - `运镜参考`：有动机方向 + 叙事目的（推近=聚焦/压迫，拉开=释放/孤立，跟随=发现，揭示=遮挡后显露，停留=余波）。不写焦距、机位、镜头表，不改 Beat。
   - `贯穿保护`：下游不得删、不得提前揭露、不得中断的贯穿信息 ID。
3. **【情绪峰谷综合】**：全集情绪作用取 `抬升｜加压｜爆发｜释放｜沉降｜低潮｜压抑蓄力｜余波｜反差过渡`；再判主/次高潮、主/次低点与入场→离场。结论以原文短引定位，不新增情绪事件。
   `指导=`：`入场锚`（上场须延续的人物/环境可见状态）｜`峰值放大`（具名承载者+可见反应+释放目的；无高潮=`无`）｜`低点放大`（具名承载者+压低方式+余波对象；无低点=`无`）｜`转折/离场`（原文节点+离场状态）｜`弧线保护`（不得提前爆发/释压、不得删改或重复兑现的节点）｜`名场面参考`。
4. **【叙事综合】**：
   - 叙事功能：`铺信息｜藏信息｜给谜面｜给线索｜误导｜验证｜解谜｜揭示｜回收｜转折｜推进目标｜制造阻力｜承上启下`。
   - 三闸：主题压力、两难、契科夫、后果、回指主题；原文没有写 `无`，禁止补造。
   - 贯穿信息：具名道具、信件/口令/证据/谜面/线索、身份秘密、人物承诺、关系变化、伤态/持物/能力状态、环境状态。格式=`信息ID/名称｜上文来源｜本场状态=引入/维持/变化/使用/转交/揭示/回收｜下文去向/待回收`。无则 `无`。
   `指导=`：
     - `关键人物`：仅改因果/改线/改知情/改胜负者入列，写 `具名｜情节改变点｜本场动作=出场/抉择/揭示/改因果｜须放大=是`。龙套、无决策权报信、纯气氛在场、本场仅陪衬不入。无则 `无`。入列者不得漏出指导。
     - `信息焦点`：本场最需读懂的具名信息/道具/关系/状态；若即关键人物，须同名对齐。
     - `显隐次序`：本场可展示 / 只暗示 / 必须继续隐藏 + 原文揭示节点。
     - `两难/选择`：双方 + 可见选择行为 + 必须保留的代价；无则 `无`。
     - `契科夫`：具名对象 + 展示/回收 + 当前状态；不得补造或提前回收。
     - `后果/回指`：由谁/何物反馈 + 原文已有主题回指；无则 `无`。
     - `贯穿保护`：不得删、不得改状态、不得提前揭露、不得断链的信息 ID；关键人物及其本场改因果动作须列入。
     - `名场面参考`。
5. **【构图综合】**：主意图 `三分｜中心｜纵深`；兼意图 `对称｜框中框｜引导线｜负空间｜无`。只写意图与原文依据，不写机位、焦距、运镜、主体落点。
6. **【场景切换与首节拍转场】**：只交判断：OT、轴锚、首个内容单元、前后场因果、出场/进场、状态差、原场细分、受损切口。不把转场画面写入正文。
7. **【服化道核销摘要】**：从本场原文初始态提取环境、服饰/换装、道具、全局道具；没有写 `无`，禁止补造。
8. **【闪回分档】**：`无｜同场短闪回｜同场闪切｜独立闪回Scene｜回忆长对话待下游可视化`。较短出去再回来用 `同场闪切` 或 `同场短闪回`；较长且完整的出去段才用 `独立闪回Scene`。本文件不把对白改写成闪回画面。
9. **【场号配对】**：START/END、连续编号、跳号/重复。
10. **【多线编排】**：`已交叉｜已有对位短切｜未做｜N/A`。本文件不重排、不新增多线画面。
11. **【Beat编号】**：输入已有 Beat 时只检查从 1 连续、跨场连编、跳号/重复，不得修改。输入无 Beat 写 `N/A｜原因=本环节不拆Beat`。

### 名场面参考（三类 `指导=` 同锁）
- 卖点 / 情绪 / 叙事的 `指导=` 均必须含 `名场面参考`；电影名必须 ∈ 最终 `project_visual_backfill.borrowed_films`。
- 格式：`名场面参考:{电影名·可辨识场面｜借鉴机制:{机制}｜本场映射:{原文对象/节点}}`。
- 可辨识场面须具体到可识别段落或事件；禁止只写“高潮场面”“经典镜头”或只写电影名。
- 只借鉴信息释放、情绪累积、表演反馈、节奏、声音、空间压迫或注意力组织机制；禁止复制原片剧情、台词、人物关系、标志性动作、构图复刻或专有设计。
- 无法确认该场面真实存在时，改选 `borrowed_films` 中能确认的场面，禁止臆造。

### 禁止写入
- 为填标签而新增、拆分、合并或重编号 Beat；仅可引用输入已有 Beat。
- 通道回填、四通道、双特写、空镜安排、强化步骤。
- `制作指导=改编/资产/分镜`、镜头调度、ENV/站位、动作加密、对白改写。
- 为满足标签而臆造卖点、高潮、低点、两难、契科夫或构图执行。

## 4. 特殊情景评估与路由（每个 Scene 强制）
**宽松判定、宁多勿缺、召回率优先**。场内原文有合理触发线索或后续可能需要专项处理，即标 `命中=是`；边界不清可 VFX/XIAN 双命中。确无任何相关线索才标否。

### 分类
- `VFX`：`近身打斗｜宏观群体｜通用法攻｜宏大特效｜追杀/穿梭`。
- `XIAN`：`仙攻｜法相/金身｜空域身法｜域场法阵｜化龙凤兽`。
- 仙侠/修真体系的灵气、真元、罡气、剑气、御剑、结印、法相、金身、域场法阵、化龙凤兽优先归 XIAN。
- 非仙体系拳脚、兵器近战、元素/能量/力场/科技投射、军阵人海优先归 VFX。

### 证据
- 禁止使用自造 Beat 编号作证据。
- 命中时至少引用一段本 Scene 原文短句：`证据=原文：“……”`；多类证据用 `；` 分隔。
- 动作、能力词、武器/法器、军阵人海、元素/能量、结印/御剑、腾空、变身、环境级异变，以及战斗将起、蓄势、对峙、追兵逼近等前置线索均可举证。
- 题材与人物身份只能辅助判断；本 Scene 零线索时不得单独造出命中。
- 难分 VFX/XIAN 时可双标，并在证据后写 `边界待专项复核`。
- 未命中：`证据=无：逐段扫描后无任何相关线索`。

### 包裹格式
必须位于对应 `[SCENE_START:{scene_id}]` **之前**，与 Scene 块相邻，**不包入 Scene**：

```text
[SPECIAL_SCENE_ANALYSIS_START:{scene_id}]
[VFX] 命中=是|否｜类型=近身打斗|宏观群体|通用法攻|宏大特效|追杀/穿梭|无｜证据=原文：“……”|无：…
[XIAN] 命中=是|否｜类型=仙攻|法相/金身|空域身法|域场法阵|化龙凤兽|无｜证据=原文：“……”|无：…
[SPECIAL_SCENE_ANALYSIS_END:{scene_id}]
```

- 两行均必填；每场恰好一对；包裹结束后必须立即开始对应 `[SCENE_START]`。
- 包裹 START/END ID 必须与紧随其后的 Scene ID 完全相同。
- 只写标签，不得把分析意见写入原文正文。

## 5. Project Visual Backfill（项目级；强制）
先通读综合信息块与全部 Scene，再生成一次项目级视觉摘要。全稿恰好一个，位于 `[SCENES_BLOCK_END]` 后；不得包进综合信息块或任一 Scene；下游不得重推断或改写。

- **信息范围**：以输入明文的题材、时代、地域、世界观、主线、冲突、情绪气质、环境与视觉元素为依据；综合信息与 Scene 正文冲突时，以 Scene 正文为准。
- **Global_Style**：全项目可持续复用的影像风格；不写单场镜头调度、机位或设备参数。
- **borrowed_films**：1–2 部真实对标电影；`borrowed_films_note` 写可借鉴风格维度；`borrowed_films_scene_refs` 登记指导实际引用的名场面及机制。
- **tone**：项目主情绪及必要变化方向，不逐 Scene 复述。
- **color_spectrum**：必填，取 `冷调主导｜暖调主导｜冷暖对比｜同温层次` 之一，并给出至少一条来自原文及对标电影的依据；禁止 K 值、四层色谱及 `color_palette`。
- **plot_summary**：`主线｜冲突｜结果/当前去向`；原文尚无结果写 `结果=待展开`，禁止补造结局。
- **music_recommendation**：项目级风格、情绪、参考方向与适用场景类型；禁止写入 Scene 原文或 Beat。

字段与 JSON 形状以 `## 6` 模板为准，此处不另给第二份 Schema。

## 7. 成稿自检
- 只做 Scene 边界、综合信息分类、场级结论、环境识别、特殊情景路由、项目视觉回填。
- 未拆/改 Beat，未写环境骨架，未把转场或名场面写进正文。
- `可复用/可参考主环境=无` 时全部 `复用=否｜来源=新建｜匹配主环境=无`。
- 一集内同一连续空间已合并；较短出去再回来已并入大场，未标 `来源=本集`。
- 每场：`SPECIAL_SCENE_ANALYSIS` 在 `SCENE_START` 前；【场景名称】恰好一行；`SCENE_ENV_IDENT` 可提取；【Beat编号】已输出。
- 三类 `指导=` 均含对象/反馈/保护与 `borrowed_films` 名场面参考；无“交下游实现”；关键人物仅改因果者入列。
- 卖点类型取闭集；构图无执行方案；运镜参考无焦距/机位/镜头表。
- Scene 正文逐字透传，未用虚化词代替；综合信息有则唯一一块。
- 每场 VFX/XIAN 两行齐全；证据来自本场原文短引。
- 结构标签 ID 闭合；原文零丢失、零重复。
- `[SCENES_BLOCK_END]` 后恰好一个 `project_visual_backfill`；`borrowed_films_scene_refs` 与三类指导引用一致。
