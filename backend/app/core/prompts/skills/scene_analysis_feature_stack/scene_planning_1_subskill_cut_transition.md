## 目标（最高）
本文件只做五件事：
1. 按时、空、叙事线、场内目标切分 Scene，并允许把原剧本的一场细分为多场。
2. 把不属于任何单独 Scene 的整体简介、人物简介、世界观等包入综合信息块。
3. 对每个 Scene 宽松评估 VFX/XIAN 特殊情景，写机器可提取路由标签与原文证据。
4. 先通读全集，再对每个 Scene 输出其全集功能、吸引人看点、情绪作用、叙事作用、跨场贯穿信息、构图、转场、服化道、闪回、多线、编号等**场级评估结论与下游放大目标**；不改写正文、不拆 Beat。
5. 根据综合信息与全部 Scene 生成一次全项目 `project_visual_backfill`，作为与场景块并列的项目级视觉摘要。

除此之外，输入内容全部逐字透传。本文件**不做 Beat 拆分，不做卖点/高潮低点/情绪弧/三闸/构图的落地设计，不做文戏/动作/特效优化，不新增转场内容**。

## 最高硬约束
1. **Scene 内容逐字透传**：每个 Scene 的正文必须是输入原文连续片段；不总结、不润色、不扩写、不重排、不删除、不改标点、不把叙述改成画面。
2. **不处理 Beat**：
   - 不新增 `[BEAT_START]` / `[BEAT_END]`，不生成 `- Beat` / `~ Beat`。
   - 不按对白、动作、特写、Reveal、快慢节奏拆 Beat。
   - 输入已有 Beat 标记时逐字保留，不改编号、不合并、不拆分、不重排。
3. **只评估、只给放大目标**：必须输出本文件规定的全部场级分析标签，但禁止通过新增/拆分 Beat 来实现结论，禁止改写 Scene 正文或新增剧情。本文件可指出下游必须放大的对象、反馈和运镜目的，但不写具体镜头执行表。
4. **不改剧情**：不改事实、因果、胜负、伤亡、人物关系、对白、专名；禁止臆造台词、动作、转场、闪回画面或服化道。
5. **允许新增的内容仅限结构、场级结论标签与项目视觉回填**：SCENES/SCENE 包裹、综合信息包裹、场景名称、五项场级评估、特殊情景路由包裹及单一 `project_visual_backfill` JSON。标签与 JSON 均不得混入原文正文。
6. **零丢失、零重复**：输入每个信息单元须且仅须出现一次；全部 Scene 正文与综合信息块按原输入顺序拼接后，能够还原输入内容。

## 1. Scene 切分
先判断**时 / 空 / 叙事线 / 场内目标**是否连续。任一明确断开即可新起 Scene：
- 时间发生明确跳转，且不是同一连续动作中的短暂感受。
- 真正异地、进入不共享外形的独立功能空间，或叙事确认已离开当前地点。
- 主叙事线切换到另一组人物/另一地点并形成独立段落。
- 场内目标、冲突对象或行动阶段发生明确切换，后段可独立成立。
- 较长且完整的回忆段、梦境段、想象段，可独立成 Scene。
- 整体环境因崩塌、火灾、水淹、域场等实质改写，且后段持续停留在改写后状态。

### 原场细分
- 原剧本已标为同一场，仍可依上述边界细分为多个 Scene；禁止因“原文写在一场”而硬并。
- 换观察侧、反打、特写、景别变化、气氛微调、同空间走位、对白换说话人，本身不是拆 Scene 依据。
- **只插 Scene 边界，不改边界两侧原文**；禁止为让新场“更完整”补开场、补收尾或搬移句子。

### 场景名称
每个 `[SCENE_START:{scene_id}]` 后可增加一行：
`【场景名称】{原文场名或简短内容名}｜{日·夜/未知}·{内/外/未知}｜{正常叙事/闪回/倒叙/梦境/想象}`
- 原文已有场名则逐字沿用。
- 原文无场名时只写用于检索的简短内容名，不做卖点、情绪或构图判断。

## 2. 综合信息块（有则强制）
输入若含不属于任何单独场景的整体剧本简介、人物简介、世界观/时代背景、全局关系说明、创作前言或其他场外资料，须与 Scene 并列输出：

```text
[COMPREHENSIVE_INFO_START]
[INFO_ITEM_START:PLOT:1]
{剧情综合信息原文}
[INFO_ITEM_END:PLOT:1]
[INFO_ITEM_START:ASSET:1]
{资产综合信息原文}
[INFO_ITEM_END:ASSET:1]
[COMPREHENSIVE_INFO_END]
```

- 综合信息块位于 `[SCENES_BLOCK_START]` 后、首个 Scene 前，与各 Scene 同级，不属于任何 Scene。
- `INFO_ITEM` 类型只分两类：`PLOT｜ASSET`；同类型 `{n}` 从 1 连续。
- **ASSET**：仅收角色、道具、环境/场景资产、载具、服装、武器、法器、生物等资产资料及其外观/属性/关系说明。
- **PLOT**：除资产资料外的全部场外综合信息均归剧情，包括整体/分集简介、梗概、主题、世界观、时代背景、剧情关系、规则说明、创作前言等。
- 同一段同时含剧情与资产时可拆成相邻的 PLOT/ASSET 项，但原文字句不得改写；无法安全拆句时整体归 PLOT，禁止为分类破坏原文。
- 只分类包裹，内容逐字保留；不总结、不补设定、不改写成 Scene/Beat。
- 一段同时含场外资料与实际场景正文时，仅分离明确的场外资料；场景正文进入对应 Scene，禁止重复。
- 输入无场外综合资料时不输出空块；全稿最多一对综合信息块。

## 3. 场级评估结论（每个 Scene 强制；只判定，不落地）
必须先通读**全集全部 Scene 与综合信息**，建立“上文输入→本场作用→下文交付”的全集视角，并先确定 `project_visual_backfill.borrowed_films` 及其中可核验的经典名场面，再逐场输出结论、指导与原文依据。禁止只看本场孤立判断。**本文件不创建 Beat**；输入已有 Beat 时可原样引用，输入无 Beat 时不得臆造编号。

1. **【场景综合】**：核心是判断**本场在全集中起什么作用**，而非复述本场具体剧情。作用闭集可多选：`引入｜铺垫｜埋伏笔｜加压｜升级｜延宕｜解谜｜揭示｜误导｜转折｜回收｜高潮释放｜低潮蓄压｜余波｜过渡｜集末钩子`。同时写上文承接与下文交付。
2. **【卖点综合】**：这是卖点与放大指导的**唯一输出行**，同时承载场号、看点、类型、吸引力、已有 Beat 引用、具体参考意见与贯穿保护；不再另写【核心卖点】或【下游放大指导】。判断观众为什么愿意看本场，卖点可以不是具体剧情事件。每场优先选最强 1–3 项；复合大场面可多选，禁止只写空泛的“精彩/刺激”。参考类型（开放枚举，可据原文写同级具体词）：
   - **动作/战斗**：`近身打斗｜兵器交锋｜打斗美学·飘逸｜打斗美学·暴力｜连续攻防｜绝地反击｜以弱胜强｜强者压制｜追杀逃亡｜团队配合｜战术智斗｜决战快感`。
   - **特效/奇观**：`通用法攻｜仙攻奇观｜法相/金身｜御剑空战｜变身/化形｜技能首次展示｜大招释放｜能量对撞｜域场/法阵｜宏大特效｜环境毁灭｜灾难奇观｜宏观群体｜军阵压境｜世界观奇观｜科技奇观`。
   - **悬念/解谜**：`埋伏笔｜伏笔悬念｜谜面抛出｜线索发现｜解谜快感｜真相揭示｜身份揭晓｜秘密暴露｜误导反转｜反转冲击｜危机倒计时｜集末钩子`。
   - **情绪/人物**：`高潮快感｜低潮压抑｜情感拉扯｜暧昧张力｜关系决裂｜重逢释放｜牺牲虐点｜复仇快感｜成长蜕变｜人物魅力｜精彩对白｜喜剧反差｜恐怖压迫｜治愈温情｜仪式感`。
   - **审美/感官**：`美景｜美物｜美人｜美食｜服化道审美｜环境氛围｜声音冲击｜蒙太奇技巧｜视觉反差｜类型爽点`。
   无独立卖点才写 `无·过场承接`。
3. **【情绪峰谷综合】**：从全集情绪曲线判断本场承担 `抬升｜加压｜爆发｜释放｜沉降｜低潮｜压抑蓄力｜余波｜反差过渡` 中何种作用，再判断主/次高潮、主/次低点与入场→离场情绪变化。结论以原文短引定位，不新增情绪事件。必须增加具体 `指导=`：
   - `入场锚`：指出应延续上场哪种人物/环境可见状态，避免情绪无因重置。
   - `峰值放大`：主/次高潮各指出具名承载者、应被读清的可见反应及释放目的；无高潮写 `无`。
   - `低点放大`：主/次低点各指出具名承载者、压低方式和余波对象；无低点写 `无`。
   - `转折/离场`：指出情绪在哪一原文节点发生方向变化，以及离场须保留给下场的状态。
   - `弧线保护`：明确不得提前爆发、不得提前释压、不得删去或重复兑现的情绪节点。
   - `名场面参考`：从 `borrowed_films` 中选择最贴合本场情绪机制的真实经典场面，写明 `电影名+可辨识场面+借鉴机制`，例如借鉴“压抑累积后突然释放”“人物静止而环境持续施压”等机制；禁止只写电影名。
4. **【叙事综合】**：
   - 判断本场承担的叙事功能：`铺信息｜藏信息｜给谜面｜给线索｜误导｜验证｜解谜｜揭示｜回收｜转折｜推进目标｜制造阻力｜承上启下`。
   - 保留三闸判断：主题压力、两难选择、契科夫信息、后果、回指主题；原文没有则写 `无`，禁止补造。
   - 识别必须跨上下文贯穿的信息：具名道具、信件/口令/证据/谜面/线索、身份秘密、人物承诺、关系变化、伤态/持物/能力状态、环境状态等。
   - 每项写清 `信息ID/名称｜上文来源｜本场状态=引入/维持/变化/使用/转交/揭示/回收｜下文去向/待回收`。原文没有则写 `无`，禁止补造三闸或贯穿物。
   - 必须增加具体 `指导=`：
     - `关键人物`（强制纳入下游放大）：列出**对情节改变有重大影响**的具名角色——本场因其出场、抉择、揭示、交付/夺走关键物、改写因果或改变后续路径，观众必须看清其人。写 `具名｜情节改变点｜本场动作=出场/抉择/揭示/改因果｜须放大=是`。判定：改因果/改线/改知情/改胜负关系者才入列；龙套、无决策权报信、纯气氛在场、本场仅陪衬者不入。无则写 `无`。入列者下游必须放大（出场升格、三轴应答、可见面可读），不得漏出指导。
     - `信息焦点`：指出本场最需要观众读懂的具名信息、道具、关系或状态；若焦点即关键人物，须与上项同名对齐。
     - `显隐次序`：明确哪些信息本场可展示、只可暗示、必须继续隐藏，以及原文揭示节点。
     - `两难/选择`：有两难时指出选择双方、做出选择的可见行为与必须保留的代价；无则写 `无`。
     - `契科夫`：指出应展示或回收的具名对象及其当前状态；不得补造枪或提前回收。
     - `后果/回指`：指出本场结果应由谁/何物反馈，并如何保持原文已有主题回指；无则写 `无`。
     - `贯穿保护`：列出不得删、不得改状态、不得提前揭露、不得断链的信息 ID；**关键人物及其本场改因果动作**须列入。
     - `名场面参考`：从 `borrowed_films` 中选择最贴合本场叙事机制的真实经典场面，写明 `电影名+可辨识场面+信息组织机制`，重点参考悬念显隐、道具铺垫、选择代价、揭示或后果回响；禁止照搬该片剧情答案。
5. **【构图综合】**：只判断本场构图意图 `三分｜中心｜纵深` 及可兼意图 `对称｜框中框｜引导线｜负空间｜无`；只写意图与原文依据，不写机位、焦距、运镜、主体落点或具体执行方案。
6. **【场景切换与首节拍转场】**：这是转场的**唯一输出行**，统一分析 OT 类型、轴锚、首个内容单元、前后场因果、出场/进场、状态差、原场细分与受损切口；不再另写【转场首节拍】。只交判断，不把转场画面写进正文。
7. **【服化道核销摘要】**：从本场原文初始态提取环境、服饰/换装、道具、全局道具；没有则写 `无`，禁止补造。
8. **【闪回分档】**：判断 `无｜同场短闪回｜独立闪回Scene｜回忆长对话待下游可视化`；本文件不把对白改写成闪回画面。
9. **【场号配对】**：检查 START/END、连续编号、跳号/重复。
10. **【场景名称】**：场景名与校验合并在**唯一一行**；检查短名是否为内容名、是否误用纯地名，原文无名时可给检索短名，禁止另写第二条“通过”说明。
11. **【多线编排】**：判断输入当前是 `已交叉｜已有对位短切｜未做｜N/A`；不在本文件重排或新增多线画面。
12. **【Beat编号】**：本文件不拆 Beat；输入已有 Beat 时只检查从 1 连续、跨场连编、跳号/重复，**不得修改**。输入无 Beat 时写 `N/A｜原因=本环节不拆Beat`。
13. **【卖点综合】中的 `指导=`（强制给具体参考意见）**：
   - 禁止写 `交下游实现｜后续加强｜加强特写｜优化运镜` 等空泛占位语。
   - `重点对象`：明确本场最需被看清的具名道具/信息载体/人物状态/环境锚；若看点即【叙事综合】`关键人物`，须同名列入，供下游放大。
   - `细节特写参考`：明确应放大对象的哪一处细节，以及该细节让观众获得什么信息或感受。
   - `反馈特写参考`：明确由谁对该看点产生何种可见反馈；悬念/解谜/高潮/低潮均须指出反馈承载者。
   - `运镜参考`：写具体可供下游选择的有动机方向，如 `沿信件文字缓慢推近以引导发现`、`由受击环境拉回人物反应形成因果反馈`；仍不划分或修改 Beat，不写焦距参数/镜头表。
   - `贯穿保护`：列出下游不得删、不得提前揭露、不得中断的贯穿信息 ID。
   - `名场面参考`：从 `borrowed_films` 中选择最贴合本场卖点的真实经典场面，写明 `电影名+可辨识场面+可借鉴的视听/表演机制`；不得只写“参考某电影风格”，不得照搬角色、事件、台词、动作招式或专有视觉设计。

### borrowed_films 名场面引用硬规则
- 三类 `指导=` 均必须包含 `名场面参考`，且电影名必须存在于最终 `project_visual_backfill.borrowed_films`。
- 引用格式统一为：`名场面参考:{电影名·可辨识场面｜借鉴机制:{机制}｜本场映射:{原文对象/节点}}`。
- “可辨识场面”须具体到观众可识别的段落或事件，如“餐桌审讯段”“走廊追逐段”“雨中告别段”，禁止只写“高潮场面”“经典镜头”。
- 只借鉴信息释放、情绪累积、表演反馈、节奏、声音、空间压迫或视觉注意力组织机制；禁止复制原片剧情、台词、人物关系、标志性动作、构图复刻或受版权保护的专有设计。
- 无法确认某场面真实存在时不得臆造；应改选 `borrowed_films` 中能够确认的经典场面。

### 唯一输出口径
各分析项只在下文 `## 6. 统一成稿模板（唯一 canonical）` 中输出一次。本节只解释判断口径，禁止在成稿中先输出一份“分析说明”、再在 Scene 内重复输出。

### 禁止写入
- 禁止为填写标签而新增、拆分、合并或重编号 Beat；仅可引用输入已有 Beat。
- 禁止通道回填、四通道、双特写、空镜安排、强化步骤。
- `制作指导=改编/资产/分镜`、镜头调度、ENV/站位、动作加密、对白改写。
- 为满足标签而臆造卖点、高潮、低点、两难、契科夫或构图执行。

这些标签是下游实现依据；下游可以细化实现，但不得无据改判已锁结论。

## 4. 特殊情景评估与路由（每个 Scene 强制）
评估原则：**宽松判定、宁多勿缺、召回率优先**。只要场内原文存在合理触发线索或后续可能需要专项处理，即标 `命中=是`；边界不清也可 VFX/XIAN 双命中。确无任何相关线索才标否。

### 分类
- `VFX`：`近身打斗｜宏观群体｜通用法攻｜宏大特效｜追杀/穿梭`。
- `XIAN`：`仙攻｜法相/金身｜空域身法｜域场法阵｜化龙凤兽`。
- 仙侠/修真体系的灵气、真元、罡气、剑气、御剑、结印、法相、金身、域场法阵、化龙凤兽优先归 XIAN。
- 非仙体系拳脚、兵器近战、元素/能量/力场/科技投射、军阵人海优先归 VFX。

### 证据
- 本文件不生成 Beat，因此**禁止使用自造 Beat 编号作证据**。
- 命中时至少引用一段本 Scene 原文短句：`证据=原文：“……”`；多类证据用 `；` 分隔。
- 动作、能力词、武器/法器、军阵人海、元素/能量、结印/御剑、腾空、变身、环境级异变，以及战斗将起、蓄势、对峙、追兵逼近等前置线索均可举证。
- 题材与人物身份只能辅助判断；本 Scene 零线索时不得单独造出命中。
- 难分 VFX/XIAN 时可双标，并在证据后写 `边界待专项复核`。
- 未命中：`证据=无：逐段扫描后无任何相关线索`。

### 包裹格式
专用包裹必须位于其对应 `[SCENE_START:{scene_id}]` 之前，与 Scene 块相邻但不包入 Scene：

```text
[SPECIAL_SCENE_ANALYSIS_START:{scene_id}]
[VFX] 命中=是|否｜类型=近身打斗|宏观群体|通用法攻|宏大特效|追杀/穿梭|无｜证据=原文：“……”|无：…
[XIAN] 命中=是|否｜类型=仙攻|法相/金身|空域身法|域场法阵|化龙凤兽|无｜证据=原文：“……”|无：…
[SPECIAL_SCENE_ANALYSIS_END:{scene_id}]
```

- 两行均必填；每场恰好一对包裹，包裹结束后必须立即开始对应 Scene。
- 包裹 START/END ID 必须与紧随其后的 Scene ID 完全相同。
- 路由分析只写标签，不得把分析意见写入原文正文。

## 5. 第三部分：Project Visual Backfill（项目级；强制）
先通读综合信息块与全部 Scene，再生成一次项目级视觉摘要。该 JSON 由本文件负责生成，是唯一输出源；不得要求文戏标准化或其他下游技能重新推断、补写或改写。

### 生成规则
- **信息范围**：以输入明文的题材、时代、地域、世界观、主线、冲突、情绪气质、环境与视觉元素为依据；综合信息与 Scene 正文发生冲突时，以实际 Scene 正文为准。
- **Global_Style**：概括全项目可持续复用的影像风格，不写单场镜头调度、机位或设备参数。
- **borrowed_films**：选择 1–2 部与题材、情绪和视觉语言可对标的真实电影；`borrowed_films_note` 说明可借鉴的风格维度；`borrowed_films_scene_refs` 登记指导实际引用的经典名场面及机制，不照搬剧情、角色或专有设计。
- **tone**：概括项目主情绪及必要的变化方向，不逐 Scene 复述。
- **color_spectrum**：必填，取 `冷调主导｜暖调主导｜冷暖对比｜同温层次` 之一，并给出至少一条来自原文及对标电影的依据；禁止 K 值、四层色谱及 `color_palette`。
- **plot_summary**：只写 `主线｜冲突｜结果/当前去向`；原文尚无结果时写 `结果=待展开`，禁止补造结局。
- **music_recommendation**：只给项目级风格、情绪、参考方向与适用场景类型；禁止把配乐写入 Scene 原文或 Beat。
- 全稿恰好一个 `project_visual_backfill`；必须位于 `[SCENES_BLOCK_END]` 后；不得包进综合信息块或任一 Scene。

### 固定 Schema
```json
{
  "project_visual_backfill": {
    "Global_Style": "...",
    "borrowed_films": ["电影名A", "电影名B"],
    "borrowed_films_note": "...",
    "borrowed_films_scene_refs": ["电影名A｜可辨识名场面｜可借鉴机制", "电影名B｜可辨识名场面｜可借鉴机制"],
    "tone": "...",
    "color_spectrum": "冷暖对比｜依据：原文…；对标电影A的…",
    "plot_summary": "主线=…｜冲突=…｜结果=…",
    "music_recommendation": "风格=…｜情绪=…｜参考=…｜场景=…"
  }
}
```

## 7. 成稿自检
- 只做 Scene 边界、综合信息分类、场级结论评估、特殊情景路由和项目视觉回填；未做 Beat 拆分。
- 已先通读全集；每场已明确全集作用、吸引人看点、情绪曲线作用、叙事功能及“上文输入→本场状态→下文去向”的贯穿信息。
- 每场已输出卖点、高潮低点、情绪弧、三闸、构图等结论与原文依据；【卖点综合】【情绪峰谷综合】【叙事综合】均已给出具体 `指导=`，包含可执行的承载对象、放大/显隐/反馈目标、保护项及 `borrowed_films` 经典名场面参考；【叙事综合】已判定并对下游标出**对情节改变有重大影响的关键人物**（须放大），未把龙套/陪衬误列入，未使用“交下游实现”等占位语，也未拆分/修改 Beat。
- 每场各标签只输出一次：卖点与指导统一用【卖点综合】，转场只用【场景切换与首节拍转场】，场景名只用一条【场景名称】；未再输出【核心卖点】【下游放大指导】或【转场首节拍】。
- 每场已输出服化道、闪回、场号、多线与 Beat编号检查；输入无 Beat 时相关字段明确写 N/A，未为填表造 Beat。
- 每个 Scene 正文逐字透传，未改写、重排、增删或改标点。
- 输入已有 Beat 标记原样保留；未新增、删除、合并、拆分或重编号。
- 场外综合资料有则进入唯一综合信息块，与 Scene 同级。
- 每场 VFX/XIAN 两行齐全；宽松判定，疑似可双标；证据来自本场原文短引，不使用自造 Beat 编号。
- 全部结构标签 ID 闭合一致；原文信息零丢失、零重复。
- `[SCENES_BLOCK_END]` 后已输出且仅输出一个符合固定 Schema 的 `project_visual_backfill`；字段依据来自综合信息与全部 Scene，`borrowed_films_scene_refs` 与三类指导引用一致，未补造剧情或名场面，未写入 Scene 正文。
