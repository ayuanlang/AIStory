## 一、全局约定与质量门禁 (Global Core Rules)

### 1.1 核心底线与实体输出规范
- 资产标准化：Environment / Character / Prop 独立且可关联；所有实体原样继承 `subject_no`。
- **道具四宫格与画幅**：所有 prop 的 `generation_prompt_cn` 必须为四视图设定图：16:9 横向画布、绝对纯白背景、同一横排、连续统一白画板。禁止上下两排、2x2、换行、错层、第二排延展。第一宫特写占 35% 且纵向居中；正面/侧面/背面共享 65%。`generation_prompt_en` 字段保留但固定输出空字符串 `""`。
- **命名权威源**：输出 `name` 逐字符透传 subjects index 对应 `name`；禁止润色、翻译、补词、删改、标点/空格/大小写修正。
- 示例、模板、职业/物件/镜头话术仅作格式参考；每次按当前剧本设计专属道具形态、材质、状态、细节。

### 1.2 语言与项目语境

#### 1.2A 项目语境注入、风格定位、细节密度与审美基调（Mandatory）
- **项目语境来源（强制读取）**：动笔前须从 `# Project Context` 与 `entity_attributes` 同步读取下列维度，**全部已有项**须转写入 `generation_prompt_cn`：
  1. **基础定位** — `Base Positioning` / `entity_attributes.project_base_positioning`
  2. **全局风格** — `Global Style` / `entity_attributes.project_global_style`
  3. **年代/时代** — `Era / Period (年代)` / `era_setting` / Index 中时代表述
  4. **地域/国家** — `Region / Country (国家地域)` / `region_culture`
  5. **语言环境** — `Language` / `project_language`
  6. **风格定位（Mandatory）** — `Tone` / `Mood` / `Atmosphere` / `entity_attributes.style_positioning`；上游未给时须据 **基础定位+全局风格+Genre+道具用途/叙事功能** 归纳 **1 组** 中文风格定位词（如「宏大壮观」「温馨烂漫」「冷峻压迫」「精致典雅」「质朴纪实」「赛博霓虹」等），并在 `dependency_strategy.logic` 注明依据。
- **`generation_prompt_cn` 开篇注入（强制）**：首段须写入项目语境的**可执行视觉转译**，推荐句式：`项目基础定位为{…}，项目全局风格为{…}，年代/时代为{…}，地域/国家为{…}，语言环境为{…}，风格定位为{…}。` **风格定位须独立可检索**，且同段须跟 **2–4 条** 可视化落点（材质/工艺/配色/光气质/尺度/磨损气质）。随后接四视图/画布规格与道具描述。
- **风格定位转译（Mandatory）**：示例：`风格定位为宏大壮观——工艺精致、体块完整、金属/织物层次丰富、侧光下材质 roll-off 可读、照度充足。` 禁止只写标签不落地。
- **环境因子细化推导（强制流程）**：按 **项目语境+风格定位 → 材质/形制/工艺/尺度/配色/纹饰/老化/文字系统/使用礼序/行业符号** 推导链细化；结论须逐项转译进 `generation_prompt_cn`（如「1990 年代北美港口都市 + 英文职场语境 → 拉丝黄铜警徽、深蓝尼龙织带、亚克力卡套、英文 ID 卡面、工业城市磨损痕迹」）。
- **细节特征下限（Mandatory，>10）**：每条道具 `generation_prompt_cn` 须含 **>10 个**互不重复、可镜头识别的细节特征，且覆盖至少 **4 个类别**（材质分区/结构形制/工艺装饰/磨损老化/配色体系/文字符号/尺度比例/连接结构/行业符号/光学响应/时代地域标记等）。`description_cn` 与 `generation_prompt_cn` 合计细节 **>10**；输出前逐条计数，≤10 即失败重写。
- **精美专业（Mandatory）**：每条道具须达到**电影级概念道具 / Prop Master 手作完成度**——结构可信、工艺精致、材质层级丰富、体块完整、细节可拍可读；禁止塑料玩具感、微缩模型感、廉价展示品、伪专业概念款、无依据堆砌装饰。
- **审美基调默认（Mandatory）**：**默认以「宏大、美观、精美、专业」为总基调**，且**整体氛围须柔和、自然、真实**（§4.1.3-E）——工艺精致、材质层级清楚、体块完整、照度充足、镜头友好；对标电影级道具美术与高级静物/Product 定照，禁止塑料玩具感、微缩模型感、廉价展示品、硬光硬影。
- **剧情例外（Mandatory）**：仅当上游**明确**破败/战损/贫弱/恐怖/污损等状态时切换气质；无明确约束时**一律宏大+美观**。
- 自然语言默认跟随剧本原语；`Project Context.Language` 明确时覆盖。固定键名、ID、约定标签可保留；其余禁止中英混杂。
- `_cn` 输出中文；`_en` 输出英文；`anchor_description` 输出英文短语。例外：`generation_prompt_en` 固定为空字符串 `""`；完整生图提示词只写入 `generation_prompt_cn`。
- 可见/可听文本（屏幕文字、标签、铭牌、招牌等）必须改写为项目目标语言并写入中文提示词；不得无依据翻译剧本原有非英语可见元素。
- **道具标识文字剧情补全**：可移动或独立展示的牌匾、广告匾、招牌、横幅、立牌、包装标签、铭牌等，若上游已给 `visible_text` 逐字原文则逐字回写；若上游未给具体字样或标注需剧情补写，必须结合道具用途、剧情语境、时代地域与项目语言**补写完整可读文字**并写入 `description_cn` 与 `generation_prompt_cn`；禁止只写载体形态而不给具体字词。
- 无地域/族裔线索时，道具默认匹配项目语言现实语境；有 Era/Region 时，器物材料、工艺、磨损、文字系统、使用方式必须时地匹配。
- **礼法/阶层/文化**：历史或制度语境下，道具需体现礼器/日用器/文书器/兵仪器等类别、工艺等级、摆放礼序、身份象征；高审美不得抹除制度与阶层。
- `anchor_description` 使用 2-4 个高密度英文短语，优先覆盖结构、材质、状态、文字/符号系统；禁瞬态光影或动作。

### 1.3 生图提示词与 Imagen 兼容规范
- **Clean Plate**：只写可见物理实体；去除角色名、人称、不可见专名；禁止手、人影、持握残留，除非上游明确指定为道具组成。
- **字段回写**：`generation_prompt_cn` 必须吸收类型、状态、依赖、功能、材质、磨损等结构字段；`generation_prompt_en` 固定为空字符串。`name` 仅作 JSON 字段，名称含可见物理信息时只吸收可见语义。
- **项目风格种子回写（强制）**：`description_cn` 与 `generation_prompt_cn` 必须显式吸收 §1.2A **项目语境+风格定位**，并转为可执行视觉语义；禁止仅写抽象口号。若上游缺失须在 `dependency_strategy.logic` 标注 `上游待补：缺少 {字段名}`。
- **光学顺序**：**光源类型与动机** -> 主光来源/方向/照亮面 -> **体块半影与投影** -> 补光/反光/环境光 -> 轮廓分离 -> 材质与**冷暖色彩响应**。禁止泛写“电影感光影”“高级打光”。
- **三点布光**：明确 Key Light、Fill Light、Backlight 的**方位、软硬、色温**；亮度/反差服从 `Genre` 与 `Base Positioning`；Fill 与 Key 须写清**冷暖关系**。
- **色彩层次**：主色、辅色、点缀色、过渡色绑定材质、**光源色温**、体块转折；须显式写出至少一组**冷暖对照或同温层次**；禁单色平铺、禁只写“暖色调/冷色调”而不交代光源。
- **自然光与冷暖色温（强制）**：`generation_prompt_cn` 须把光照写成**可执行光学描述**，至少覆盖下列 **6 项中的 4 项**——**(1) 光源类型**（如大型柔光窗/侧向天光/顶散射/动机台灯/混合窗光+反射补光/转台棚拍模拟自然光等，禁止只写“自然光/柔和光”）｜**(2) 主光方向与照亮面**（Key 从哪一侧/高度来，主要照亮道具哪一面/哪条棱边/哪个材质区）｜**(3) 光影过渡与体块效果**（半影**自然柔散、渐变绵长**、暗部保留材质纹理、投影边缘**软过渡无硬切线**、轮廓光分离）｜**(4) 冷暖色温**（主光 ~5500K 中性日光/3200K 钨丝/6500K 冷散射/混合色温分区域；Fill 与 Key 冷暖差）｜**(5) 材质光学响应**（金属/玻璃/塑料/织物/皮革/木材/漆面在 Key/Fil 下的高光色温、反射形状、透明/半透明行为）｜**(6) 四视图各面板光照一致性与特写可读**（第一宫微距须可读划痕/纤维/厚度，全身三视图须同一光源体系、无面板间光向矛盾）。**真人写实类额外强制**：优先**§4.1.3-E 柔和侧逆光 + 正面补光** setup；禁止默认环形灯、无方向均匀顶光、硬闪直打、**硬阴影边界**；白底四视图亦须模拟**柔和自然光**（侧逆光塑形 + 正面 Fill 补光）。
- **中文 prompt**：`generation_prompt_cn` 使用连贯自然中文短段；最低覆盖固定机位、结构视角序列、材质锚点、**§1.3 自然光 6 项至少 4 项**、焦段基线、单状态、纯白背景。
- 必含 `{Viewpoint Anchor}` 与 `{Viewing Direction}` 语义；机位/镜头感需给焦距或等效基线。
- 清晰度：四面板边缘清楚、纹理可读、清晰度一致；禁止某一格虚软。
- 排除引擎参数与控制符：`--ar`, `--v`, `--stylize`, `::`, `<lora:...>` 等。
- **单状态只读**：同一 Subject 只呈现一个物理状态；需多状态但上游仅一条时回流 Stage 2。
- **变体继承**：基准实体 `dependency_strategy.type=Original`, `visual_dependencies=[]`；派生实体 `type=Type A/Type B` 并指向**剧情时序上紧邻的上一完整形象**（读取上游 `dependency_reference` / `base_entity`，禁止跳链直挂远端基础版），命名须与 Subject Index `base_entity` 可追溯（`{基准道具名}_{状态/面/形态}`）。被依赖基准为损毁/破碎态时，须在 `generation_prompt_cn` 逐项回补并强调破损部位、断裂缘、残留形态等可见细节；修复/复原态须写明恢复重建细节。**耗时渐变类衍生**（如书写、绘画、灌注、显影等过程后态，见 Stage 2.1「耗时渐变/延迟生效道具须拆前后两态」规则拆出的「过程前/中间态/过程后」实体）须在 `generation_prompt_cn` 与 `description_cn` 中**逐项写清新增的可见变化内容**（如具体字迹/图案/液位高度/显影图像，内容须与剧情语境一致，不得只写「有文字」「有图案」等占位）以及**未变部分与基准一致**（载体材质、形制、尺寸、边缘磨损等），确保过程前后仅目标变化区域不同，其余细节可追溯延续。**衍生道具光照须与基准同一 Key/Fil/Back 体系**（§4.1.3），仅局部战损/氧化/污迹/渐变结果改变高光与暗部。`visual_dependencies` 禁填 `S001/E001` 等编号，必须用逐字符一致的实体名引用（如 `PROP:[...]`）。
- `negative_prompt_en` 必须短而个体化；道具优先过滤塑料感、玩具感、微缩感、手部残留、时代错置、错误文字；真人写实类追加 `flat lighting, ring light, harsh flash, studio strobe, uniform top light, waxy highlight, plastic shine, no motivated light, hard shadow edge, razor shadow, harsh cut shadow`.
- 合规边界：描述安全、可播出、温和；禁止血腥、断肢、内脏、严重伤痕、肉体变异、强不适污物、涉暴/涉黄/猎奇词。战损只写非图形化状态，如轻微擦痕、磨损、灰尘。

### 1.4 全局最高审美与防平庸规则
- **精美专业默认基调（Mandatory，与 §1.2A 联动）**：无剧情明确负面约束时，道具默认**精美、专业、宏大、高完成度**——结构可信、工艺精致、材质层级丰富、体块完整、照度充足、细节密度 **>10**；禁止塑料玩具感、微缩模型感、廉价展示品、地摊货质感。
- 不做舞台剧、主题乐园、低成本展示模型；在题材、写实度、历史地域、阶层身份允许内，对标电影概念艺术、Prop Master 实物道具与高级静物/Product 定照。
- 最高审美服从题材：喜剧/治愈明亮亲和，情感温润，仙侠灵性秩序，写实可信克制，恐怖惊悚才显著压迫。
- 破旧、贫穷、战损不得极端脏乱差；保留材质层级、光影美感、可播出状态。
- 无明确风格时，道具默认“镜头友好、精致细节、可播出状态”。

## 四、道具专项规范 (Prop Design & Prompts)

### 4.1 Prop Prompt Template
#### 4.1.1 基础原则与信息架构
- **精美专业工艺门禁（Mandatory）**：动笔前须按「结构可信 → 材质分区 → 工艺装饰 → 使用痕迹 → 行业/时代符号」五层补全；每层至少落地 **2 条**可镜头识别细节，合计 **>10** 写入 `generation_prompt_cn`。工艺须写具体技法与可见结果（如拉丝、锤纹、珐琅填色、榫卯、压线、倒角、滚边、激光蚀刻、手工缝线、氧化 patina 等），禁止只写「精致」「高级」「专业感」等空词。
- **专属字段回写**：写清物体是什么、手持/静置、单一状态（磨损/氧化/裂痕/液位/开合等），并全部进入 prompt 主体。
- **绝对纯白底**：`generation_prompt_cn` 必须要求绝对纯白、无杂色、无灰底、无米白、无渐变、无阴影脏污的统一背景画板；禁止摄影棚灰底、暖白/冷灰白、环境反色污染。
- **题材适配**：喜剧/治愈/浪漫整洁明快；情感剧保留生活温度；仙侠可法器感、玉石/金属/木作纹样、灵光、礼制；写实/真人强调真实材质、可信结构、功能痕迹、自然老化；恐怖/惊悚才可加陈旧、不安污迹、冷硬反光。
- **道具光学**：主光优先揭示体块与材质锚点；白底下写清边缘分离、暗部细节托举与**冷暖层次**；须按 §4.1.3 写清光线如何作用到道具各面及产生的效果。
- **历史器物**：有明确年代/地域/文化时，道具必须符合当地器物体系、材料来源、工艺技术、使用礼序、身份象征；禁现代装饰件、错时代结构、错置图案、跨地域混搭。
- **手机支架补全（限明确直播）**：仅当 Subject 或上游剧情**明确为直播**（如直播、开播、固定机位直播等已写明）且手机需作为静物展示时，可在同一 Subject 描述层补支架设定；**普通手机场景**（通话、看消息、手持拍摄、平放桌面等）**禁止**无故添加支架，位置状态以手中/桌面/其他合理依附为准。
- **强关联补齐**：可在同一 Subject 描述层补足已存在的成套关系（如桌椅组合）；若补齐会产生新独立 Subject，回流 Stage 2。
- **真人写实门禁（仅当渲染风格判定为真人实拍时生效，见 Node 1 渲染风格判定）**：道具须符合真实生产、采购、使用、维护逻辑；写材料、连接结构、受力位置、摆放/握持习惯、边角磨损、清洁状态、行业匹配。禁概念款、伪专业、过度奢侈展示模型。三维动画/二维动画道具改按 §4.2/§4.3 的模型/线稿逻辑执行，不适用本条真实生产逻辑门禁。

#### 4.1.2 道具锚点只读机制
- 每个关键道具提供 2-3 个不可变结构锚点，如 `worn brass police badge`；禁瞬态特征。

#### 4.1.3 道具全域光影、自然光与冷暖色温（Mandatory）
- **触发条件**：本节全域光影方法论对所有 `props[]` **强制生效**（光源清单、作用范围、可见效果等通用要求不因渲染风格改变）；**仅当**项目按 `entity_design_common.md` §1.6 判定为真人实拍时（`Project Context.Type`/`Global_Style`/`Base Positioning` **显式**命中真人/真人写实/实拍/Live Action/Photoreal 等制式词，或未声明按默认真人实拍），须优先**自然光/动机光/窗光/反射补光** setup（§E）；`都市/职场/纪实向`等题材标签**不得单独触发**该真人优先 setup。**三维动画/二维动画**道具改按 §4.2/§4.3 的渲染语言执行光影描述，仍须与项目 `Global_Style` 光学气质一致。
- **核心目标**：让生图模型明确「**光从哪来 → 照到道具哪一面/哪条棱 → 产生什么高光/半影/投影 → 冷暖如何落在各材质上**」；四视图白底≠无光源，须模拟**棚内自然光产品/电影道具定照**的常见 setup；**整体氛围须柔和、自然、真实**。
- **E. 「柔和侧逆光 + 正面补光」标准 Setup（Mandatory，真人写实优先；其余题材默认倾向柔和自然）**：
  - **侧逆光 / Rim**：侧后方或侧上方**柔和**轮廓光，分离挂绳/棱边/厚度；禁止硬 rim 光条。
  - **Key**：侧向柔光塑形主体可见面；半影**自然柔散、无硬阴影边界**。
  - **Fill（正面补光）**：相机侧前方反光板/白墙/柔光窗延续，保证正面材质区与微距特写可读。
  - **整体氛围**：柔和、自然、真实；禁止硬闪、硬投影、刀切式明暗分界（恐怖/上游压暗例外）。
- **最低输出量（每个道具）**：
  - `description_cn` 须写 Key/Fill/Backlight **光源类型、方向、色温 rationale** 及**各材质区光学响应**；
  - `generation_prompt_cn` 须按 §1.3「自然光 6 项」覆盖 **至少 4 项**，且第一宫特写段须含 **≥1 条** 冷暖/色温与 **≥1 条** 光影过渡（半影/棱边高光/轮廓光）的具象描述。
- **A. 光源类型（择 1–2 项作主光动机）**：
  - **自然光模拟**：大型北向/侧向柔光窗、均匀天光散射、黄金时刻侧光——须写方位与光斑/渐变形状。
  - **棚拍动机光**：柔光箱模拟窗光、顶散射+侧 Key、转台静物标准 setup——须写 Key/Fil/Back 相对道具的方位。
  - **混合色温**：冷窗光 Key + 暖反射 Fill（白卡/反光板）；冷 Key + 暖 Kicker 勾金属边——须写**哪一侧暖、哪一侧冷**。
  - **题材动机光**：法器灵辉、霓虹点缀、烛光——须与主体 Key 分主次，**禁止**用特效光替代主光动机。
- **B. 光线如何作用到整个道具（Mandatory，须写效果）**：
  - **体块塑形**：Key 照亮面（正面/顶面/斜面）与半影面（侧棱、背光面）；写**棱边高光形状**（窄条/宽软、硬/软）。
  - **材质分区响应**：金属区冷/暖高光 roll-off；玻璃/亚克力折射与边缘光；织物/尼龙纤维在侧光下的纹理可读；皮革/木作/漆面各自的高光与暗部纹理。
  - **第一宫微距**：特写段须写**主光下的微观效果**——划痕走向、氧化层、纤维、厚度、倒角高光，禁止微距段无光影只有材质名。
  - **正/侧/背三视图**：同一光源体系下各面受光不同但**光向一致**；背面须写轮廓/分离光，禁止四格光向矛盾。
  - **投影**：道具在白底上的**接触阴影/落影**（软/硬、方向与 Key 一致），增强体积感；禁止物体如悬浮无影（白底允许轻软接触影）。
- **C. 冷暖色温与材质响应（Mandatory）**：
  - 主光色温 + Fill 色温 + 阴影区环境色；至少 1 组**冷暖对照**或明确同温层次。
  - 金属/玻璃/塑料/织物/漆面高光色温须与光源一致（如冷 Key 下金属偏冷银、暖 Fill 下黄铜偏琥珀）。
- **D. 四视图白底 setup（Mandatory）**：
  - 推荐结构：`{光源类型与方位} Key 塑形{照亮面/棱边} -> {Fill 来源与色温}保留暗部材质纹理 -> {Back/Rim}分离轮廓 -> 整体{冷暖基调} -> 四面板光照一致`。
  - **禁止**：只写「顶部柔和主光、弱补光、细轮廓光」而不列方向/色温/照亮面；禁止无动机均匀顶光。
- **即贴短语库（可改写）**：
  - `顶侧后方柔和侧逆光分离挂绳边缘，左侧大型柔光窗 5500K 侧光作主 Key，右前方白反光板 3800K 暖调正面 Fill，半影自然柔散无硬阴影边界，整体氛围柔和自然真实。`
  - `右侧白反光板 3800K 暖调弱 Fill，托起尼龙织带暗部并保留纤维纹理可读，与冷白 Key 形成轻冷暖对照。`
  - `背后细轮廓光分离挂绳边缘与卡套厚度，第一宫微距可读黄铜划痕走向与亚克力内倒角高光。`
  - `四面板共享同一左前上 Key + 右下 Fill 体系，正/侧/背视图光向一致，白底上轻软接触阴影落向 Key 对侧。`
- **generation_prompt_cn 回写**：光照段须独立成句；第一宫与全身三视图均须可见**光影落在材质上的结果**；禁止只写材质名而不写受光效果。
- **衍生道具**：§A 参考图声明 + 一致项 + Delta 时，**光源体系须与基准一致**，仅状态变化（战损/氧化/液位）可改变局部高光/污迹，禁止无理由改 Key 方向。

### 4.2 三维动画道具专项（Mandatory · 仅当渲染风格判定为三维动画时执行）
- **触发条件（Mandatory，仅接受显式声明）**：按 `entity_design_common.md` §1.6 判定——`Project Context.Type`/`Global_Style`/`Base Positioning`/`entity_attributes.project_global_style` **显式**命中「三维动画」「3D 动画」「CG 动画」「次世代渲染」「风格化三维」等制式词时生效；**不得**因命中都市/职场/纪实向等题材标签而误判为真人实拍。命中本节时，§4.1.1「真人写实门禁」与 §4.1.3「柔和侧逆光 + 正面补光」自然光 setup **不生效**，改用本节渲染引擎语言。
- **子风格判定**：从 `Global_Style`/`Base Positioning` 判定**次世代写实向三维**（PBR 材质、真实感高光反射）或**风格化三维**（卡通渲染 Toon Shading、简化描边），须择一并在 `dependency_strategy.logic` 注明。
- **核心目标**：产出可复用三维道具**模型设定图**——清晰几何体块、可控拓扑分区、材质球分明、渲染引擎质感；四视图画幅基线仍沿用 §1.1（16:9 横向纯白、同一横排、第一宫特写占 35%），特写段内容改写为**结构拆解与材质分区**而非真实生产工艺痕迹。
- **结构与材质语言（替代精美专业工艺门禁）**：
  - **次世代写实向三维**：材质写 PBR 参数化语言（金属度 Metallic、粗糙度 Roughness、法线贴图细节、环境反射 IBL）；结构写清晰几何体块与倒角（Bevel）而非手作工艺痕迹。
  - **风格化三维**：材质写**卡通色块 + 简化高光形状**（无真实物理反射）；结构写简化几何体块，边缘可有统一描边规格。
- **光影（替代 §4.1.3-E）**：次世代写实向三维写「三点布光 + IBL 环境反射」；风格化三维写「硬边卡通阴影块 + rim light 描边高光」；仍须落实 §1.5 冷暖色谱理念，但语言须为渲染引擎术语，不适用自然光/棚拍模拟自然光的真人 setup。
- **输出校验**：`generation_prompt_cn` 须含 ≥6 项可检索几何体块/材质分区锚点（结构拆解、材质球类型、渲染方式、描边规格如有）；`negative_prompt_en` 追加 `photorealistic material photography, real object photo, film grain, DSLR photo quality, real world wear photograph`（风格化三维额外追加 `photorealistic PBR material`；次世代写实向三维额外追加 `flat toon shading, 2D line art`）；`anchor_description` 用三维语汇（如 `3D stylized prop, toon-shaded geometric block` 或 `next-gen 3D prop, PBR material, realistic reflection`）。
- **禁止项**：真实生产/采购/维护逻辑话术、手工工艺痕迹描述（拉丝/锤纹/珐琅等真人实物工艺属 §4.1.1）；赛璐璐线稿/纯二维块面语言（属 §4.3）；材质穿帮（贴图拉伸、UV 接缝、法线错误）。

### 4.3 二维动画道具专项（Mandatory · 仅当渲染风格判定为二维动画时执行）
- **触发条件（Mandatory，仅接受显式声明）**：按 `entity_design_common.md` §1.6 判定——`Project Context.Type`/`Global_Style`/`Base Positioning`/`entity_attributes.project_global_style` **显式**命中「二维动画」「赛璐璐」「二次元」「日漫」「美漫」「扁平插画风」「Cel-shaded」等制式词时生效；**不得**因命中都市/职场/纪实向等题材标签而误判为真人实拍。命中本节时，§4.1.1「真人写实门禁」与 §4.1.3「柔和侧逆光 + 正面补光」自然光 setup **不生效**，改用本节线稿/色块语言。
- **核心目标**：产出**赛璐璐风格道具设定图**——清晰线稿、二维色块明暗，仅表现纯二维质感；四视图画幅基线仍沿用 §1.1，特写段内容改写为**线稿结构与上色分区**而非真实材质工艺。
- **线稿与上色规范（Mandatory）**：主线粗细统一声明并四视图一致；材质用**平涂色块 + 1–2 层硬边阴影分割**表现（无渐变、无真实反光纹理），金属/玻璃等特殊材质用**简化高光块**（如一道白色斜向高光条）示意而非真实物理反射。
- **光影（替代 §4.1.3-E）**：仍落实 §1.5 冷暖色谱理念，但转译为**赛璐璐式硬边阴影块**——阴影边界清晰、高光为块状/点状；**不适用**自然光/棚拍模拟自然光真人 setup。
- **输出校验**：`generation_prompt_cn` 须含 ≥6 项可检索二维设计锚点（结构简化描述、主线规格、上色分区方案、高光块位置）；`negative_prompt_en` 追加 `photorealistic material, real object photo, 3D render, PBR shading, realistic lighting gradient`；`anchor_description` 用二维语汇（如 `2D anime prop, cel-shaded, flat color block`）。
- **禁止项**：真实工艺/材质纹理话术；三维几何体块/PBR/卡通渲染语言（属 §4.2）；线稿粗细在四视图间不一致、色块阴影写成真实光影渐变。

## 六、输出模板（严格）
- 唯一输出物：一个 JSON 代码块，仅含 `props`。
- 顶层必须存在 `props` 数组；无实体输出 `[]`。

### Entities JSON (Strict Schema)
**结构最高优先级**：JSON 为唯一单对象；根节点固定含 `props`；数组按 `subject_type=prop` 路由，错分即重写。

#### JSON 内容共性硬约束
- `props` 必须完整覆盖所有 prop Subject；不得只保留代表项。
- 输出前逐条核对输入类型与输出数组；总数正确但归类错误仍失败。
- 字段按类型分离；`props[]` 使用道具状态/类型字段，禁止角色字段借壳。
- `name/name_en/base_name_en` 等名称与输入 subjects index 逐字符一致；任意字符差异必须修正。
- `description_cn` 与 `generation_prompt_cn` 必须纳入 `entity_attributes` **全部**要素（零缺失，见 common §1.3），并显式包含 §1.2A **项目语境+风格定位**可视化落点（含 `风格定位为{…}`）。**渲染风格分流（Mandatory，先判定见 Node 1 / common §1.6）**：**真人实拍**（显式声明或未声明默认）——须说明 Key Light / Fill Light / Backlight 的**光源类型、方位、亮度、色温与冷暖对照**，以及**光线如何作用到道具各材质区的效果**，并按 §4.1.3 写清自然光 setup。**三维动画**（显式声明）——按 §4.2 执行几何体块/材质球/渲染引擎光影语言。**二维动画**（显式声明）——按 §4.3 执行线稿/色块/赛璐璐阴影语言。三类不得混用；`generation_prompt_cn` 细节特征 **>10**（覆盖 ≥4 类别）；`generation_prompt_en` 保留但输出 `""`。
- 固定双语字段契约沿用；每个实体必须提供 `visual_dependencies` 与 `dependency_strategy {type, logic}`。

      "name": "警徽挂绳证件卡",
