  - **边界**：未达上列明文 → 不得自称全局而绕过极严；一次消耗品即使偶写「重要」≠全局。❌ 玉佩写「全局性道具」却只进服装｜✅ 提 PROP + `prop_scope:全局`。
- **全局角色 / 全局环境（场级核销；提取不漏名）**：上游或 Stage 1【实体覆盖】明文`全局角色`/`全局环境`（及等价词）且本场涉及 → CHAR/ENV 行**必须**落表（命名逐字）；环境名须与【主环境】/上游注册名一致。禁因戏份少漏提**有可见形象**的全局角色；禁把全局环境近义改名另建。**例外**：全局标签但全输入仅画外音/无形象 → 仍服从「纯画外音禁 CHAR」，不提。
- **ENV/PROP 互斥（XOR，根本原则）**：同一物理物件**必须且只能**落一侧——ENV 空镜字段（`fixed_furniture_and_set_dressing` / `fixed_architecture_and_finish` / 四向拓扑/标识文字等）**或**独立 `PROP` 行；禁双写/交叉描述。**例外=载具双用途**：整车 PROP 与舱内/甲板占用 ENV 分名并存，不算同物双写（见下条）。拟建 PROP 前必先检索全部 ENV 行（同名/同义/可识别同物），并过上条极严原则（或全局强制）：
  1. **全局性道具→PROP（强制）**：命中全局明文 → 建 PROP，**立即从全部 ENV 剥离**；不适用四禁拒提。
  2. **过极严门槛→PROP**：不可归 ENV/CHAR，且有可持续关键状态变化（或跨场复用资产价值）并过四维 → 建 PROP，**立即从全部 ENV 剥离**。**拿起/递交/使用/破坏/一次性出画 alone 不够**；**一次消耗品不适用**（见「三、道具」）。
  3. **固定空镜→ENV**：固定建筑/装修/大件家具/基础陈设，或可归环境描述且未过极严门槛、亦非全局性道具 → 留 ENV，禁单列 PROP。
  4. **歧义默认不提 PROP**：未达极严门槛且非全局、一次性露出/一次性出画/纯装饰/可归 CHAR → 归 ENV 或 CHAR 或仅留 Beat。**一次消耗品**默认仅留 Beat（Stage 1 已作氛围陈设则留 ENV），不视为两侧遗漏。
- **载具/机甲：体内体外双用途（最高；覆盖“无状态不提 PROP”）**：扫描每个驾驶舱、客舱、操纵舱、甲板、舰体表面及其他载具占用主环境，**体内与体外各自判断**。本集要把整车/整舰放入港口/海面/道路/天空等他环境展现 → 必须找到 Stage 1 具名整车 PROP，且其 `挂场ENV` 须是更大的宿主主环境；**禁止以“舱内/甲板 ENV 已经代表整车”为由漏提，禁止把自身占用 ENV 当作容纳整车的子环境或挂场**。**占用 XOR**：`挂场ENV` 只给整车 PROP 无人全景用；有人占用舱/甲板时当前环境仍是占用 ENV，不得把宿主大环境写成占用场的挂场。
  - 整车/整机/整甲置于宿主环境中的可移动完整物体 → `PROP`（`exterior_asset_scope:完整外轮廓`）。因体内外连续性与跨镜复用，直接过极严门槛。
  - 舱内或甲板/舰体表面/车顶/翼面等可站立走位的占用空间 → `ENV`（`exterior_asset_scope:外部场景空间` 仅甲板等体外占用）。占用 ENV 与整车 PROP **分名并存**，不算 XOR 双写。具人格按角色表演的机甲仍按上游分类，禁擅自降格。
  - 内部/甲板 ENV 行必填`host_exterior_subject:{整车PROP逐字名}|无`；整车 PROP 行必填`interior_env_refs`/`exterior_env_refs`（多舱/甲板用`|`）、`exterior_asset_scope:完整外轮廓`。体内外与整车共同透传车型/舰型、尺度、主色材质、舱门窗位；舱内座椅/仪表不写进整车，整车完整外轮廓不写进占用空镜。
  - 占用 ENV 存在而 Stage 1 未登记整车、且本集确有整车入他环境 → `upstream_missing_vehicle_mecha_exterior_asset:需要回流 Stage 1 具名登记整车PROP`，禁本阶段自造型号；已有泛称则按原词建泛型资产，禁臆造品牌型号。
  5. **输出前自检**：逐物件删并归位；确认无「可归 ENV/CHAR / 无状态变化 / 一次性出画」误入 PROP；**全局性道具无漏提**；无消耗品误入 PROP。
- **全覆盖 XOR**：Stage 1【主环境】清单每一实体恰好落一侧（PROP 或 ENV）或（未达 PROP 门槛时）留 ENV/Beat；禁双写与两侧同时消失。**未过极严门槛且非全局者不得为「全覆盖」硬提 PROP**——应留 ENV（或 CHAR/Beat）。**全局性道具必须进 PROP**。**一次消耗品例外**：可仅留 Beat（或保留 Stage 1 已写 ENV 氛围），不强制进 PROP。
- **落表序**：先 ENV 后 PROP（PROP = 过极严门槛者 **或** 全局性道具）。
- **冲突优先级**：`上游硬约束`（含**全局性道具强制提取**） > `ENV/PROP XOR` > `道具提取极严` > `命名完全匹配` > `输出格式边界` > `不重不漏闭环` > `美术建议`。文字载体 `visible_text`/`text_layout`/`typography_requirement`/`script_variant` 剧情补字属「不超出原文」的补字例外（见上条），优先于「禁创造」但不得扩及其他臆造。

## 核心任务

- 只提取 **`cover_poster`** → 标准 `Subject Index`；角色/道具/主环境完全继承全局统筹与环境规划，**不得落 CHAR/ENV/PROP 行**。
- **场级卖点→资产优先级（只读指导；不改提取门槛）**：读取 Stage 1 Part1【核心卖点】逐场行与各 Scene【高潮与核心情绪点】/【卖点综合】中的`本场卖点/类型/制作指导·资产/卖点通道`。有卖点场：对该场已声明且命中类型的实体（如四美·美食/美物→对应 PROP；四美·美人/精彩对白/`冲突`→相关 CHAR；动作/打斗→载具/兵器类已声明 PROP）在落表时**优先完整摘录**上游外观/状态字段，禁因「次要」省略。四美·美景/宏观**不**在本环节落 ENV——归环境资产设计。仍服从极严/XOR/禁补衍生——卖点**不**授权新建未声明资产。
- **闪回/回忆同等提取**：完整闪回 Scene 与快速闪回切片中 Stage 1 已具名可见主体，同规则落表；禁因「回忆/短/仅质感」漏提（细则见「一、整体底线」）。
- **多主环境 / 衍生环境（只读，不落表）**：同 Scene 可有多块【主环境】与【衍生环境】。本环节**不提取**主环境行、`0度{主名}` 或任何 `{N}度…` 衍生行。缺主环境/缺衍生→回流环境规划或现场编排，禁本阶段补建或写入 Index。闪回/蒙太奇异地只核销 CHAR/PROP，不另建 ENV。

## 标准流程

1. 读 `SCENE_ENV_IDENT` + 环境块（只读）→ 锁定挂场主环境名与 IDENT `情绪表达`；【未落清单】作道具/待入画落点，**不**默认升 PROP（不建 ENV；升 PROP 须过极严门槛）。IDENT 或缺主环境→回流环境规划。**禁止**据此落 `environment` 行。
1-b. **先完成本环节服化道核销**（见「服化道核销」）再深扫 Beat。
2. 逐 Beat 建置+入戏（禁按已废弃分列查找）：⓪承接 → ①可见 CHAR/PROP（对照未落清单落点+摘要环境细节；**不改清单落点、不落 ENV**）→ ②交互/轨迹 → ③换装（摘要「服饰/换装」优先，见「剧情明文换装」）→ ④对白具名 → ⑤微表演跳过 → ⑥群演/龙套分流（有个体具体剧情动作→龙套单提；仅全员无个体动作者→群演簇）。闪回同等。无【Scene实体覆盖】时以 Beat 明文为准。
3. 新 Scene 前重检 CHAR/PROP（见「CHAR 重评估」）；摘要已写新装/换装时优先新衍生。
4. 分类：先落**全局性道具**再过常规极严+XOR；上游已写描述入库；换装先多行 CHAR 再写各行 `clothing:`。
5. 终检 checklist → 输出单表（仅 CHAR/`cover_poster`）。

## 资产建立规范

### 一、整体底线

- **`plot_stage:`（每行必填）**：据场景头后缀（正常叙事/闪回/倒叙）或明文「梦境/想象」等；无则 `plot_stage:正常叙事`。
- **`basic_positioning:`（CHAR/PROP 每行必填；最高）**：一句**叙事基本定位**——清单与 Stage 3 须立刻读出「这是谁的什么、多大、什么气质」。**≠** `purpose`（观察用途/功能槽位）**≠** `identity`/`plot_role`（可引用，禁只复述番位或职衔）。句式优先：`{剧情归属或叙事身份}，{体量档}，{气质/品级/类型}`。
  - **CHAR**：如`女主，婚前独立生活，精致克制的都市白领`。须含番位或叙事身份 + 可核销处境/阶层/气质（有则）；**不得**只写`女主`或只抄 `identity:`。群演簇写簇定位（如`婚礼宾客群演簇，背景气氛体`）。神兽/宠物写物种+叙事关系（如`女主婚前伴侣猫，小型家猫`），无关系则物种+在场功能。
  - **PROP**：如`女主婚前随身玉佩，掌心大小，温润精致`。须含剧情身份/信物属性 + 文学体量气质；`relative_scale` 仍另写人体参照。禁只写`道具`/`信物`。全局性道具须点明贯穿/信物定位。
  - **证据**：CHAR/PROP 从【角色设定】/服化道/命名表/Beat 可核销词**压缩转译成一句**（归档，非创造新资产）。气质词（精致/素净/豪华/简朴）须有上游或等价可核；无则省略气质，只写归属+类型+体量。CHAR/PROP 体量无明文时，可据名称类型词或相对尺度弱推断一档；禁无据升格豪宅/宫殿。❌只落名无定位｜❌CHAR 只写男主｜✅归属+体量+气质一句可检索。
  - **衍生行**：CHAR/PROP 衍生继承基准句，可在句末加本态短注（`…；晚宴盛装`／`…；点燃态`），禁另起无关定位。
- **资产外形设计线索全量总结（最高；供 Stage 3 环境与服化道）**：凡剧本/Stage 1 对该资产写过的**外形及相关设计信号**——含**风格、地位/品级、作用/功能**，以及色泽材质、妆发服饰、陈设气质、品级档、信物档等——**必须扫全并总结写入**对应行 `entity_attributes`，使 Stage 3 **不必回读全文**即可做环境空镜与服化道定妆。`basic_positioning` 只给一句总括，**不能**顶替本条分键。
  - **软性外形决定因素（最高；与硬外形同核）**：身份、特殊用途、地位，以及剧本**明确写出**的外形评价词，均可决定 CHAR/PROP/ENV 的外形完成度、品级、气质与性感/精致档——**必须完整总结**入该行 `entity_attributes`。禁只收色泽/形制而丢掉这些软性信号；禁因「主观夸赞/对白口吻/一次性评价」省略。硬外形（黑外套/木桌）不够；软性因素同等强制。
    - **身份** → `identity:`（世界内身份；须可视觉化：警察制服信号、公主冠服品秩、修士层级）。≠ `plot_role`。
    - **特殊用途** → ENV/PROP=`purpose:`；CHAR 另有叙事功用且≠身份时=`narrative_function:`（晚宴诱饵、传家信物、刑侦伪装——**用途定外形档**，禁只写功能不写其对完成度的暗示）。
    - **地位** → `social_status:`（阶层/品级/信物档/场域品级；≠身份职衔、≠番位）。
    - **原文评价词** → **`appearance_cues:`（有则必写）**：对该实体明确写出的外形/气质形容词**原词完整收录**，多词用全角`｜`分隔。典型闭集不限：`高贵`｜`精致`｜`漂亮`｜`性感`｜`绝美`｜`华贵`｜`素净`｜`冷艳`｜`俊美`｜`秀丽`｜`雍容`｜`华丽`｜`清丽`｜`朴素`（仅原文有）等。**禁止**改写成更虚的「好看/高级/有气质/漂亮点」。对白「你真漂亮」「这小屋真精致」「穿得那么性感」、场注「绝美裙子」、主环境「精致小屋」、服化道「高贵礼制」均=可复用设计信号。无原文评价词→**静默省略本键，禁臆造**性感/高贵。评价词可同时作 `style:`/`appearance:`/`clothing:`/`literary_atmosphere` 定语，但 **`appearance_cues` 必须可检索原词**（不能只用风格概括顶替）。
    - ❌原文「绝美裙子/精致小屋/高贵/性感」Index 无 `appearance_cues`｜把「性感」压成 `style:时尚`｜对白夸赞当瞬时微表演跳过｜只用 `basic_positioning` 吞掉「漂亮」
    - 合法句式：`identity:公主；social_status:当朝嫡公主；appearance_cues:高贵｜漂亮；clothing:绝美礼服`
  - **四维归键（有证据必写；无则该维静默省略、禁臆造）**：

    | 维 | 写入键 | CHAR | PROP | ENV |
    | :--- | :--- | :--- | :--- | :--- |
    | **外形** | `appearance:`/`clothing:`；PROP 另 `form:`/`material:` | 相貌妆发体态、服饰形制色泽、可见配饰 | 形制/材质/色泽/工艺/可读面 |
    | **风格** | `style:` | 冷峻机能/精致克制/礼制华贵等 | 同左，跟物件工艺气质 |
    | **地位** | `social_status:`（≠ `identity`/`plot_role`） | 阶层品级（当朝公主/小康白领/世家子弟）；职衔仍走 `identity:` | 物件品级/信物档（传家/御赐/日常随身） |
    | **作用** | PROP=`purpose:`；CHAR 另有叙事功用且≠身份时写 `narrative_function:` | 如`本场控场女主人`（禁只写女主） | 何时何功能+槽位（已有 `purpose`） |
    | **软性评价** | **`appearance_cues:`**（有则必写；原词`|`并列） | 漂亮/性感/高贵/绝美等对人外形词 | 精致/华贵/温润等对物件词 |

  - **扫描源（强制；散落也要收）**：①【角色设定】外形/性情/特定动作/**身份·地位·外形评价**；②服化道三项（环境细节/服饰换装/道具细节）；③【主环境】文学、固定清单定语、【场景名称】；④【角色命名】地位/身份列；⑤各 Beat【建置】【入戏】中的外形/服饰/陈设/气质词；⑥对白与场注里可核销的外形评价（「这小屋真精致」「穿得那么素净/性感」「你真漂亮」「御赐玉佩」「高贵」）——**对白夸赞≠瞬时微表演，须入库**。只收**可复用设计信号**，不收瞬时微表情/单次走位（评价词除外）。
  - **写法**：按维**总结成短短语**入库，**保留上游原词**（可压缩并列，禁改成更虚的「好看/高级/有气质」）；`script_entity_coverage` 须覆盖各维关键词及 `appearance_cues` 原词。同一语义只写一次、按项目语言去重。ENV 四维成稿仍守纯空镜：地位/作用用场域语，禁角色姓名。
  - **失败**：剧本有「精致小屋/素净衣裙/礼制/传家/漂亮/性感/高贵」等却 Index 无对应键或无 `appearance_cues`｜只写 `basic_positioning` 丢掉分维｜把地位压进 `plot_role`｜把风格丢掉只留功能｜把评价词改成「好看」。❌「室内」吞掉「不大但精致」｜❌「绝美裙子」只写礼服无 `appearance_cues:绝美`｜✅ `style:精致克制` + `social_status:婚前精致小屋` + `appearance_cues:精致` + 外形原词进 `literary_atmosphere`/`appearance`。
- **季节/气候联动**：场景头有季节/气候时，ENV 写 `season`/`climate`；CHAR/PROP 若着装/材质受影响须显式入库。
- **上游已有描述零缺失入库（共通权威）**：Stage 1 /【角色命名】/【角色设定】/服化道摘要/环境块/Beat 中对该实体**已写明**的可复用描述**必须**按上条四维归键总结入库，并严格保留原词（风光、服饰妆发外形、尺寸色泽、性格、**身份/职衔/品秩/修为层级**、**地位/阶层/品级**、**特殊用途**、**原文外形评价词（高贵/精致/漂亮/性感等→`appearance_cues`）**、年龄、**风格**、材质、**作用/用途**、氛围、特定动作、**活动空间/活动适配**、**剧情配饰挂载体侧/具体部位**、**基本定位可核销词**等）；**CHAR/PROP/ENV 另强制 `basic_positioning:`**。禁只落名、禁压成「主角/道具/室内」、禁因「下游会补」省略。无证据→**静默省略、禁臆造**（`basic_positioning` 除外：无气质证据可省略气质词，仍须写归属+类型+体量）；有证据缺一即失败。`script_entity_coverage` 覆盖对应关键词。【角色设定】`外形/性情/特定动作` 优先（`appearance:`/`personality:`/`signature_action:`）；**身份/职衔类必须进独立键 `identity:`**（见「二」），**地位/阶层另进 `social_status:`**（见上条），**原文评价词另进 `appearance_cues:`**，禁互代、禁只埋性格句；服化道非「无」具体词须入库；ENV 活动空间见「四」；**PROP 另强制 `relative_scale:`（见「三」）**；**升格配饰 PROP 另强制 `wear_side`/`mount_body_part`/`detachable`（见「二」）**。分类节只补键名要求，不重述本条。
- **服化道/环境初始态锁定（最高；继承 Stage 1 §7）**：主环境基准行与 CHAR/PROP **基础版**属性 = 服化道摘要 +【主环境】/【角色设定】的**原文初始建立态**（开场/场头/空境/入场初态）——**严格摘抄，禁把 Beat 剧情发展终态（狼藉/废墟/战损/湿透/毁损）回填进基础版**。剧情过程变化：已声明状态衍生→写入对应衍生行；明文换装→独立 CHAR 衍生行；仅瞬时过程且无衍生行→留 Beat、禁臆建、禁污染基础版。**整体环境状况改写分场（继承 Stage 1 受损切口）**：上场主环境基础版=完好基准；下场（从受损实际发生拍起）基础版=该场开场改写后建立态；禁把上场基准写成废墟，禁把下场基础版写成完好。Stage 1 若把终态写进主环境基准而未拆状态衍生/新 Scene，或受损分场切口错位（崩塌写完在上场再切）→ 标 `upstream_mixed_plot_into_baseline` / `upstream_damage_cut_misaligned` 并回流，禁自行「修正」混写。
- **服化道核销（最高；本环节产出）**：先从本场原文初始态（开场/场头/空境/入场初态、【主环境】、【角色设定】、【场景衔接】、Beat 建置/入戏可见初态）自行提取，再据此入库。内部须能核销为：
  `【服化道核销摘要】环境=…|无｜服饰/换装=…|无｜道具=…|无｜全局道具=…|无`
  三项语义=**该场初始态**；没有写 `无`，禁止补造。上游若已有标准三项或【场景衔接】内自由写法（`服饰换装：…` / `服饰/换装：…` / `换装：…`）→ 对照消费，不得因缺标签忽略。必须识别并消费：
  1. **服饰/换装→CHAR（最高硬约束）**：非「无」时**逐具名**解析着装/换装证据。凡命中「剧情明文换装」任一触发 → **必须**拆 ≥2 条独立 `character`（基础版 + 新装衍生），**禁止**只更新一行 `clothing:` 糊弄；仅同套已着装且无换装/第二套证据 → 才写入当前行 `clothing:`。例：`Serena从员工便服换为绝美裙子` → 必出 `Serena` + `Serena_礼服版`（或 `_裙子版`/`_盛装版`）两行，各写各装。基础版 `clothing:`=旧装/入场初装；衍生行=新装——**禁**把新装终态写回基础版唯一行。
  2. **环境细节→不落 ENV**：服化道「环境细节」只作 XOR / CHAR `scene_mood_cue` 对照；**禁止**写入 Index `environment` 行。狼藉/域场终态不得回填环境规划基准（归环境资产设计读场景分析）。
  3. **道具细节→先扫全局性道具，再判极严门槛**：摘要/未落清单/【实体覆盖】/设定明文「全局性道具」等 → **必须 PROP**；场级漏标但项目/集纲明文全局且本场持用 → 仍强制 PROP + 回流 `stage1_missing_global_prop_scene_mark`；其余可归 ENV/CHAR、无状态变化、仅一次性出画 → **不提 PROP**（ENV 定语 / CHAR `clothing:`/`appearance:` / 仅留 Beat）；过常规极严门槛者 → PROP（服从 XOR）；入场初态进基础版；明文状态衍生进对应行。
  4. **与 Beat 冲突**：画面过程/终态以 Beat 为准，但**入库基础版仍以初始服化道+角色设定为准**；摘要多出可核销初始细节仍入库；摘要写换装而 Beat 仅新装现态 → 仍按换装多行（入场新装=换装后衍生；**禁**因「未见更衣过程」并回单行）；Beat 终态毁损/狼藉**不得**覆盖基础版，须落已声明衍生或回流 Stage 1。
  5. ❌ 摘要有换装/新装却只落一行｜跳过摘要/跳过转场块只扫 Beat｜把两套服装塞进同一行 `clothing:`｜把剧情终态狼藉写进主环境基准｜✅ 先转场服化道再 Beat 双核销，一人一套一装一行；初始归基准、剧变归衍生。
  6. **服化道连续性（单独列 `form_continuity`；最高；与资产名一并注入场景编排）**：CHAR/PROP 须在本列写清**形态变化发生在哪一场、什么时候**。本列≠ `entity_attributes` 里的 `applicable_scenes`/`activation_beat`（那六键仍写衍生行属性）；本列是给场景编排的**可读换版说明书**。见「服化道连续性」。
- **闪回/回忆**：
  - 完整闪回 Scene（较长回忆）/ 同场快闪·蒙太奇切片内 Stage 1 已声明主体同等提取；本阶段**不**自创环境——Stage 1 据情节新建的异地主环境须已声明，缺则回流。
  - Stage 1 已声明的闪回/蒙太奇【主环境】及对应衍生**必须逐条提取**（`plot_stage:闪回` 或场景头/主环境角色证据）；同场蒙太奇多主→多行主环境基准，各挂各衍生族；独立闪回 Scene 的主环境按该场提取。
  - 与当下无实质差异、仅质感区分 → 可复用基础版；有年龄/妆发/空间时代/道具状态/身份等可识别差异 → 建衍生并写链。
  - 仅出现于回忆仍须提取。❌ 闪回幼年/父亲/旧客厅只提当下｜✅ 提闪回主环境+CHAR/PROP 衍生并建链。
- 安全红线：禁血腥/断肢/肉体变异词；战损意象化。
- 新增实体须可持续、可复现、可继承；瞬时变化不建新实体。
- 特效不独立成实体，挂宿主衍生；跨 Beat 可持续改写固定空间结构的域场 → ENV 状态衍生（见命名规范）。临时光效/粒子/拖尾仅留 Beat；可持续可命名施法形态建衍生并写触发源/持续形态/识别锚点。
- ENV 仅纯空镜（见「四、环境组」）；XOR 见「规则强约束」。

### 二、角色（CHAR）

- **群演簇 vs 龙套（最高硬约束；先判动作再落表）**：
  1. **群演簇门槛（须同时满足）**：Stage 1 以簇/阵/列/若干描述；**无具名个体**；无独立对白/OS；无跨 Beat·Scene 可持续身份；且簇内**每一个**成员均**无具体剧情动作**——仅统一反馈、簇状动势、氛围密度、齐进齐退/齐跪齐立等集体行为。→ **一条** collective `character`；名与 Stage 1 逐字一致；属性含 `plot_role:群演簇`、`crowd_role:群演簇`、**数量区间（人数/规模，摘抄 Stage 1 可核销规模词）**、**排列/队形**（纵队/横列/方阵/扇形围观/散点等；军警/仪仗制式簇须含整齐度与行列）、FG/MG/BG 分布、反馈模式、景别约束、服饰倾向。Stage 1 缺人数或队形 → 标 `upstream_missing_crowd_scale_or_formation:需要回流 Stage 1 补人数/规模与排列`，**禁**臆造。**服饰倾向须标制式信号（供 Stage 3）**：有军警/卫兵/僧道仪仗/校服工装/同制甲胄等统一着装 → 写 `制式统一`（或等价）；路人宾客杂装等 → 写 `杂装`；异兽/神兽/魔兽等非人簇 → 写 `非人集群`（有鞍辔甲胄制式则兼标 `制式统一`）。**人态簇另须把上游已写服饰词与附属物写入 `clothing:`**（形制/色泽/甲胄/靴履/徽识/骑装/器械/旗帜/坐骑鞍辔），粒度同具名 CHAR 衣着+道具描述；军警/仪仗/大军等制式簇禁只标「制式统一」而无任何可画形制词——上游无词则标 `upstream_missing_crowd_clothing`，禁臆造朝代空壳。**群演不抽 PROP（最高）**：簇自用配饰/器械/旗帜/坐骑等**禁止**另建 `prop` 行、**禁止**写 `accessory_props`；一律并进该簇 `clothing:`。有坐骑/骑阵须摘物种+鞍辔/蹄装词（有则）。禁拆纯氛围 filler/编号个体；禁把具名角色并入簇。簇已入 Index 时 ENV `literary_atmosphere` 不得重复写同名簇密度。
  2. **有具体剧情动作→龙套单提（强制）**：凡上游对某人写了**可核销的个体剧情动作**（独立走位/递物拦路开门传信/单独交互或受力/单独主动作链/**画内**个体对白或可辨识个体反应等——区别于「众人齐望/簇状骚动」；**纯画外音/OS/V.O./旁白且全输入无可见形象者不适用本条，见「纯画外音禁 CHAR」**）→ **禁止**并入或冒充群演簇；必须按**龙套**抽取为**单个** `character`：`plot_role:龙套`（非`群演簇`）；无真名则合法取名（禁番位词）；过「具名 CHAR 门槛」的可持续身份可升配角等，仍禁塞回簇。同一场景可同时存在「氛围群演簇一条」+「若干龙套单行」——有动作者从簇剥离单提，余下仍无个体动作的氛围体才可留簇。
  3. ❌「卫兵甲推门入画、卫兵乙递刀」却整并一条群演簇｜把有单独走位终点的手下塞进「随从簇」｜✅ 有动作者各提龙套；仅齐跪/背景晃动的余部才可提群演簇。
- **纯画外音禁 CHAR（最高；无形象不提资产）**：凡说话人在全输入中**仅**以画外音/OS/V.O./旁白/电话·对讲听筒声等**听得见但镜头不可见**的方式出现，且**无任何可核销可见形象**（无建置落位、无入画出画、无外形/服饰/姿态描写、无【角色设定】外形、无闪回可见本体、**无照片/视频/画像/屏幕等介质面孔**）→ **禁止**抽取为 `character`（亦禁 PROP/ENV 冒充其人）。声线/台词只留 Beat；禁因具名、`voice_identity`、全局角色标签或「有 OS 叙事功能」落表。**例外（须可核销可见）**：同名主体在任一场/Beat/闪回已入画、有外形证据，或**介质内可辨识面孔** → 按正常 CHAR 门槛提取（可含其 OS 戏份）。❌ 全片只闻其声的老板/系统音/电话那头却建 CHAR｜✅ 不提行，OS 留剧本｜✅ 桌上遗照/监控回放里的具名人须提 CHAR。
- **介质可见也抽 CHAR（最高；与全局统筹同核）**：照片/相片/遗照/证件照/画像/肖像/通缉令/屏幕/电视/手机录像/监控回放/全息等载体上出现可辨识个体面孔（具名或原文独一面貌/身份线索）→ **必须落 `character` 行**，即使本人从未入画。介质物件（相框/相册/手机）按 PROP/ENV XOR 另判；**禁止**只提「某某的照片」PROP 而漏提人。群像背景无法辨认的路人脸不提。
- **具名 CHAR 门槛**：①具名（或龙套合法取名）；②**须有可核销可见形象或画内戏份**（建置/入戏可见落位、外形/服饰证据，或**介质内可辨识面孔**；**纯画外音不适用**）；③独立叙事功能（**画内**对白、**具体剧情动作**/跨 Beat 主动作、跨 Scene 身份、可继承外观/身份态、**介质内被指认/被观看的身份**——OS  alone 不够）；④非纯氛围单次出现。纯氛围且全员无个体动作 → 才可走群演簇。命中「纯画外音禁 CHAR」→ 直接不提，不走本门槛。
- **有戏份宠物→CHAR（强制）**：具名/专属称呼，或跨 Beat 主动作/反应，或为互动/情感焦点，或可继承外观关系态 → `character`；禁降 PROP/并 ENV。必含 `entity_kind:宠物`、`species:`；`plot_role` 配角/龙套等；外形性情特定动作入库；`gender`/`age_tier` **仅上游明文公母/代词/龄态时才写**（不足则静默省略，**禁**默认 `男`、**禁**套用 23 岁）；幼崽有明文→可写幼童/儿童层次，仍禁臆造岁数。无戏份氛围活物→PROP「无意识活物」或留 Beat；无人格坐骑/载具→PROP（**群演簇自用坐骑除外**：并入该簇 `clothing:`，不另提 PROP）。❌ 旺财提 prop｜✅ character+宠物字段。
- **人态化特效主体→CHAR（有可持续身份时）**：Stage 1 已具名且跨 Beat 可辨外形的**法相**/化龙凤兽/巨化体/拟人灵体等，若有独立叙事功能或可继承外观 → 提 `character`（`entity_kind:法相|化形|巨物|其他` 择一；`plot_role` 多为其他/配角）；命名与 Stage 1 逐字一致。仅单拍瞬时无定形介质→不提 CHAR，留 Beat。建置朝向等仍由 Stage 1 承载，本阶段只落可复用行。**性别/年龄服从下条「神兽/非人」豁免**（非拟人且无明文时禁硬填）。
- **神兽/异兽/魔兽/妖兽/灵兽/坐骑等非人主体（性别·年龄豁免；最高）**：凡 `entity_kind` 或上游定位为神兽/异兽/魔兽/妖兽/灵兽/瑞兽/坐骑/非人集群/非拟人化兽形等——**禁止**为凑三键而臆造或强制填写明确 `gender`/`age_tier`/`约N岁`。上游明文公母/雌雄/性别代词或龄态（幼崽/千年等）→按证据摘抄；**无明文→静默省略这两键**，只写物种外形/性情等可核销属性。❌ 青鸾无性别却填`gender:女`+`约23岁`｜✅ 只写 `entity_kind`/`species`/外形，性别年龄从缺。
- **结构化三键（每 CHAR；人态角色必填 gender/age；神兽类见豁免）**：
  - `plot_role:`∈`男主|女主|男二|女二|反派|配角|龙套|群演簇|其他`（优先命名表→占位→戏份；宠物默认配角/龙套；簇=`群演簇`；衍生继承，禁因换装改番位；禁多名同时男主/女主，双主角项目除外）——**每 CHAR 必填**
  - `gender:`∈`男|女`（簇可 `混合`；优先命名/身份→`plot_role`→代词；衍生继承；不足时具名**人态**据称谓裁定）。**神兽/异兽/魔兽/妖兽/灵兽/坐骑/宠物/非人集群等**：无上游明文→**省略本键**，禁默认男/女
  - `age_tier:`∈`幼童|儿童|少年|青年|中年|老年`（可另写 `约N岁`；**未明确年龄默认（仅人态角色）**：`age_tier:青年` + `约23岁`；有层次无岁数且层次为青年时补 `约23岁`；层次为幼童/儿童/少年/中年/老年时只写层次、禁套 23；年龄态衍生写该态，其余继承）。**不适用 23 岁默认**：群演簇、宠物、神兽/异兽/魔兽/妖兽/灵兽/坐骑/非人集群及上列非人豁免主体——无明文龄态则省略 `age_tier`/`约N岁`，禁硬填
- **身份 `identity:`（具名人态 CHAR 强制；最高；供 Stage 3 `role`/服制）**：社会/职业/品秩/修为等**世界内身份**——与 `plot_role`（番位）**分字段并存、绝不可互代**。
  - **写什么**：可核销的身份标签短语（项目语言），优先具体可视觉化：`警察`｜`刑侦警探`｜`皇子`｜`公主`｜`王爷`｜`普通修仙者`｜`内门弟子`｜`店员`｜`医师`｜`卫兵统领` 等。层级可叠写短串（如`皇子·三皇子`｜`普通修仙者·散修`），禁空泛「重要人物/有权势者/高手」代替可识别身份。
  - **≠番位**：`plot_role:男主` **不能**顶替 `identity:`；❌只写男主漏警察｜❌`identity:女主`｜✅`plot_role:女主` + `identity:公主`。
  - **证据源（按序扫；有则必入库）**：①【角色命名】地位/身份/称谓列；②【角色设定】/服化道可核销职衔；③对白称呼与自称（「殿下」「警官」「师兄」等可落具体身份时）；④制式着装/徽章/冠服明文；⑤项目台账全局角色身份。摘抄上游原词，禁同义改写成更虚的概括。
  - **粒度**：上游已写细职衔→用细的（`刑侦警探`优于笼统`警察`；`三皇子`优于仅`皇子`若原文有）；仅有大类→写大类（`警察`/`公主`/`普通修仙者`），**禁**无据升格细职或降格抹掉。仙侠/玄幻：明文境界/门派位阶（散修/外门/内门/长老等）并入 `identity:` 或紧随其后短注，禁只留「修仙者」若上游区分了普通/精英。
  - **谁必填**：具名人态基础版与换装/战损等衍生（衍生**继承**基础版身份，除非本条「身份体系变化」）；龙套有可核销身份亦必写。
  - **谁可省略**：群演簇（写服饰倾向/制式即可）；宠物/神兽/非人豁免主体无社会身份时；纯瞬时无名氛围体。人态具名却全输入无任何身份证据→标 `upstream_missing_identity:需要回流 Stage 1/命名表补身份`，**禁**臆造警察/皇子等。
  - **身份体系变化**：跨 Scene 可持续的新身份（登基/废黜/从警→卧底平民/散修→宗门弟子等）→新建衍生行（`derivative_kind:身份态`）并写**新** `identity:` + §六六个强制键；禁只改基础版一行糊弄。
  - ❌ 只落三键无 `identity:`｜用番位冒充身份｜把「普通修仙者」压成「男主」｜有「公主」称呼却不写｜✅ `identity:公主` 与 `plot_role` 并存且可检索。
- **性格/定位/风格（有则必写）**：摘抄入 `personality:`/`style:`/`signature_action:` 等（身份**只**走 `identity:`，地位/阶层走 `social_status:`，原文外形评价走 `appearance_cues:`，禁塞进性格句冒充已写）；优先【角色设定】+命名表+Beat/对白外形词；禁只留三键丢原文词；禁块未写却补。**外形四维 + 软性外形决定因素见「一」全量总结**；`basic_positioning` 与 `plot_role`/`identity`/`social_status`/`style`/`appearance_cues` **并存不互代**。
- **CHAR 重评估（新 Scene）**：禁因同名跳过重检。触发（其一且可持续→衍生或独立）：①时间跨度大；②身份体系变化（须更新 `identity:` 或拆身份态衍生）；③性情表现体系变化（非瞬时情绪）；④任务/职能实质差异；⑤摘要/明文换装或跨 Scene 可区分装束。先判新增再复用；**换装命中时禁止复用旧行冒充新装**。
- **衍生门禁（默认）**：`重大变化 + 持续变化`；缺一不可。重大=稳定换装体系/年龄态/长期遮面/可持续宿主特效/非紧密转场/重检差异等；持续=跨多 Beat/Scene 或可继承。未过门禁→只写基础版属性或留 Beat。**例外**：剧情明文换装（下条）豁免「持续」时长门槛，且**优先级高于**「衍生最小化」。
- **剧情明文换装 → 强制新建角色行（最高硬约束；覆盖门禁持续项与衍生最小化）**：
  - **效力**：命中即**必须**输出 ≥2 条独立 `character`（基础版 + `{角色}_{装束标识}` 衍生）；每行各自完整 `clothing:`；**禁止**单行混写两套服装；**禁止**只改属性不增行；缺衍生行=本阶段失败须重写。
  - **触发（任一即强制拆行；不要求更衣过程入画）**：
    1. 服化道「服饰/换装」非「无」，且含换装/更衣/改换装束/第二套及以上可区分着装描述；
    1-b. 【场景衔接】/【场景切换与首节拍转场】出现 `服饰换装`/`服饰/换装`/`换装` 等标签或「从{旧装}换为{新装}」句式（即使未写三项标准摘要）；
    2. Beat/【角色设定】/「服装要求」出现换装、更衣、换上…、卸甲换便衣、改穿、盛装/便装切换、制服↔便服/员工便服↔裙子礼服等过程或结果词；
    3. 同一具名角色在输入内出现**两套及以上可区分服饰体系**（如先前机能外套/员工便服 vs 后礼服/绝美裙子/战袍/病号服/泳装/盔甲），即使只见新装现态、未见更衣动作；
    4. 新 Scene 入场着装与该角色已落表基础版/`clothing:` **可核销不同**（摘要或 Beat 明文），且差异属装束体系而非撩袖级微调。
  - **命名/链**：衍生=`{基准}_{装束标识}`（如 `_礼服版`/`_便装版`/`_制服版`/`_裙子版`/`_盛装版`）；`base_entity`→上一稳定版 `subject_name_zh`；`dependency_reference`→其 `subject_name_en`；`plot_role`/`gender`/`age_tier`/`identity` 继承（身份未变时逐字复述；身份变走身份态衍生）；新装行 `clothing:` 只写该态，禁夹带旧装。
  - **衍生属性（强制，见「六」）**：换装衍生行须写全 §六六个强制键；其中 `derivative_kind:换装`，`return_or_continue` 默认 `continue`（上游明文换回旧装则 `return`）。缺键=失败。
  - **扫描序（强制）**：①本环节服化道核销 + 全场【场景衔接】/【场景切换与首节拍转场】「服饰/换装」（含自由写法）逐 Scene → ②【角色设定】外形/服装 → ③逐 Beat 建置+入戏服装词 → ④跨 Scene 同名角色着装对照表（内部）→ 命中则先建齐多行再写属性（§六六个强制键；`activation_beat` 可选）。
  - **边界（不建行）**：撩袖/解扣/披外套未换体系、瞬时湿衣未成新装束（可走 `clothing_env`）、纯情绪「看起来不一样」、摘要「无」且全输入无第二套可区分证据。
  - **终检失败项**：有换装证据却同名仅 1 行｜两套 `clothing` 挤一行｜新装并入基础版｜因「未见更衣过程/只出现一次」拒拆｜衍生行缺 §六六个强制键。
- **服饰/妆发/外形（有则必写）**：摘抄入 `clothing:`/`appearance:`；剧本/Beat/对白里凡与该角色外形相关的风格、地位、作用、**身份视觉信号**、**原文评价词（漂亮/性感/高贵/绝美等）**须一并按「一」四维+`appearance_cues` 入库。无则静默省略，禁写「未明示服饰」等元话术。不覆盖 `clothing_req` / 换装多行。**凡可作为角色描述一部分的配饰/随身件**（耳环/胸针/发簪/领带夹/造型挂件等；含仅一次性露出、无可持续关键状态变化者）→只写入 `clothing:`/`appearance:`，**不**另提 PROP（见下「角色配饰↔PROP」+「道具提取极严原则」）。
- **角色配饰↔PROP（强制；与「三」联读；服从极严原则）**：角色设定/服化道/Beat 明文写出佩戴、挂戴、随身的配饰或随身件时：
  1. **默认可归 CHAR（极严）**：可作为角色外形/服饰一部分、无可持续关键状态变化、或仅一次性交互/一次性出画 → **不提取**独立 `prop`；只留在该 CHAR 的 `clothing:`/`appearance:`（若上游写了挂载部位，**仍须**摘入短注，如`左耳垂小银环`）。**禁止**因拿起/把玩一次/递交出画升格。
  2. **符合道具提取规则才升格**（见「三」：**全局性道具明文** → 强制提；或常规极严：**不可归 CHAR**，且有**可持续关键状态变化**或跨场复用资产价值，且过四维门槛）→ **必须**另建 `prop` 行，并写挂载字段 + **`detachable:`**（下条）。
  3. **离身性判定（最高；角色依赖闸门）**：凡升格为角色随身 PROP 的件，PROP `entity_attributes` **必须**写 `detachable:否|是`。Stage 1 若写揣入怀中、塞入衣襟、放入口袋/包袋/袖中/腰封等而使物件本体不可见，须按**出画**核销；从上述位置取出并重新可见，须按**入画**核销——本阶段据此摘抄收纳位置与宿主，禁把收纳误读为物件毁弃、无故消失或换宿主：
     | 值 | 含义 | 角色侧 |
     | :--- | :--- | :--- |
     | `detachable:否` | **不可离身**——定妆/外形常挂身体（颈饰/耳饰/指环/常佩徽章等），无明文摘下/放下/移交则始终在身 | 宿主 CHAR **必须**写 `accessory_props`+`accessory_mount`；`clothing:`/`appearance:` 含挂位短注；供 Stage 3 挂 `visual_dependencies` **并**写入角色生图词 |
     | `detachable:是` | **可离身**——可掏出/持握/放下/递交/收纳离身（打火机/手机/剑/可卸挎包等） | PROP 可写 `host_character`/`wear_side`/`mount_body_part` 供戏份守恒；宿主 CHAR **禁止**写入 `accessory_props`/`accessory_mount`；Stage 3 **不**挂角色依赖、**不**进角色定妆生图词 |
     判定优先上游明文；默认可放下/手持交互 → `是`；仅永久佩戴、剧情当身体一部分 → `否`。缺键=失败。
  4. **挂载部位继承与属性对齐（最高；仅已升格 PROP）**：Stage 1 已写（或可核销）的挂载/持握信息**必须**入库；有宿主则 PROP 写 `host_character`/`wear_side`/`mount_body_part`。**仅 `detachable:否`** 时 CHAR↔PROP 双向挂链（`accessory_props`/`accessory_mount`）并对齐——禁只挂名不挂部位。上游跨拍无离身链却某 Beat 漏写随身件=Stage 1 缺口（`upstream_missing_carried_prop_continuity`），本阶段不臆补消失。写入 `purpose`/`form`/`appearance` 前过**物件可视性核验**。
     | 字段 | 写在 | 口径 |
     | :--- | :--- | :--- |
     | `host_character:{CHAR名}` | PROP | 宿主 `subject_name_zh`；衍生 PROP 继承 |
     | `wear_side:正面\|背面\|左侧面\|右侧面` | PROP | **相对宿主身体**（非机位）；闭集；摘抄 Stage 1 |
     | `mount_body_part:{具体部位}` | PROP | 颈前/胸前/后腰/左腕等具名锚；禁「身上」 |
     | `detachable:否\|是` | PROP | **强制**；见上表 |
     | `accessory_props:{道具名}\|…` | 宿主 CHAR | **仅不可离身**；名与 PROP 逐字一致 |
     | `accessory_mount:{道具名}@{wear_side}/{mount_body_part}\|…` | 宿主 CHAR | **仅不可离身**；与 PROP `wear_side`+`mount_body_part` 逐字一致；多件`|`分隔；换装衍生若仍佩戴则同写 |
     另：**不可离身**时 CHAR `clothing:`/`appearance:` 须含等价短注（如`胸前佩戴玉牌`），与 `accessory_mount` 不矛盾。上游缺挂载体侧或部位 → 标 `upstream_missing_accessory_mount:…`，**禁臆造**。
  5. **禁双写糊弄**：已提为 PROP 的戏份不得只埋服装句而不落 PROP 行；未达极严门槛禁硬提 PROP；禁 CHAR/PROP 挂载部位互斥；禁把可离身件写入 `accessory_props`「凑依赖」。
  6. ❌ 银打火机跨拍把玩+**可持续点燃态**却只写进服装｜✅ 提 PROP + `detachable:是` + 挂载字段（**不**写 CHAR `accessory_props`）。❌ 常佩传家玉牌（不可离身）升格却不写 `accessory_props`｜✅ `detachable:否` + CHAR `accessory_props`+`accessory_mount`。❌ 仅为造型的耳钉/无状态玉牌另提 PROP｜✅ 耳钉/无状态配饰只进 `clothing:`/`appearance:`；一次性出画物件留 Beat。
- **`clothing_req:`（服饰例外）**：依赖服装结构的动作（藏袖/掏袋/塞怀/掖腰/卷入下摆等）→ 必须写可核销形制硬约束（如须有可纳物袖管/可用口袋/可开合衣襟/腰带/足够下摆），即使原文未展开时装。禁臆造完整版型配色。
- **`clothing_env:`（服饰例外）**：游泳/暴雨/灾难/泥沙等显著改变衣态 → 写场合+可见落点（湿贴/沾灰/焦边等，可播出、禁血腥）。可持续重大差异→可建衍生（如 `_游泳态`）；禁写入 ENV 空镜。
- 时序断点（闪回/多年后/重生等）须重判 CHAR，并同步 ENV/PROP 时序；闪回首次 PROP 仍过极严原则+四维（禁因闪回一次露出硬提）。重生/转世默认新角色（明文可直接继承除外）；多人逐个判定。时序新建：`dependency_reference`→上一稳定版英文名，`base_entity`→上一 `subject_name_zh`。
- 表情态/微表情/瞬时姿态/tone（环节 4–5）不得实体化。证据不足默认不新增；衍生最小化。
- **群体词**：已分别具名且独立互动→分提 CHAR；上游写「众人/卫兵们」但其中有人有具体剧情动作→有动作者按龙套单提，其余无个体动作者才可留一条群演簇；禁把具名夫妻或有动作龙套误并簇。
- **仅声音无可见实体（与「纯画外音禁 CHAR」同锁）**：禁新建 CHAR/PROP/ENV；仅明文要求声源设备入镜时可建 PROP/ENV，仍禁凭声音补 CHAR。具名画外音角色无形象 → 不提资产。

### 三、道具（PROP）

归属裁决服从「规则强约束」**道具提取极严原则** + XOR（此处不重述步骤）。本节只补 PROP 专属门槛与字段。**默认不提；宁少勿滥。**

- **极严门禁（与规则强约束同文）**：非全局性道具时——可归 ENV｜可归 CHAR｜无状态变化｜仅一次性出画/一次性交互 → **一律不提**。视频模型按 Beat 处理一次性动作即可。仅当物件须作为**独立可复用资产**且有**可持续关键状态**（或跨场复用）时才建行。
- **全局性道具强制提取（最高；覆盖极严四禁与四维）**：剧本明文全局/贯穿级道具 → **必须**提 `prop`（证据口径见「规则强约束·全局性道具」）；`purpose:` 点明全局定位；建议 `prop_scope:全局`；有宿主则挂链字段齐全；漏提=本阶段失败。禁因本场戏份少/无状态/可塞进服装或环境而省略。
- **四维门槛**：非全局物件在已过极严门禁后，再核频次、剧情驱动、镜头权重、情感价值；门槛=剧情驱动或情感价值至少一项高且综合「明确焦点」。每 PROP 一句可解释理由（全局：写「上游明文全局性道具」；常规：须含**为何不可归 ENV/CHAR** + **何种可持续状态/跨场复用**）。**禁止**仅用「拿起/递交/使用一次」作理由（全局明文除外）。
- **角色配饰升格（强制；与「二」联读）**：明确归属某**具名**角色的配饰/随身件——**全局性道具明文 → 强制提**；否则**仅当**不可归 CHAR 造型描述，且有可持续关键状态变化（典型：跨拍把玩+点燃/开合/损毁残片需独立视觉资产），并过四维 → 才提 `prop`。提则必写 `host_character:` + **`wear_side:`** + **`mount_body_part:`** + **`detachable:否|是`**；**仅 `detachable:否`** 时宿主 CHAR 写 `accessory_props:` + **`accessory_mount:`**。非全局且可归 CHAR / 无状态 / 一次性出画 → 不提。上游无部位→`upstream_missing_accessory_mount`，禁臆造。**宿主为群演簇 → 不升格**：只写进该簇 `clothing:`，禁 `prop` 行、禁 `accessory_*`。
- **一次消耗品禁 PROP**：用后即弃、无跨 Beat 可复用形态、无独立叙事焦点（纸巾/零食碎屑/一次性杯/烟蒂等）。**一次性出画物件同禁**（即使具名信封/钥匙递交后离场，只要无可持续关键态与跨场复用、且非全局明文）。例外：①罪证/具名信物且跨 Beat·Scene 持续在场并有关键状态变化；②**全局性道具明文**。默认留 Beat；Stage 1 已作 ENV 氛围→留 ENV。
- **状态（升格核心；全局除外）**：非全局时，可持续关键态是提 PROP 的**通常必要**条件；纯瞬时/单次交互不升格。耗时渐变（书写/绘画/灌注/显影）→ 过程前基础版 + 过程后衍生（如 `纸_已书写`）；瞬间开关/点燃——仅当点燃后态跨拍可见且需独立资产时才提，并**若已拆衍生行则必须写全「六」键**。无状态变化 → 即使多次入画，若可归 ENV/CHAR 且非全局仍不提；**全局性道具无状态亦须提基础版**。
- **必填/有则必写**：**`basic_positioning:`（强制，见「一」）**；`purpose:`（作用：何时/何功能/落点槽位，禁空泛；**禁把角色名写进 purpose 正文**——配饰宿主只进机读键 `host_character:` + 挂载部位）；**`relative_scale:`（强制，见下）**；外形/材质/风格/地位/原文评价有证据则按「一」四维+`appearance_cues` 写入 `appearance:`/`form:`/`material:`/`style:`/`social_status:`（传家/御赐/日用等），禁只留功能丢外形、禁丢掉「精致/华贵」。角色配饰升格行另须 `host_character:` + `wear_side:` + `mount_body_part:` + `detachable:`（见上）。无戏份活物→PROP（与有戏份宠物 CHAR 互斥）。须对照建置核销该道具后续交互所需操作净空/朝向面（签署面、翻面、桌面旁一臂区），写入 `purpose` 或 `placement:` 等无人称语。
- **相对尺度 `relative_scale:`（强制；供 Stage 3 确认与生图）**：每条 PROP（含衍生）`entity_attributes` **必须**可检索 `relative_scale:`；缺则本阶段失败。用相对真人常见参照写清体量，便于清单审阅与下游转译——参照优先：成人手掌/掌宽、拳头、手指节、人头/脸宽、前臂；若常与某类共现实体同框（手机↔证件、杯↔桌、枪↔双手等）再补 1 条相对比例。写法例：`约一掌长·掌心可握`｜`约拳头大小`｜`约人头直径`｜`较标准证件卡略厚`。禁只写「小/大/适中」无参照。
  - **有上游尺寸/尺度证据**（服化道道具细节、外形句、Beat 持握/对比描写等）→ **严格摘抄并补足人体参照短语**（禁丢原文尺度词）。
  - **无明文尺寸**→据 `purpose`/形制/持握方式推断可信相对尺度（手持物默认对标掌/拳；桌面文具对标掌宽/指节；可穿戴对标腕/颈/头等）；禁臆造精确厘米数；推断值须与用途不自相矛盾。
  - **衍生行**：体量与基准相同→可复述同句或写 `relative_scale:同基准`；`variant_delta` 改变体量/展开态（翻开的本、展开的伞等）→须写本行新尺度。
  - `script_entity_coverage` 须覆盖尺度关键词（掌/拳/指/头/前臂或上游原尺度词）。
- **PROP 衍生属性（强制，见「六」）**：凡 `base_entity≠None` 的道具衍生（状态/面/形态）须写 `derivative_kind:`（多为`道具状态`/`设备面`）+ `derivative_trigger` + `activation_evidence` + `variant_delta` + `return_or_continue`；供 Stage 2.2 在点燃/签署/翻面等情节换 `PROP:[…]` 版本名。
- **设备/亮屏/朝向**：正反面或设备态拆 `{基准}_{状态/面}`。上游写到手机/平板等发声屏设备时，须能摘抄**现位**（手上/桌上/已收纳）与**正面朝向**；缺位向→`upstream_missing_prop_orientation:…`（兼标缺位置）。仅明文直播可补支架。亮屏须 `visible_text` 或界面摘要；仅「亮屏」无内容→`upstream_missing_screen_content:…`。响铃/外放证据入库时保留声源现位，禁把桌上响写成手上持握默认态。
- **可见文字**：`visible_text`/`form_field_text`/`text_carrier`/`text_layout`/`typography_requirement`/`script_variant`/`marked_text_requirement`/`readability_requirement`。明示逐字透传（**保持原繁简字形，禁擅自繁简互转**）；动作隐含字段须反推；无精确字样→标「原文未明示…必须存在[字段]」或走补字例外。凡可读中文载体（书/纸/牌匾/招牌灯级 PROP 或 ENV 陈设）须可检索：`visible_text`（逐字）+ `text_layout:`∈`横排|纵排` + `typography_requirement`（字体/书体+工艺+**字色+底色**；招牌灯/霓虹/灯箱另写**发光色**）+ `script_variant:`∈`简体|繁体`（有核销混排可写说明）。**文字载体补字**见「规则强约束」唯一例外。

### 四、环境块（只读核销；禁止落 `environment` 行）

环境规划已锁定主环境名、三属性、四向/固定清单与【未落清单】；场景分析与现场编排补场核/衍生名。**本环节不入库、不重编码**。只做：

- **XOR 对照**：固定建筑/装修/大件家具/基础陈设 → 留环境（不提 PROP）；过极严或明文全局 → PROP，并从环境叙述中剥离。
- **挂场**：CHAR/PROP `scene_mood_cue` 的 `挂场ENV` 与 IDENT 主环境名逐字一致；主情绪抄 IDENT `情绪表达`。
- **回流**：缺 `SCENE_ENV_IDENT`、缺【主环境】、家具堵死活动区 → 回流环境规划。禁止本环节补造空间或写入 Index。
- **载具双用途**：舱内/甲板占用 ENV 已声明且本集整车入他环境时，整车仍按「规则强约束」提 PROP，挂场须指向宿主大环境（仅无人全景）；占用空间由环境资产设计承接。本环节不把舱内/甲板写成 Index ENV 行，也不因已有占用 ENV 漏整车 PROP 或把整车挂到自身甲板/舱内，也不把宿主大环境写成有人占用场的挂场。

### 五、衍生实体命名规范（强制）

- **统一**：`base_entity`=基准 `subject_name_zh`（基准=`None`）；`dependency_reference`→基准 `subject_name_en`。
- **依赖链时序（单权威）**：CHAR/PROP 单向时序链；禁跳链回挂远端基础版（族系首个衍生除外）。连续态→族系上一稳定版。环境衍生名与依赖链由环境规划 + 现场编排 + 环境资产设计承接，**本环节不写**。
- **CHAR / PROP / cover_poster**：CHAR 衍生=`{基准}_{标识}`；PROP 衍生=`{基准}_{状态/面/形态}`；海报依赖填核心实体中/英名（多依赖取主视觉锚点）。

### 六、CHAR/PROP 衍生版本属性说明（最高；供 Stage 2.2 继承切换）

凡 `character`/`prop` 且 `base_entity≠None`（衍生行），`entity_attributes` 必须含六个强制键：`applicable_scenes`、`derivative_kind`、`derivative_trigger`、`activation_evidence`、`variant_delta`、`return_or_continue`；`activation_beat` 可选。基础版（`base_entity=None`）若同族已有衍生，可写 `has_derivatives:Yes`。

| 键 | 闭集/写法 | 用途 |
| :--- | :--- | :--- |
| `applicable_scenes:` | **必填场景号**；一个或多个 `EPxx_SCyy`（多场用`\|`分隔，如 `EP01_SC02\|EP01_SC03`）；须与上游 `[SCENE_START:…]` **逐字一致** | **往下传递的场次闸**；Stage 2.2 先按本场 `Scene ID` 过滤，再匹配换版 |
| `activation_beat:` | 可选；本衍生在适用场内首次生效拍号（整数，如 `3`）；入场即该态→`1`；跨多场延续且本场开场已是该态→`1` | 同场内「自第几拍起用本版」；缺则仅靠证据串匹配 |
| `derivative_kind:` | `换装\|战损\|年龄态\|身份态\|特效宿主\|道具状态\|设备面\|时序断点\|其他` | 衍生类别；Stage 2.2 先按类过滤 |
| `derivative_trigger:` | 一句摘抄上游触发（换装/点燃/签署/战损现场等） | 说明「为何拆行」 |
| `activation_evidence:` | 适用情节关键词（可含「本场入场即…」） | Stage 2.2 **匹配何时换版**的证据串（在 `applicable_scenes` 内） |
| `variant_delta:` | 相对基础版/上一稳定版的**可见差异**（服装/外观/状态，禁空泛「不一样」） | 与 Beat 明文外观词对照核销 |
| `return_or_continue:` | `continue`＝确立后跨拍（及所列后续适用场）沿用直至明文恢复/另换版；`return`＝一次性或已写明恢复基础版 | 控制跨 Beat/跨所列场是否保持该衍生名 |

- **场景号纪律（最高）**：
  1. `applicable_scenes` **只写**本衍生版实际应使用的场次 ID；禁写未出现该态的场；禁用 Scene No. 整数代替（必须 `EPxx_SCyy`）。
  2. 换装/状态仅发生在某场后半 → 仍写该场 ID，并用 `activation_beat` 标首次生效拍；前序拍不在本行生效范围（Stage 2.2 用拍号+证据区分）。
  3. `continue` 且后续场仍着该态/持该态 → **把后续场 ID 一并列入** `applicable_scenes`（否则下游无法跨场继承）。
  4. 同族多衍生行场次可重叠仅当拍号/证据不冲突；禁两行对同一 `(Scene ID, Beat)` 争抢且证据无法区分。
- **书写纪律**：键值只写可核销事实与关键词；`activation_evidence`/`variant_delta` 须能与服化道摘要或 Beat 建置/入戏原文对得上；禁臆造未写情节。
- **换装例**：`applicable_scenes:EP01_SC02\|EP01_SC03；activation_beat:3；derivative_kind:换装；derivative_trigger:服化道服饰/换装：从员工便服换为绝美裙子；activation_evidence:更衣｜换上裙子｜礼服/晚宴裙现态；variant_delta:员工便服→绝美裙子/礼服廓形；return_or_continue:continue`
- **道具状态例**：`applicable_scenes:EP01_SC01；activation_beat:4；derivative_kind:道具状态；derivative_trigger:Beat4 点燃打火机；activation_evidence:点燃｜火光｜火轮按压后火焰；variant_delta:闭合机身→可持续点燃火焰可见；return_or_continue:continue`
- **基础版污染禁令不变**：剧情终态差异只进衍生行上表字段 + 该行 `clothing:`/`clothing_env:`/`appearance:` 等，**禁**回填基础版。
- **Stage 2.2 消费契约**：场景编排只注入**资产名 + `form_continuity`**（不读整份 `entity_attributes`）。先按本列「哪场/何时」选衍生名；六键作核销。漏写本列或场景号=`下游无法按场换版`=失败。

## 服化道连续性（单独列 `form_continuity`；CHAR/PROP 强制）

本列是给**场景编排**的可读换版说明书，与 `subject_name_zh` **成对注入**。禁把本列内容再塞进 `entity_attributes` 顶替本列；六键仍写衍生行属性，不顶替本列。

| 行类 | 写法 |
| :--- | :--- |
| ENV / `cover_poster` | `无` |
| CHAR/PROP 全片无形态变化 | `无` |
| CHAR/PROP 基础版（同族有衍生） | `初态至{EPxx_SCyy} Beat{n}；变化见{衍生中文名}@{EPxx_SCyy} Beat{n}` |
| CHAR/PROP 衍生行 | `{EPxx_SCyy} Beat{n}起：{旧态→新态}；延续至{EPxx_SCyy}`（入场即该态写 `Beat1起` 或 `入场即`；仅本场写 `延续至本场`） |

- **必须写清**：哪一场（`EPxx_SCyy`，与 `[SCENE_START]` 逐字一致）+ 什么时候（`Beat{n}` / `入场即` / `场末`）+ 变了什么（旧→新，可核销）。
- 同族多变：基础版只写「初态止点 + 指向第一衍生」；每一衍生行各写**本行首次生效**的场/拍与 delta。后续场仍持该态 → 写进 `延续至`。
- 单元格禁 ASCII `|`（用 `；` / 全角 `｜`）。禁空、禁只写「换装/有变化」、禁把终态回填基础版当「无」。
- ❌ 换装已拆行但本列全 `无`｜只写 `EP01_SC02` 无拍号或无旧→新｜✅ `EP01_SC02 Beat3起：员工便服→礼服；延续至EP01_SC03`

## 最终输出格式
