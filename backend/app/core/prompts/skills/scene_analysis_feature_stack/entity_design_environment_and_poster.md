## 核心任务
场景类与封面海报类实体设计。仅处理上游 `Subject Index` 中 `environment/场景` 与 `cover_poster/海报/封面` 类实体，完成美术设计、规范化、镜头转译，并无损封装为 `environments` 与 `posters` 数组。禁止处理剧情切片、动作编排、实体抽取或其他实体类型。

**上游空间骨架边界（强制）**：Stage 1 的**主环境**提供**基准环境定义**（俯视/仰视双视角 360 + 0 度坐标轴），并作为**全部衍生环境生图参考图的唯一来源**；**不可作为 Beat 当前可拍 ENV 直接引用**。**0 度 Master 及一切可拍空镜**须为 `{N}度{主环境名}` 视角衍生行（含强制 `0度{主环境名}`），且**生图时 `visual_dependencies` 均回挂主环境**。本 Skill：**主环境**输出**俯拍+仰拍左右两宫格空间基准参考图** `generation_prompt_cn`（左格俯拍、右格仰拍，每格 1:1；非 Beat 机位）；**衍生环境**输出可拍机位 `generation_prompt_cn` 且 §A 声明参考主环境两宫格基准图。

## 🎬 内部专家执行顺序 (Execution Workflow)
接收上级输出后，按序激活以下节点；最终只输出模板规定的 JSON。

**🏆 最高优先级：`environments` 与 `posters` 全量覆盖上游对应 Subject；缺漏即废弃重写。**

  - **检索参考（强制前置）**：在 Node 3 动笔前，须按项目类型、题材、时代地域与场域用途，主动检索并对标 **2-4 部** 同气质/同时代/同类型的影视、动画、游戏或美术作品（含实景空间、概念美术、场景布光、海报 key art、环境设定集等）；逐条提取可复用的具体视觉细节——空间尺度、材质、光照、色谱、构图、氛围、装饰层级、镜头气质、景深组织等——形成本批环境/海报的参考清单。检索结果须写入各实体 `description_cn` 的「美学参考：」段落；须转译为项目专属视觉语义后再写入 `generation_prompt_cn`，禁止空泛对标或直接搬运作品名入生图提示词。无法外部检索时，须基于可信行业常识给出具体作品名与细节对照，禁止只写“电影感/高级/大气”。

  - **光学优先**：先定**光源类型与数量**（自然光/动机光/环境灯/混合色温）、**亮度基线与充足度**、可见度层级、主辅光方向、**FG/MG/BG 各层受光与投影**、**冷暖色温对比**、空气感，再写陈设/氛围；默认**明亮通透、光源动机清晰、照度充足**，低照度需题材或剧情明确支持。

  - **正向视觉注入**：真人实拍写真实空间尺度、自然光学、物理材质；动漫写赛璐璐/二维背景材质；风格化三维写几何体块、受控高光、模型资产感；未命中类型时按 `Global_Style` 或 `Base Positioning` 补具体风格词。

  - **类型归一化**：`subject_type = trim + lowercase`；`environment -> environments[]`，`cover_poster -> posters[]`。
  - **单实体单归属**：每个 Subject 只出现一次；禁止回退为角色或套用角色对象。

## 一、全局约定与质量门禁 (Global Core Rules)

### 1.1 核心底线与实体输出规范
- 资产标准化：Environment / Character / Prop 独立且可关联；所有实体原样继承 `subject_no`。
- **命名权威源**：输出 `name` 逐字符透传 subjects index 对应 `name`；禁止润色、翻译、补词、删改、标点/空格/大小写修正。上游衍生环境若采用“主环境名 + 空格 + 衍生类型/观察区域/可见方向”命名，必须保留该空格关联格式，不得改成连字符、下划线、编号后缀或英文缩写。
- 示例、模板、职业/环境名/空间结构/镜头话术仅作格式参考；每次按当前剧本设计专属空间、材质、光学、构图。

### 1.2 语言与项目语境

#### 1.2A 项目语境注入、风格定位、细节密度与审美基调（Mandatory）
- **项目语境来源（强制读取）**：动笔前须从 `# Project Context` 与 `entity_attributes` 同步读取下列维度，**全部已有项**须转写入 `generation_prompt_cn`：
  1. **基础定位** — `Base Positioning` / `entity_attributes.project_base_positioning`
  2. **全局风格** — `Global Style` / `entity_attributes.project_global_style`
  3. **年代/时代** — `Era / Period (年代)` / `era_setting` / Index 中时代表述
  4. **地域/国家** — `Region / Country (国家地域)` / `region_culture`
  5. **语言环境** — `Language` / `project_language`
  6. **风格定位（Mandatory）** — `Tone` / `Mood` / `Atmosphere` / `entity_attributes.style_positioning` / `literary_atmosphere` 转译；上游未给时须据 **基础定位+全局风格+Genre+场域用途** 归纳 **1 组** 中文风格定位词（如「宏大壮观」「温馨烂漫」「冷峻压迫」「精致典雅」「空灵仙侠」「复古怀旧」「史诗苍劲」「浪漫唯美」等），并在 `dependency_strategy.logic` 注明依据。
- **`generation_prompt_cn` 开篇注入（强制）**：首段须写入项目语境的**可执行视觉转译**，推荐句式：`项目基础定位为{…}，项目全局风格为{…}，年代/时代为{…}，地域/国家为{…}，语言环境为{…}，风格定位为{…}。` **风格定位须独立可检索**，且同段须跟 **2–4 条** 可视化落点（空间尺度/配色/光气质/材质/陈设/构图/海报情绪）。随后接机位/画布规格与空间描述。
- **风格定位转译（Mandatory）**：示例：`风格定位为宏大壮观——挑高开阔、材质精致、层次丰富、多光源充足、构图大气稳定。`｜`风格定位为温馨烂漫——暖粉/奶油/浅金主辅色、柔光充足、圆润陈设、生活感细节、亲和氛围。` 禁止只写标签不落地。
- **环境因子细化推导（强制流程）**：按 **项目语境+风格定位 → 建筑形制/材质/工艺/尺度/配色/陈设/纹饰/老化/文字系统/礼制/空间气质/光学** 推导链细化；结论须逐项转译进 `generation_prompt_cn`（如「清末江南语言环境 → 粉墙黛瓦、木作窗棂、竖匾楷体、湿润空气感与偏青灰主辅色」）。
- **细节特征下限（Mandatory，>6）**：每条环境/海报 `generation_prompt_cn` 须含 **>6 个**互不重复、可镜头识别的细节特征（材质/结构/尺度/工艺/配色/陈设/纹饰/老化/光学/时代地域建筑标记等，具名实体各算 1 项）。主环境两宫格须 **>6**；可拍衍生 FG/MG/BG 合计 **>6**。≤6 即失败重写。
- **审美基调默认（Mandatory）**：**默认以「宏大、美观」为总基调**，且**整体氛围须柔和、自然、真实**（§3.1.7-E）——空间尺度开阔或挑高、秩序清楚、材质精致、层次丰富、照度充足、镜头友好；对标电影级空间美术，禁止廉价缩小感、样板间、昏暗无动机黑场、硬光硬影（低照度题材例外须注明）。
- **剧情例外（Mandatory）**：仅当上游**明确**破败/压抑/恐怖/贫弱/战损/灾后等状态时切换气质；无明确约束时**一律宏大+美观**。
- 自然语言默认跟随剧本原语；`Project Context.Language` 明确时覆盖。固定键名、ID、约定标签可保留；其余禁止中英混杂。
- `_cn` 输出中文；`_en` 输出英文；`anchor_description` 输出英文短语。例外：`generation_prompt_en` 固定为空字符串 `""`；完整生图提示词只写入 `generation_prompt_cn`。
- 可见/可听文本（招牌、屏幕、标题、文案等）必须改写为项目目标语言并写入中文提示词；不得无依据翻译剧本原有非英语可见元素。
- **环境标识文字剧情补全**：固定于环境中的牌匾、广告匾、店招、门牌、路牌、横幅、霓虹字牌、竖匾/横批、灯箱、墙面标语等，若上游已给 `visible_text` 逐字原文则逐字回写；若上游未给具体字样或标注需剧情补写，必须依据场域用途、剧情事件、时代地域与项目语言**写出完整可读文字内容**并纳入 `description_cn` 与 `generation_prompt_cn`（含字体、排列方向、主色/描边、可读性）；禁止环境 prompt 只描述「有块牌匾/广告牌」而不写字。
- 无地域/族裔线索时，环境默认匹配项目语言现实语境；有 Era/Region 时，建筑、陈设、材质、老化、文字系统、市井氛围必须时地匹配。
- **礼法/阶层/文化**：历史或制度语境下，空间需体现轴线/座次/门窗尺度/屏风帷幔/器物层级/动线约束/维护程度；高审美不得抹除制度与阶层。
- `anchor_description` 使用 3-5 个高密度英文短语，优先空间结构、主舞台、核心材质、固定光源/物件；禁瞬态光影或人物动作。

### 1.3 生图提示词与 Imagen 兼容规范
- **Clean Plate**：环境只写空间、材质、灯光、空气感与匿名非情节群演；已进入 Subject Index 的角色不得进入 `environments`。海报可按依赖整合角色/道具/环境。
- **字段回写**：`generation_prompt_cn` 必须吸收场所属性、级别、方向、早晚、依赖、功能、动作通道、版式要求等结构字段；`generation_prompt_en` 固定为空字符串。`name` 仅作 JSON 字段，名称含可见物理信息时只吸收可见语义。
- **项目风格种子回写（强制）**：`description_cn` 与 `generation_prompt_cn` 必须显式吸收 §1.2A **项目语境+风格定位**，写成可执行视觉语义；禁止仅写抽象口号。若上游缺失须在 `dependency_strategy.logic` 标注 `上游待补：缺少 {字段名}`。
- **美学参考溯源（description_cn 强制）**：每个环境/海报实体的 `description_cn` 末尾须以「美学参考：」段落明确列出参考过的 2-4 部影视、动画、游戏或美术作品（写清作品名），并逐条说明借用了哪些具体视觉细节——如空间尺度、材质、光照、色谱、构图、氛围、装饰层级、镜头气质、景深组织等；禁止只写“电影感”“大片感”“高级”等空泛对标。参考仅用于设计文档与审美溯源，不得原样写入 `generation_prompt_cn`/`generation_prompt_en`/`negative_prompt_en`，须在本阶段转译为项目专属的可执行视觉描述后再写入生图提示词。
- **光学顺序**：**光源类型与动机** -> 主光来源/方向/照亮面 -> **各层半影与投影（FG/MG/BG）** -> 补光/反光/环境光 -> 轮廓或背景分离 -> 材质与**冷暖色彩响应**。禁止泛写“电影感光影”“高级氛围光”。
- **三点布光**：明确 Key Light、Fill Light、Backlight 的**方位、软硬、色温、照度**；亮度/反差服从 `Genre` 与 `Base Positioning`；Fill 与 Key 须写清**冷暖关系**。
- **色彩层次**：主色、辅色、点缀色、过渡色绑定材质、**光源色温**、距离层；说明曝光、白平衡、反差、风格化影调；须显式写出至少一组**冷暖对照或同温层次**；禁单色平铺、禁只写“暖调/冷调”而不交代光源。
- **环境全域光影与光源充足性（强制）**：`generation_prompt_cn` 须把光照写成**可执行光学描述**，至少覆盖下列 **7 项中的 6 项**——**(1) 光源清单与动机**（须列 **≥2 个**可识别光源：如主吊灯+窗光、台灯+顶灯、天光+壁灯、霓虹+街灯、法阵辉光+天光等；每个光源写**位置锚点**——天花板/窗侧/桌面/墙龛/门外/悬挂物，禁止只写“有光/明亮”）｜**(2) 主光方向与照亮面**（写明 Key 从哪来、主要照亮 FG/MG/BG 哪一层、哪一面墙/地面/家具受光）｜**(3) 光源作用范围（Mandatory）**（**每个动机光源须写清作用范围**——覆盖 FG/MG/BG 哪一区段、哪些具名表面/结构进入亮区/半影/暗区、光能到达的纵深边界与未照亮暗口袋；禁止只写「有窗光/有台灯」而不写照到哪里、哪里未被照到）｜**(4) 光源可见效果（Mandatory）**（**须写光线作用产生的具体效果**——窗格条纹光、桌下椭圆影、门边斜投影、湿地面/金属/玻璃反射、体积光束、文件柜冷高光条、椅脚短影、墙面明暗分界等；禁止只写「有光影/有层次」而不写效果形态）｜**(5) FG/MG/BG 光影分层**（前景框景明暗、主舞台受光面与半影、背景远层退暗或冷化；写清**投影落点**）｜**(6) 光影过渡与体积感**（半影**自然柔散、渐变绵长**、空气透视、暗部细节可读、**投影边缘软过渡无硬切线**）｜**(7) 冷暖色温与材质光学响应**（主光/Fil 色温、Fill 与 Key 冷暖差；木/石/金属/玻璃/织物在光下的高光形状与反射色温）。**真人写实类额外强制**：优先 **§3.1.7-E 柔和侧逆光 + 环境正面补光/反射 Fill**；禁止**硬阴影边界、刀切式投影、无动机硬光**。**光源充足硬约束（Mandatory）**：除恐怖/惊悚/悬疑低照度题材或上游明确压暗外，环境默认须**照度充足、主舞台与动线通道清晰可读**——须写 **≥2 个动机光源** + **≥1 种环境反射/补光**（墙面反弹、地面反射、天光散射等）；豪宅/办公室/厅堂/商业/户外日景等**禁止**写成单一昏暗点光、无动机黑场或“只有氛围没有光源”；**夜景见 §3.1.8**——剧情允许时须强化自然主光/暖调覆盖/多人工覆盖照明，禁止整室漆黑仅一盏灯。
- **中文 prompt**：`generation_prompt_cn` 使用连贯自然中文短段；最低覆盖机位落点、观察朝向、主舞台分层（MG/BG 必写，FG 按镜头需要可选）、主次主体、**§1.3 环境光影 7 项至少 6 项（含每光源作用范围+可见效果）**、材质/空间结构、可达性、去人物化；主舞台与动线保持净空的同时，BG/边缘/窗外等非动线区须补足装饰、植被、天象、雾气等氛围细节以强化美感与层次。不得为满足模板强行添加不合理前景遮挡。

- **转译自检（提交前强制）**：若把 `generation_prompt_cn` 单独复制给不了解项目的第三方，对方应能**直接据此生图**而无需阅读 `description_cn`；若仍依赖拓扑/对照/继承等上下文才能理解，则转译未完成，须重写 `generation_prompt_cn`。
- **主环境 `generation_prompt_cn` 写法（两宫格专用）**：首句须声明画布格式，再分格写可执行指令。推荐结构：

  **§0 画布契约（首句，必填）**——`生成一张单画布左右两宫格空间基准参考图；总共只能有两格，左格俯拍全景、右格仰拍全景，每一格均为固定 1:1 正方形画幅（左格 1:1、右格 1:1），禁止把任一格拉成 16:9 或其他比例；禁止增格、禁止 2×2、禁止上下两排或把任一格再拆成宫格。两格左右并排于同一横排，描绘同一物理空间，以 0 度坐标轴为顺时针标注原点。Clean Plate，无人物，非 Beat 叙事机位。`

  **§A 参考图声明（首句，必填）**——`参考图为主环境「{主环境名}」两宫格基准图（左格俯拍全景、右格仰拍全景）。基于同一物理空间不变……`（视角衍生补顺时针回转 N 度/状态衍生补结构 Delta 任务说明）。

  - **180 度/正反/OTS 衍生**：在 §A 基础上补互补半空间说明。
  - **状态/特效衍生**：`参考图为主环境「{主环境名}」两宫格基准图。与参考图同一空间边界，仅叠加/替换以下可见结构变化：{逐条列举}。`（状态链 `base_entity` 仍可按时序指向前一状态，但**生图参考图统一用主环境两宫格**）

- **变体继承与 360 度拓扑**：**主环境**在 `description_cn` 写俯视/仰视 360 + 0 度坐标轴，输出**俯拍+仰拍左右两宫格** `generation_prompt_cn`，`visual_dependencies=[]`，`dependency_strategy.type=BaselineDefinition`。**全部衍生**（含 `0度{主环境名}`、其他 `{N}度`、状态/特效）：`visual_dependencies` **必须含 `ENV:[主环境名]`**；§A 统一声明参考主环境两宫格基准图。禁止衍生互挂（如 180 度回挂 0 度）。
- `negative_prompt_en` 必须短而个体化；环境优先过滤角色残影、可识别人脸、杂乱阻塞、塑料/微缩感、时代错置；海报过滤错画幅、标题不可读、拼贴感。

### 1.4 全局最高审美与防平庸规则
- **宏大美观默认基调（Mandatory，与 §1.2A 联动）**：无剧情明确负面约束时，环境/海报默认**宏大、美观、高完成度**——尺度开阔、材质精致、层次丰富、光源充足、**整体氛围柔和自然真实**；禁止廉价棚拍感、缩小模型感、样板间、硬光硬影。
- 不做舞台剧、主题乐园、低成本布景或样板间；在题材、写实度、历史地域、阶层身份允许内，对标电影级空间/海报美术。
- 最高审美服从题材：喜剧/治愈明亮亲和，情感温润，仙侠空灵秩序，写实可信克制，恐怖惊悚才显著压迫。
- **豪宅/高贵室内基线**：当上游场景为豪宅、别墅、庄园、宫殿、会所、贵族宅邸、高端酒店、奢华厅堂或其他高贵室内空间，默认向高挑层高、宽敞尺度、明亮通透、灯火通明、材质精致且秩序清楚定位；除非剧情明确要求阴暗、狭窄或破败，不得生成低矮压抑、昏暗小房间或廉价棚拍感。
- 贫穷/破旧/压抑环境不得极端脏乱差；保留空间秩序、材质层级、光影美感、可演可读。
- 无明确风格时，环境默认“优美/大气/现代/摄影机质感”。

## 三、环境专项规范 (Environment Design & Prompts)

### 3.1 Environment Prompt Template
#### 3.1.1 基础原则与信息架构
- **上游空间骨架只读**：完整继承 Stage 1 / Subject Index 的实体清单、360 度拓扑、转角对照、`empty_view_delta` 与 **`literary_atmosphere` 文学氛围**；**禁止**改写拓扑或增删固定实体。**本阶段新增（技术层）**：将上游文学氛围转译为材质、纹理、光源/三点布光、声场气质、色彩层次、美学参考与 `generation_prompt_cn` 生图描述；不得把 Stage 2-1 文学句原样粘贴为最终 prompt 而不做光学/材质/色彩拆解。
- **专属字段回写**：`name/name_en` 中的场所属性、级别、方向、早晚必须转译进提示词。写清 FG/MG/BG、Primary/Secondary Subject；禁止只有构图没有空间物理身份。

#### 3.1.2 舞台构筑与空间实体化
- **Stage 中心**：`generation_prompt_cn` 围绕上游 `{Stage}` 组织；核心舞台清晰可见，优先放 MG 承载表演。先写固定实体与空间边界，再写 FG/MG/BG、光照、材质、Delta。
- **Stage 实体回写**：把舞台边界、关键界面、固定物、通行路径转成可见结构，如门框、窗沿、桌边通道、柜台内外分界、台阶起点、栏杆转角；不重新发明边界。
- **剧情相关实体空间关系回写（强制）**：上游与剧情交互/站位/动线/视线/座次直接相关的固定结构/家具/陈设，除各自 FG/MG/BG 层位外，须在 `description_cn` 与 `generation_prompt_cn` 中写清**实体间前后左右关系**（锚定空间基准或另一具名固定物，如椅在桌哪一侧/哪一头、门轴在哪侧、屏风相对主舞台的左右与前后面）；禁止只列物件名而不交代相对位置。**门窗开闭态（强制）**：凡描述中出现门/窗/柜门/推拉门/百叶/阳台门/窗洞/玻璃幕墙开口等可开合或可调光构件，**必须写明开闭状态**（紧闭/半开约几度/全开/合拢/叶片开启等）及**内开|外开、门轴/铰链侧**；禁止只写「有门/有窗/门口/窗边」而不交代是否闭合。**方向性实体具名+朝向+正反面（强制）**：椅子、门/窗/柜门、长桌/会议桌/餐桌、主位/客位/上首/下首座次、沙发、床、屏风、柜台、祭案、讲台、台阶、招牌/牌匾等具有正面/背面/开合/使用朝向/座次指向/内外侧/文字面差异的固定物，须**具名并同步写开闭态、朝向与正反面**——`description_cn` 可用拓扑方位（如「半开内开木门，180 度墙段，门轴右侧，门扇向室内开启，室外侧为正面」）；`generation_prompt_cn` 须转译为镜头可见描述（如「BG 半开内开实木门，门轴在画面右侧，门扇向室内开启，当前可见室外侧门扇」），写清可见面、椅背/椅面、门扇开向与开闭态、窗扇/百叶开闭、桌头/桌尾/主客位、屏风/牌匾正背面，禁止只写「两把椅子/有门/一张桌子/有窗」。纯装饰性远景点缀可只写层位与分布区段。
- **动作支持**：若 Beat 要求穿门、绕桌、切换内外、跨阈值，必须保留通行净空、界面两侧结构、视线通廊。
- **活动空间与氛围细节平衡**：主舞台、角色站位区、通行净空与主要动线须保持空旷清晰，不得被杂物阻塞。在此范围之外，须写入适量可见细节以强化画面美感与景深层次——如墙面/梁架装饰、陈设点缀、花草植被、星辰天象、雾气烟尘、粒子光效、悬挂物、远景点缀等；细节优先落于 BG 远层、画面边缘、顶部/底部非动线区或窗外远景，须写清景别、尺度与受光/分布逻辑，陪衬主构图、不抢主舞台。
- **构图简洁有序**：明确主导构图策略，如三分法、对称、前景框景 + 中景主舞台 + 背景收束。主舞台、次级主体、引导线、留白区、通行动线服从同一秩序。
- **控杂**：只保留服务主构图、主舞台、题材气质的关键物件；前景框景/柱列/屏风/灯具/树枝等不得平均抢戏。写明主体位置、陪衬、留白或框景如何压向主舞台；控杂不等于剥离氛围细节，非动线区的装饰与空气感细节仍须按上条补足。

#### 3.1.3 光学语境与美学强化
- **环境光学总领**：先定**光源清单与充足度**、亮度基线、可见度层级、主光/辅光/轮廓光、**FG/MG/BG 各层受光与投影**、色温、空气透视，再写陈设风格。氛围与可读/可拍/可演冲突时，优先后者。
- **演出展示基线**：环境需有**相对明亮、光源动机清晰、照度充足**、利于角色展示的光源设计；情绪表达不得牺牲基本质感、通透性与**主舞台可读照度**；须写 **≥2 个可识别动机光源**。
- **豪宅/高贵室内提示词落点**：`generation_prompt_cn` 必须显式写入高挑层高、开阔厅堂或宽敞房间尺度、**多源明亮主光**（主吊灯/天窗/落地窗/壁灯/筒灯等 **≥2 项**）与**充足环境照明**、通畅动线和精致材质层级；用柱列、挑空、落地窗、宽楼梯、长廊、吊灯、反光石材、木作或金属细节组织纵深，**写清各光源如何照亮主舞台与地面/墙面**；避免把奢华只写成抽象形容词或昏暗单点光。
- **执行清单**：先写**光源清单（≥2）**、主光/补光/各层受光与投影、色彩层次；必须含 MG/BG 与明亮/压暗基线、至少三项色彩参数、空间深度、材质反射层次。FG 非强制，仅在有明确框景、遮挡或景深组织价值时书写。
- **氛围收束**：用可执行词闭环，如通透、厚重、柔和、清冽、温润、冷峻、朦胧、肃穆、轻盈、凝练；默认补通透度/柔和度，权力/奇观/历史/压迫题材补厚重/肃穆/压强。
- **焦距**：写镜头焦距以控制空间感：16-35mm 宏大/开阔，50mm 自然，85-200mm 压缩/窥视/疏离。
- **亮度与角色弧线**：默认可读通透；**夜景见 §3.1.8**——剧情允许时须强化自然主光/暖调光源/多人工覆盖照明，只改光源组织，不取消主舞台可见度。角色关键区域与走位路径稳定照亮；背景人群/次要物体主动后退。
- **风格后置**：奢华、复古、工业等风格优先通过 BG 材质、光照、色温、体块、纹理节奏表达；动作通道保持空旷清晰。
- **深度显性写法**：优先“前景框景/遮挡 + 中景主舞台受光 + 背景远层收束”，用门框、柱列、屏风、雾层、远窗、灯带、反光地面等标记纵深。
- **色谱显性写法**：至少一组可生成的综合色谱，并拆到表面/光源/距离层，如墙面冷灰、木作中棕、金属暖高光。
- **礼制空间**：宫廷、王府、府邸、宗祠、官署、厅堂、祭祀等需写中轴/主次空间、座次、门窗尺度、屏风帷幔、器物陈列、动线约束、对称性、维护程度；民居/市井/边塞/乡野按生活方式、气候、工艺构建秩序。
- **真人写实门禁**：环境必须像真实可拍场地；写真实尺度、装修层级、收纳方式、通行动线、老化位置、清洁程度、灯具来源。普通住宅/办公室/医院/学校/餐馆等禁无依据过度高级、空旷、对称、棚拍化；默认保留适量生活痕迹与功能杂项。

#### 3.1.4 仙侠/东方幻想特设
- **构图想象力**：可用悬空平台、云上宫阙、非现实比例门洞、层叠山门、深渊天光同框、地空法阵、雾中桥廊、巨物尺度差等；要求主体清楚、重心稳定、层次分明。
- **色彩**：可用月白-青碧、苍蓝-冷金、黛青-玉绿等双主干，扩展法阵辉光、灵泉雾气、神木微光；禁无依据退回普通古风写实用色，仙侠多以金色点缀。
- **祥瑞异观**：可适度加入仙鸟、灵兽、异草、祥瑞云气、灵蝶、符光游丝、远空神兽剪影、灵木花雨、灵泉光粒等作为尺度/气运/宗门气质；需写景别、尺度、数量、发光/受光逻辑，不得抢主舞台。
- **反水墨模板**：除非上游明确水墨/写意/卷轴/丹青/黑白法界，仙侠环境不得默认黑白灰水墨主调；优先鲜活、灵气、宝石感/法器感色彩，如青碧、玉绿、月白、冷金、灵银、雾紫、朱砂。
- **简式模板**：**列光源清单（≥2）** -> 主光源建立主舞台受光与半影 -> 辅光/反射托暗部 -> **写 FG/MG/BG 各层受光面、投影与冷暖** -> 主辅色与过渡色绑定材质/距离 -> 落题材氛围词。

#### 3.1.7 环境全域光影、光源充足与冷暖色温（Mandatory）
- **触发条件**：所有 `environments[]` 与 `posters[]` **强制生效**；真人写实/都市/职场/家庭/纪实向须优先**自然光/动机光/窗光/天光** setup；仙侠/科幻/赛博等按题材写动机光源但须**清单清晰、照度可读**。
- **核心目标**：让生图模型明确「光线从哪来 → **作用范围照到哪里** → **产生什么可见效果** → 冷暖如何分层」——不仅是“有光”，而是**光源→作用范围→受光面/暗区→半影/投影/反射等效果→材质响应→冷暖层次→空间体积**的完整链条；**环境须光源充足**，主舞台、关键家具、动线通道、材质细节在默认题材下**清晰可读**；**整体氛围须柔和、自然、真实**。
- **E. 「柔和侧逆光 + 环境补光/反射 Fill」标准（Mandatory，真人写实优先；环境/海报/封面默认倾向）**：
  - **侧逆光 / Rim**：窗外天光、顶侧窗光或 Practical 作**柔和**侧逆光，塑形空间轮廓、梁架、家具边缘、人物（海报）轮廓；禁止硬 rim、刀切明暗。
  - **Key**：侧向窗光/天光/主 Practical 塑形 MG 主舞台；半影**自然柔散、渐变绵长**。
  - **Fill（环境正面补光/反射）**：白墙/地面/桌面/天光散射作 Fill，托起暗部并保持材质可读；FG/MG/BG 各层投影须**软过渡、无硬阴影边界**。
  - **海报/封面**：群像与 key art 同样优先**柔和侧逆光 + 正面 Fill**，标题区留白须柔和自然、非硬光切割。
  - **整体氛围**：柔和、自然、真实；禁止硬闪、硬投影、高反差刀切式空间明暗（恐怖/上游压暗例外）。
- **最低输出量（每个环境/海报）**：
  - `description_cn` 须写 Key/Fill/Backlight **光源清单、各层 rationale、FG/MG/BG 受光与投影设计**；
  - `generation_prompt_cn` 须按 §1.3「环境光影 7 项」覆盖 **至少 6 项**，且须**逐层写清**光线如何作用——**每个动机光源须写作用范围 + 可见效果**；**FG**（框景/近距遮挡物的明暗与投影边缘）｜**MG**（主舞台家具/地面/主结构受光面、半影、落地投影）｜**BG**（远层退亮/退冷/虚化、窗外天光或城市光渗入、轮廓分离）。
- **A. 光源清单与动机（Mandatory，≥2 项）**：
  - **自然光**：落地窗/高窗/天窗/百叶窗条纹光/北向柔光窗/户外天光/黄金时刻侧光/阴天均匀散射——须写**窗方位**与光斑形状。
  - **室内动机光（Practical）**：主吊灯、壁灯、台灯、落地灯、筒灯、灯带、蜡烛、壁炉、屏幕/霓虹——须写**固定位置**（如「MG 桌面左后角黄铜台灯」「BG 天花板主吊灯」「FG 门框侧壁灯」）。
  - **户外/都市/夜景**：日光、**月光/星辉/暮光天光/城市天光穹顶**、街灯、车灯轨迹、霓虹招牌、广告牌、建筑洗墙灯、水面/湿地面/雨痕玻璃反射——须写**主光+至少 1 补光来源**；**夜景细则见 §3.1.8**。
  - **混合色温（写实常用）**：冷窗光 Key + 暖 Practical Fill；日光 + 阴影冷蓝环境反射；霓虹冷点缀 + 主舞台暖 Practical——须写**哪一区暖、哪一区冷**。
  - **禁止**：只写「明亮/通透/有氛围」而不列光源；**禁止**默认单点昏暗光（除非悬疑/恐怖/上游压暗）。
- **B. 光线如何作用到整个环境（Mandatory，须写作用范围 + 可见效果）**：
  - **作用范围（每个光源必填）**：逐光源写清**覆盖哪一层/哪片空间/哪些具名表面**进入亮区或半影、**未覆盖暗区**在哪里（如「Key 仅覆盖 MG 会议桌桌面与左侧半墙，BG 文件柜列大部分处于 Key 半影外仅边缘受 rim」「FG 门框内侧处于窗光半影外、深褐木纹保留暗部」）；须写纵深边界，禁止只写「照亮室内」。
  - **可见效果（每个光源必填）**：写清该光源在作用范围内产生的**具体可见效果**——投影形状与落点（桌下椭圆影、门边斜投影、椅脚短影）、条纹/窗格光、湿地面/金属/玻璃反射条、体积光束、墙面明暗分界、空气尘粒光柱等；禁止只写「有光影/有层次」。
  - **主舞台（MG）**：Key 照亮哪一面墙/桌面/地面；半影落在哪一侧；写**主受光面 + 半影面 + 落地投影**。
  - **前景（FG，若有）**：框景元素受光侧与暗侧；是否形成**明暗框景**；投影是否落在 MG。
  - **背景（BG）**：远层如何**退暗/退冷/略虚**；窗外/门外光如何渗入；BG 实体的**受光面与背光分离**。
  - **垂直面与地面**：墙面哪一段亮、哪一段入影；地面反射是否托起暗部。
  - **空气与介质**：体积光/光束；写**光在介质中的可见路径**。
- **C. 冷暖色温与色谱响应（Mandatory）**：
  - 主光色温 + Fill 色温 + 阴影环境色；至少 1 组**冷暖对照**或明确的同温层次。
  - 材质响应：旧木暖褐、金属冷高光、玻璃冷反射、雨痕窗冷蓝、霓虹饱和点缀——须与光源色温一致。
  - 海报：主光塑形群像 + 标题区留白区的**明度/色相对比**须写清。
- **D. 主环境两宫格的光学要求**：
  - 左格俯拍、右格仰拍均须写**全局光源动机**（如「中央主吊灯 + 四向高窗天光」）与各方位**受光差异**（哪一方向窗更亮、哪一方向入影更深）；禁止两格光照矛盾。
- **E. 四视图白底/空镜与可拍衍生的区别**：
  - 可拍衍生 `generation_prompt_cn` 须按**当前机位**写 FG/MG/BG 分层光影；180° 反打须**重判光源方向**（同一物理光源，但 Key 方向相对镜头改变，BG 半空间更替）。
- **即贴短语库（可改写）**：
  - `BG 百叶窗 6500K 冷蓝雨夜侧光作柔和 Key，顶侧窗缘侧逆光分离文件柜轮廓；MG 黄铜台灯 2800K 暖 Practical + 白墙/地面反射 Fill，桌下椭圆投影边缘柔散无硬切线，整体氛围柔和自然真实。`
  - `FG 左侧门框处于窗光半影区，深褐木纹保留暗部细节；MG 桌面左后角黄铜台灯作 2800K 暖 Practical Key，Fill 来自右侧白墙反弹，半影自然柔散。`
  - `户外日景：5500K 侧上方日光为主光，MG 石阶受光面暖白、背光面微冷；BG 远树与山峦空气透视退冷退蓝；地面短投影清晰，体积感来自轻微扬尘光柱。`
- **generation_prompt_cn 回写**：光照须**独立成段或长从句**，按 FG→MG→BG 顺序写「光源→**作用范围**→**可见效果**→受光/投影→冷暖→材质响应」；**每个动机光源至少 1 句作用范围 + 1 句可见效果**；禁止与材质/构图混写后省略光源、范围或效果。
- **negative_prompt_en 追加**：`flat lighting, single light source, underexposed, muddy shadows, no motivated light, dark unreadable space, vague atmosphere only, black crush, no window light, no practical lights, inconsistent light direction, hard shadow edge, razor shadow, harsh cut shadow, hard rim light, high contrast hard light, night scene with only one dim lamp, entire room black except one spotlight`.

#### 3.1.8 夜景环境照明强化（Mandatory，剧情允许时）

**触发**：`visual_params`/上游/Beat 标注**夜/夜景/雨夜/深夜/内景夜/外夜景**，或 `description_cn` 明确夜间；**恐怖/惊悚/悬疑「刻意压暗」且上游/剧情明确要求低照度时除外**——例外须在 `description_cn` 与 `dependency_strategy.logic` 写明依据，仍须保留主舞台/动线**最小可读动机光**。

**核心原则**：夜景≠整室漆黑或单点蜡烛。**剧情允许可读演出时**，须主动设计**覆盖照明**——让 FG/MG/BG 主舞台、动线通道、关键家具/结构在夜间仍**层次可读、光源动机清楚**；优先从下列 **三路径择一或组合**（须在 `description_cn` 光学 rationale 与 `generation_prompt_cn` 中显式写出所选路径）：

1. **强化主要自然光源（Natural Key/Fill 路径）**
   - 须写清**主自然光来源 + 作用范围 + 可见效果**：如满月/弦月侧光、暮光/蓝调时刻天光、城市天光穹顶、云层反射、雨夜窗玻璃/湿地面/水面反射的冷蓝环境光、远处港口/都市辉光渗入。
   - 自然光须**覆盖 BG 或 MG 至少一层**（如「BG 雨痕玻璃透入 6500K 冷蓝街光，覆盖文件柜列与窗墙，在金属面形成冷高光条；MG 桌面边缘受环境反射弱补光」），禁止只写「外面很黑」而无自然光作用描述。

2. **强化暖色调光源（Warm Coverage 路径）**
   - 须设计 **≥2 个暖调 Practical**（3200K–4000K 钨丝/暖 LED/蜡烛/壁炉/黄铜台灯/暖色筒灯/暖色灯带等），写清**各暖光源作用范围**如何托起 MG 主舞台、地面动线与木质/织物暖褐响应。
   - 可与少量冷自然光形成**冷暖对照**（常见：冷窗光/街光 Key + 暖 Practical Fill 覆盖 MG）；禁止夜景只有冷光导致主舞台不可读。

3. **多人工光源覆盖照明（Multi-Practical Coverage 路径）**
   - 须列 **≥3 个可识别人工动机光源**，且须写**重叠覆盖关系**——各光源作用范围如何**接力照亮** FG/MG/BG 不同区段，形成「无大面积无动机死黑」的覆盖网（例：天花板主吊灯照 MG 桌面区 + 壁灯/筒灯照通道 + 台灯/落地灯补桌面暗部 + 门外走廊灯/橱窗光渗入 FG/BG + 墙面/地面反射 Fill）。
   - **覆盖照明写法（Mandatory）**：须用自然语言写「**A 光照亮…，B 光覆盖…，C 光补…，三者叠加使{主舞台/动线/关键结构}可读**」；须写各光源**可见效果**（池化暖光、地面反射、墙面上洗、灯带洗墙、霓虹边缘点缀等）。

**夜景最低输出量（剧情允许时）**：
- 动机光源 **≥3**（或 **1 强自然光 + ≥2 Practical/环境反射**）；
- **MG 主舞台 + 至少 1 条动线通道**须落在某光源作用范围内；
- `generation_prompt_cn` 须含 **≥1 句自然光作用范围/效果** 或 **≥2 句暖调 Practical 覆盖** 或 **≥1 段多光源覆盖网描述**（按所选路径）；
- 禁止：整室仅一盏灯、主舞台全黑、只有「昏暗/神秘氛围」而无覆盖照明设计。

**即贴示例（可改写）**：
- 自然主光：`BG 雨夜街灯与湿玻璃透入 6500K 冷蓝环境光，作用范围覆盖百叶窗墙与文件柜金属面，形成冷高光条与窗格反光；MG 桌面受环境弱反射补光，FG 门框处于半影外保留深褐暗部。`
- 暖调覆盖：`MG 天花板主吊灯 3200K 暖光向下覆盖会议桌与椅区；桌面左后黄铜台灯 2800K 补桌面暗部；右侧白墙反弹 3800K 暖 Fill 托起通道，三源叠加使主舞台与动线可读。`
- 多人工覆盖：`主吊灯照 MG 中央、壁灯洗亮左右墙面与通道、台灯补桌下暗部、门外走廊暖光渗入 FG 门框区，四源覆盖网使办公区夜间仍层次可读。`

#### 3.1.5 变体与正反环境逻辑
- **主环境基准定义（Beat 不可用，生图参考源）**：`description_cn` 须写俯视/仰视 360 + 0 度坐标轴；`generation_prompt_cn` 为**俯拍+仰拍左右两宫格空间基准参考图**（§0 画布契约 + §1 左格俯拍 + §2 右格仰拍；非 Beat 机位）；`visual_dependencies=[]`。
- **全部衍生（含 `0度{主环境名}` Master）**：可拍机位 `generation_prompt_cn` + **`visual_dependencies` 必须含 `ENV:[主环境名]`** + §A 参考主环境两宫格基准图；**`description_cn` 须写本衍生独立的 0/90/180/270 四向自然语言具名实体描述**（见 §3.1.5）。
- **360 度坐标系定义（强制，先于拓扑与衍生设计）**：
  - **0 度是什么**：0 度 = **摄影机 Viewing Direction（观察朝向）**，不是建筑真北或默认进门方向。主环境 **0 度坐标轴** = 上游 Stage 1 开场建置/首 Beat Master 视角的机位落点 + 朝向（**仅作映射基准，不可拍**）；须在主环境 `description_cn` 显式写清「观察起点 → Viewing Direction」。
  - **角度递增方向**：90°、180°、270° 等均为**顺时针**递增——**站在空间内俯视**，从 0 度正面沿顺时针扫视；禁止混用逆时针标注。
  - **各向可见/不可见对照（强制，主环境）**：主环境 360 度拓扑每个方位除写固定结构/景物外，须标注相对**主环境 0 度**的可见性——**0 度可见 / 0 度不可见（机位后方或被遮挡）**。**180 度方位须特别写明**：对侧半空间；切至 180 度衍生视角时，其 BG 应呈现 0 度不可见/被遮挡的背景（例：0 度 BG 为百叶窗墙 → 180 度视角百叶窗位于机位后方不作当前 BG，而 0 度不可见的入口/对侧墙段成为 180 度 BG）。
  - **衍生各向自然语言实体描述（强制，全部视角/状态衍生）**：**每条衍生环境须独立撰写**（`0度` Master、各 `{N}度`、各 OTS/反打/状态行**不得照抄彼此**）。`description_cn` 须以**本衍生 Viewing Direction 为 0 度**、**顺时针**依次写 **0°/90°/180°/270°** 四段**自然语言**（每段 **【{N}度方向】** 起头）——每段用完整句子写清该方向可见与不可见的具名固定实体（**须全部来自主环境固定清单，全名+定语+开闭态/朝向与主环境逐字一致**；不可见项仍须具名）。**镜像映射对齐原则（强制，最高优先级）**：衍生环境各向实体描述须与主环境保持**同等具体度**——每个具名固定实体的**全名、功能/位置定语、材质/结构/尺度/工艺/配色/开闭态/门轴侧/椅位/桌向/连接关系/方位归属**等描述颗粒度**不得低于主环境**；物理实体清单与空间逻辑**严格一致匹配**；**唯一允许变化**为观察角度旋转后的**可见/不可见分配**与**方向性物体在当前 Viewing Direction 下的可见面/左右镜像重判**；衍生 **k 度方向**=主环境 **`(view_angle_from_main+k)%360`** 拓扑的**镜像映射对齐**，禁止简化、泛化、缩写或另写不同版本的同一实体。**主环境一致性（最高硬约束）**：四向中出现的每个物体**必须与主环境俯视/仰视 360 与固定实体清单完全一致**——**禁止**增删改物体、改名、改开闭态/门轴/椅位/桌向/连接关系/材质尺度定语；仅允许变化**可见/不可见**与**可见面重判**。须完整继承上游 `derivative_view_360_entities`；**禁止**键值标签式写法、省略号、泛称或只写 `empty_view_delta`。**`generation_prompt_cn` §B/§C** 所列实体亦须与主环境同等具体、逻辑一致，禁止另造参考图中不存在的固定物或简写版实体。
  - **方向性物体朝向随视角调整（强制）**：椅子、沙发、床、长桌/会议桌/餐桌、门/窗/柜门、屏风、柜台、祭案、讲台、台阶、主位/客位等须**具名 + 写清朝向**；衍生视角须按当前 Viewing Direction **重判**椅背/椅面、门扇开向与铰链侧、桌头/桌尾/主客位、床头/床尾、柜台内外；禁止沿用 0 度朝向导致左右/前后/可见面矛盾。
- **主环境俯视/仰视双视角强制设定**：主环境 `description_cn` 必须用 **俯视全局 360 + 仰视全局 360** 完整描述同一物理空间（以 0 度坐标轴为顺时针原点）；**可拍机位描述只写入 `0度{主环境名}` 及其他视角衍生** 的 `generation_prompt_cn`，禁止写入主环境。
- **各向实体差异化（强制）**：360 度拓扑各方位**尽量避免**出现名称与功能完全相同的固定实体（❌ 0 度=楼梯、180 度=楼梯；❌ 90 度=门、270 度=门）。同类型结构若多向并存，必须用**定语/功能/位置/连接层级/材质/尺度**明确区分，使各方位实体可独立辨识、生图不混淆——如「主厅通往二楼的赭红实木旋梯（0 度 BG）」vs「厨房后巷铁艺逃生梯（180 度 BG）」vs「侧廊双跑石阶（90 度 MG）」；禁止各向仅写泛称「楼梯」「门」「窗户」「台阶」而无定语区分。确须同类重复时，各向描述须写清**方位归属、连接楼层/空间、用途差异与可见特征**，不得让不同方位的同类实体在 `description_cn` / `generation_prompt_cn` 中无法区分。
- **视角衍生转角对照映射（强制）**：环境名 `{N}度{主环境名}` 表示相对主环境 0 度**顺时针**旋转 **N** 后的机位。该衍生环境的 **0 度正面** 必须严格采用主环境 360 度拓扑中 **N 度方位** 的描述作为正面基准（例：90 度衍生 → 主环境 90 度描述 = 衍生 0 度正面）；衍生 90/180/270 度依次对应主环境 `(N+90)%360`、`(N+180)%360`、`(N+270)%360` 方位。**转角对照、新可见/不可见半空间、180 度 BG 互补关系只写入 `description_cn`**；`generation_prompt_cn` **禁止**粘贴对照公式，须转译为参考图声明 + 机位落点 + 顺时针回转 + 背景更替 + 不可见区实体化（见 §1.3 生图无记忆性规则）。
- **四向一致性与现实逻辑强校验**：凡涉及 0/45/90/135/180/225/270/315 度方向描述，必须保证各向信息彼此匹配、可互相推导、无左右颠倒或前后冲突，并符合真实空间结构与摄影机轴线逻辑。涉及门、窗、柜门、屏风、百叶、推拉门、阳台门等可开合或具正反面构件时，**必须逐视角明确**：**开闭状态**（紧闭/半开/全开/合拢等）、内开或外开、铰链（门轴）位于哪一侧、门扇/窗扇当前朝向与**当前可见面（正面/背面/内外侧）**；禁止只写「有门/有窗/开着门/关着窗」而不交代开闭态、开向与正反面。
- **上游衍生环境衔接**：来自 Stage 1/2 的衍生环境名称若为“主环境名 + 空格 + 衍生类型/观察区域/可见方向”，本阶段不得重新命名、拆分或合并；必须在上游环境清单中匹配“最长同名主环境前缀 + 单个空格”，用该主环境回挂 base environment，再设计当前衍生视角。禁止简单截取第一个空格前文本，避免误伤本身带空格的主环境名。若找不到同名主环境 Subject，不得擅自补造基准环境，标记 `dependency_strategy.logic="上游待补（回流 Stage 2）：缺少同名主环境"` 并保留原名。
- **衍生环境生成策略**：`description_cn` 须先写明继承的主环境共同锚点、转角对照与新可见/不可见半空间（**设计推导层**）；`generation_prompt_cn` 须按 §1.3 **三段式**（参考图声明 → 一致项具象清单 → 视角/状态 Delta）撰写，禁止把 `description_cn` 中的拓扑段落原样粘贴到 `generation_prompt_cn`。禁止把衍生环境生成成完全不同的空间，也禁止只写“正反打/屏幕内/门外/桌面区域”而不回扣主环境；**禁止**在 `generation_prompt_cn` 中用「继承锚点」「延续主环境」「同上」等抽象词替代具象可视描述。
- **镜像映射重写（非简化）**：衍生环境**禁止**相对主环境**简化实体描述**（如把主环境「半开内开木门（180 度墙段中央，门轴右侧，门扇向室内开启）」缩成「半开木门」或「背景门」）；须**完整保留**主环境对该实体的全部定语与逻辑属性，仅按当前机位做**可见/不可见分配**与**观察角度镜像映射对齐**（可见面、遮挡、左右、前后、远近、通道、受光面重判）。不同衍生 ENV 之间**禁止照抄四向段落**；若某衍生四向实体颗粒度低于主环境对应方位，视为不合格。
- **衍生环境前景继承规则**：衍生环境的前景组织必须与继承环境的可见逻辑一致。若继承环境该视角不存在有效前景锚点（如门框、栏杆、近景遮挡），可不写 FG；禁止为凑“FG/MG/BG”格式硬加前景物体，导致与基准拓扑或镜头轴线不匹配。
- **共同锚点与视角轴线**：正反、内外、桌两侧、门两侧等成组衍生环境必须选定一个可见且稳定的空间锚点作为 180 度翻转轴，如长桌中线、门槛/门框、柜台边、走廊轴线、窗墙、屏风或柱列。`description_cn` 写锚点与转角对照；`generation_prompt_cn` 须用镜头语言写清机位位于锚点哪一侧、观察朝向哪一侧（如「机位位于会议桌长边靠窗一侧，沿桌轴线看向半开木门」），**禁止**写「相对基准环境顺向/反向」等推导词。
- **180 度互补覆盖**：正反视角通常不是两个相似构图，而是围绕同一锚点分别看向相反半空间；两条衍生环境合并后应能形成主环境的 360 度空间理解。`description_cn` 须说明与配对视角互补的对面背景；`generation_prompt_cn` 只写当前镜头**实际看见**的 BG 实体，并将主视角不可见/位于机位后方的对侧半空间**实体化**写入 BG（如「BG 为半开木门与门外走廊；参考图主视角的百叶窗墙位于机位后方不在当前背景中」），不得把同一背景重复给正反双方。
- **跨越 180 度轴线（越轴）方位重映射**：当机位跨越同一空间锚点建立的 180 度轴线（越轴）时，必须执行方位重映射：须先按主环境 360 度拓扑与当前衍生转角 N 确定基准对照，再按新机位翻转重判左/右关系；前景/后景与近距/远距按当前可见性重新分配；不得沿用主环境 0 度视角的左右与前后表述。
- **广角与越轴专项约束（强制，全部可拍衍生）**：
  - **焦段档位（`lens_profile`，须继承上游 Index）**：**Wide（24–35mm 等效）**——仅用于 `0度 Master`、首场建置、Two Shot、航拍/高位全局建置；`generation_prompt_cn` 可写「35mm 广角」等，四向描述须体现宽画角下的边缘拉伸、框景更开、远景略退。**Standard（50–85mm 等效）**——**OTS/正反/反打/对白可读**衍生**强制**；`generation_prompt_cn` 写「50mm 自然焦距」等，**禁止** 24mm 以下广角与强透视畸变；四向描述须按标准焦段的压缩感/背景分离写 FG/MG/BG。**禁止**反打 ENV 复用 Master 的广角 prompt 或照抄其左右序位。
  - **轴线与越轴（`spatial_axis` + `axis_crossing`）**：成组衍生须继承 `spatial_axis`（桌轴线/门槛/走廊轴）；**`PlannedReverse`**（180° 反打/正反配对）——沿锚点有意翻转，§C 须写清 BG 半空间互补与「Master 侧百叶窗墙→本视角机位后方不可见」类翻转；**`MotivatedCross`**（计划外越轴）——须与 Stage 1 Beat 过轴动机一致，**完整重映射**画面左/右/前后，禁止微调 Master 文案；**`None`**——同侧 OTS/连续观察，不翻转横向序位。
  - **自检**：若 `generation_prompt_cn` 写 Wide 但 ENV 为 OTS/反打 → 不合格；若 `axis_crossing:PlannedReverse` 但四向/§C 仍保留 Master 的「画面左=门框」而未翻转 → 不合格。
- **方向性物体朝向同步翻转**：椅子、沙发、床头/床尾、书桌/会议桌/餐桌、柜台、门扇、窗扇、屏风正背面、招牌、讲台、祭案、车头、主位/客位/上首/下首等具有正面/背面/开合方向/使用朝向/座次指向的物体，**必须随 Viewpoint Anchor 与 Viewing Direction 改变而明确改写可见面与朝向**——按当前机位重判椅背/椅面、门扇开向与铰链侧、桌头/桌尾/主客位、床头/床尾、柜台内外、台阶上下行。例如椅背在反向视角可能变为椅面或椅背背面，门应写清向里开/向外开及门扇位于画面哪侧，桌前/桌后与左/右关系需按镜头方向重新判定；**禁止沿用 0 度或基准描述导致物体朝向自相矛盾**。
- **可见性优先于模板分层**：FG/MG/BG 服从真实遮挡与透视逻辑，不得机械对位。若基准视角可由开门看到外侧并形成前景框景，而反向 180 度视角对应为实体墙面或不可透视界面，则该元素不得继续作为前景，应改写为当前可见的墙面/转角/通道结构并重组景深层次。
- **环境组传承**：同组衍生环境（正反、内外、**状态/特效域场**）保留宏观共性，只放大当前视角或当前状态需要的差异化物理要素。
- **状态/特效衍生环境**：`visual_dependencies` **必须回挂 `ENV:[主环境名]`**（生图参考图统一用主环境；`base_entity` 拓扑/时序链仍可按上游指主环境或前一状态）。
- **共同可见锚点严格一致**：衍生须与**主环境两宫格基准参考图**（尤其左格俯拍所呈现的平面布局与材质）在共同可见部分逐项一致。
- **依赖显式交代**：**全部衍生**（含 0 度 Master）§A 须声明「参考图为主环境「{主环境名}」两宫格基准图」；§B 共性锚点；§C 当前视角/状态 Delta。

#### 3.1.6 纯净去剧情角色化与门禁自检
- 环境只写空间、材质、灯光、空气感、匿名非情节群演；任何已进入 Subject Index 的角色实体不得进入 `environments`。
- 匿名群演仅用于规模/时代/生活气息：成组或稀疏背景，不成单独主体；远景、焦外、大幅虚化、面部模糊、不可复用；写数量、密度、分布、景别、服饰/肤色/发式/体态与项目时地阶层一致。禁止“信息量低”这类不可画抽象词单独承担指令。
- 提交前清除：主角/配角残影、可识别人脸、特定服装轮廓、镜中/窗面反射人影、舞台占位人形。需“有人活动过”时优先写非人格痕迹：座椅位置、杯盏余温、脚印、水痕、翻开卷册、未熄灯火、未关门、风动帷幔。

### 3.2 对话正反打与 OTS
- OTS/正反打/明确多角度同场时，沿用上游“角度 + 主环境名 + 衍生类型/观察区域/可见方向”或“主环境名 + 空格 + 衍生类型/观察区域/可见方向”的环境名，例如 `ENV:[180度侯府正厅反向OTS环境]`、`ENV:[侯府正厅 女主视线正向环境]`；禁止改写为 `_OTS_A`、`_OTS_B`、`A面/B面` 或其他编号名。
- **反打/OTS ENV 角两步确认（强制，继承上游）**：设计或核对反打/OTS 衍生环境前，**① 先确认被拍对手当前可读角 N_对手**（相对主环境 0 度顺时针，对照 360 度拓扑与对手落位/面向）；**② 再 ±180° 确认**本镜 ENV 角 = `(N_对手 ± 180) % 360`；禁止跳过①盲套主环境 180 度或不经判定一律写 180 度衍生。
- OTS/正反环境仅呈现正反方位的物理对立结构，并继承主环境共同锚点；当前视角只改变可见背景、阻隔物、**光源相对方向与 FG/MG/BG 受光面**、通道与构图 Delta；**180° 反打须重写 Key 方向、BG 受光与投影**，不得照抄 Master 光影句。
- 正反打必须通过同一空间锚点建立镜头轴线，正向环境写从 A 侧越过锚点看 B 侧，反向环境写从 B 侧越过同一锚点看 A 侧；两者约为 180 度互补，合在一起补足桌前/桌后、门内/门外、走廊来向/去向等 360 度方位信息。
- 每个 OTS/正反环境必须重判方向性物体的面向：椅背朝向、桌椅前后、门窗开合方向、屏风正背、牌匾文字面、柜台内外、台阶上行/下行方向都按当前机位书写；若锚点共同可见，其材质、尺度、位置与光照保持一致，但可见面和左右关系按 180 度反向更新。
- OTS/正反环境描述禁止“原文照抄+方位词替换”写法；反向镜头必须按跨轴线后的左右翻转、前后重排与可见性变化重写。若正向可见开门前景而反向为实体墙或封闭面，反向描述必须移除该前景并改写有效空间层次。
- OTS 继承 Clean Plate；严禁前景肩膀、人影、角色残留。

## 五、特殊资产规范 (Special Assets)

### 5.1 封面海报资产 (Cover Poster)
#### 5.1.1 上游类型响应与 JSON 结构
- `subject_type=cover_poster` 必须进入 `posters[]`，不得混入 `environments` 或漏掉。`name/name_en` 优先透传上游；缺命名时回退 `name="封面海报"`, `name_en="Cover Poster"`。
- 读取并归一化 `dependency_reference` 为 `visual_dependencies`（如 `CHAR:[@...]`, `PROP:[...]`, `ENV:[...]`）；`dependency_strategy.logic` 说明依赖如何整合为同一海报主视觉。禁凭空生造剧情外资产。

#### 5.1.2 国际大片制与视觉层级
- 封面海报按 `premium theatrical one-sheet` 完成度：大气、明确、强情绪、强冲突、强识别度；**整体氛围须柔和、自然、真实**（§3.1.7-E 柔和侧逆光 + 正面 Fill）；用前中后景群像、道具引导线、环境纵深、光区切分、块面分区或多层叙事焦点压缩剧情分格感。必须是一张完整海报主视觉。
- 光学继承主光源先行规则；主光同时服务群像塑形、标题留白保护、前后层次分离；须写 **≥2 动机光源** 及**冷暖对照**如何划分前中后景。
- **标题可读性**：说明标题位置和留白；标题背景低噪声/低信息密度；标题区有足够明度对比、色相分离或受控暗底/亮底；人物高光、武器/法器、烟雾、雨丝、火花、复杂纹样不得压住标题主阅读区；副标题/演员名/宣传文案也需稳定版式。
- `description_cn` 与 `generation_prompt_cn` 必须拆解并落实上游 `entity_attributes`，把“大片感”转成可见元素、物理细节、光影与站位压迫关系；`generation_prompt_en` 固定为空字符串。

#### 5.1.3 画幅与移动端排版规让
- 海报 `generation_prompt_cn` 必须显式声明固定 `4:3 poster canvas`；画幅写进提示词主体，不另设 JSON 键。
- 读取上游留白要求；标题置于指定位置或安全区内纵向 1/3（建议 `y=30%-35%`，横向 `x=20%-80%`）；保留右侧移动端按键区与底部菜单/字幕区净空。

## 六、输出模板（严格）
- 唯一输出物：一个 JSON 代码块，仅含 `environments` 与 `posters`。
- 顶层必须存在 `environments`、`posters` 两个数组；无实体输出 `[]`。

### Entities JSON (Strict Schema)
**结构最高优先级**：JSON 为唯一单对象；根节点固定含 `environments` 与 `posters`；数组按 `subject_type` 路由，错分即重写。

#### JSON 内容共性硬约束
- `environments` / `posters` 必须完整覆盖所有对应 Subject；不得只保留代表项。
- 输出前逐条核对输入类型与输出数组；总数正确但归类错误仍失败。
- 字段按类型分离；`environments[]` 与 `posters[]` 使用 `atmosphere`、`visual_params` 等环境/海报字段，禁止角色字段借壳。
- `name/name_en/base_name_en` 等名称与输入 subjects index 逐字符一致；任意字符差异必须修正。
- **主环境基准定义行**：输出**俯拍+仰拍左右两宫格（每格 1:1）** `generation_prompt_cn`（§0/§1/§2）；`visual_dependencies=[]`；`dependency_strategy.type=BaselineDefinition`；**禁止**作 Beat ENV。
- **全部衍生行（含 `0度` Master）**：`visual_dependencies` **必须含 `ENV:[主环境名]`**；§A 声明参考主环境两宫格基准图；**`description_cn` 须含本行独立的衍生 0/90/180/270 四向具名实体清单**（禁止省略号/照抄其他衍生行；**四向实体须与主环境固定清单逐字一致、同等具体度，逻辑严格匹配，仅观察角度做各向镜像映射对齐，可见/不可见可变**）；§C 转译看见/不再看见；**§B/§C 禁止出现主环境未列固定物或简写版实体**。
- `description_cn` 与 `generation_prompt_cn` 必须纳入 `entity_attributes` **全部**要素（零缺失，见 common §1.3），并显式包含 §1.2A **项目语境+风格定位**可视化落点（含 `风格定位为{…}`），同时说明 Key Light / Fill Light / Backlight 的**光源类型、清单（≥2）、方位、亮度、色温、FG/MG/BG 各层受光与冷暖对照**；须按 §3.1.7 写清光线如何作用到整个环境；`generation_prompt_cn` 细节特征 **>6**；`description_cn` 末尾须含「美学参考：」段落；`generation_prompt_en` 保留但输出 `""`。**分层硬约束**：拓扑/转角/`empty_view_delta`/美学参考作品名**只进** `description_cn`；`generation_prompt_cn` 只接收转译后的可执行视觉语义，须含衍生环境参考图 §A 声明且**不得**含 §1.3 禁止项。
- 固定双语字段契约沿用；每个实体必须提供 `visual_dependencies` 与 `dependency_strategy {type, logic}`。
